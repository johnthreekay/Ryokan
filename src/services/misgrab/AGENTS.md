# services/misgrab/AGENTS.md

Misgrab guardrails, the download-side half: judging a grab by its file list, and what happens to one judged wrong. The search-side half is match provenance (`src/services/auto_search/AGENTS.md`).

Keep this file under 40,000 characters (`wc -m`): past that, a Claude Code session with a 200K context window is given only its start. `tests/agents_md_audit.rs` enforces it.

## Layout

- `misgrab/` — misgrab guardrails (the download-side half; the search-side half is match provenance, `src/services/auto_search/AGENTS.md`). `verdict.rs` is the pure file-list judgment: media files only; a file names the series when its normalized path contains an own or sibling alias (or a multi-word colon / dash segment of one, other than a franchise name: `AliasSet.franchise_names`, #300) verbatim, or carries 60% of its distinctive tokens; **misgrab** only when at least one file has title signal (2+ Latin-lettered content tokens after `GENERIC_TITLE_TOKENS`, release noise, and episode / resolution / CRC tokens are stripped; a file named only in another script, like a Chinese raw group's file for a Japanese series, is unverifiable because no alias can match it) and no file matches or even shares one distinctive word with any alias, so abbreviated fansub names (`JoJo Stardust - 01`) and generic names inside a titled folder are never condemned; everything else is **unverifiable**. Where the series' franchise is known (`AliasSet.franchise`, loaded with the cached metadata, or from the parent detail in auto-expand), `verdict::apply_identity` can only soften the result: a misgrab whose files `services::identify` reads as the series, a tie or a pack across its entries is unverifiable, and so is a verified grab whose every titled file is another entry's by name or structure. It never makes a misgrab. `mod.rs` stamps the verdict once (`grabbed_torrents::stamp_verification`, first writer wins) wherever a file list first appears: the grab-time wait in `auto_expand::expand_from_files` (which returns before any route / coverage write on a misgrab, **including one the sweep stamped while the waiter was still polling**: a stamped verdict is final whoever wrote it, and only an unjudged grab is assessed), the post-processing import path (`import_torrent` judges an unjudged grab from the client's file list before importing), and the `misgrab_sweep` task. Remediation lives only in the sweep: `remove_and_blocklist` (client `delete` unless `respects_seed_rules`, usenet never touched; `mark_failed_by_hash_with_reason("misgrab")`, which makes the failed row the blocklist entry for hash and title; `episode_tags::mark_grab_failed_for_release`), then `emit_misgrabbed` and a detached re-search through the auto-search handler, gated by `research_allowed` (`RESEARCH_LOOP_BREAKER` = 3 misgrabs per series per 24h). `config.misgrab_auto_remove` off turns remediation into flag-and-hold. Restore / Dismiss are `handlers::library::misgrabs`. `assess` is pure CPU (a regex normalization per alias form plus a release-title parse per path segment) and runs under `spawn_blocking` from `assess_and_stamp`; alias forms are prepared once per verdict (`prepare_aliases`) and folder parses are memoized per segment, so cost is files + aliases, not files × aliases.

## The rules that hold it together

- **Misgrab guardrails, the rules that hold it together**: `grabbed_torrents.verification` is NULL / `verified` / `misgrab` / `whitelisted` / `unverifiable` and is written once; `misgrab_action` is `removed` / `removed_no_delete` / `flagged`; `failure_reason` (`misgrab`, `import_stalled`, `client_error`; empty for an import failure) renders as a tag on the Downloads → Blocklist row. **The blocklist is `state = 'failed'`** and every automatic path honors it: the auto-search collectors drop candidates through `blocklist_snapshot` (hash globally, except a misgrab's hash, which blocks only the series it was misgrabbed for, since the verdict means "not this series"; exact title per series) after scoring, which also covers the upgrade sweep, the batch auto-grab, and the misgrab re-search; RSS records a `rejected` decision; autobrr keeps its hash check. `find_all_for_target` (the interactive picker) is deliberately not filtered so its unblock-and-continue flow works, and that flow now calls `whitelist_by_hash`. **Whitelist is by hash across rows**: Restore whitelists every row for the hash except another series' misgrab verdict and writes a fresh `pending` row (`unblock_by_hash` points the failed one at it), so a re-added torrent is never judged again. Both functions take the series being grabbed for, so the picker's unblock-and-continue and Restore leave another series' misgrab row (its "not this series" block) in place. For a removed grab the whitelist is written **after** the client accepted the re-add: `whitelisted` rows leave the Misgrabs tab (that is its filter), so whitelisting first would strand a failed re-add with no retry button; every failure before the add leaves the row untouched. `source_url` is stamped by every grab path that has the URL (`set_source_url` right after `record_grab`); the picker path has none and Restore falls back to `magnet:?xt=urn:btih:<hash>` for 40-hex hashes. Don't loosen the verdict to catch more; the failure mode of a false misgrab (deleting a correct download) is worse than a missed one, which import preflight and the user still catch.

## The sweep

- **`misgrab_sweep` shape**: 60s tick (`services::misgrab::SWEEP_INTERVAL`), `sweep_once` split from the loop like `grab_sweep`. Pass (a) asks the client for the file list of every `pending` grab with `verification IS NULL` older than `MIN_AGE_SECS` (the grab-time spawn gets first go): empty list = metadata not ready, retried until `METADATA_GRACE` (15 min) then `unverifiable`; client errors retried for 30 min; usenet is `unverifiable` on sight (SAB reports article names). Pass (b) runs `remediate` on every `verification = 'misgrab'` row with `misgrab_action IS NULL`. `grabbed_torrents::get_all_pending` excludes misgrab rows, so post-processing never imports one even in the minute before the sweep acts.
