# services/backup/AGENTS.md

Backup and restore (#126). `apply_pending_restore` runs in `main.rs` before the pool opens; the root `AGENTS.md` ("Routes") has that boot-order note.

Keep this file under 40,000 characters (`wc -m`): past that, a Claude Code session with a 200K context window is given only its start. `tests/agents_md_audit.rs` enforces it.

## Layout

- `backup/` — #126 backup / restore. `create_backup` = `try_lock(BACKUP_LOCK)` → free-space precheck (`nix::statvfs`, 2×DB + artwork) → `VACUUM INTO` a work dir under the data dir (spliced as an escaped literal: SQLite reads a *bound* parameter here as `""` and silently runs a plain `VACUUM`; also a no-op against sqlx's shared in-memory DB, so tests use a file-backed pool) → optional sanitize (`services::sanitize::run_sanitize`: config secrets, `indexers.api_key`, `download_clients.password`, `api_keys.key`, sessions, password hashes, OAuth tokens, and the query string of `grabbed_torrents.source_url` / `direct_rss_feeds.url`, since torznab download links carry `apikey=`; + log trim to `SANITIZED_LOG_ROWS`, key and hostname omitted; also notification configs (Discord webhook URL, webhook URL / HMAC secret / headers), every URL column cut to scheme and host by `redact_url` since passkeys can sit in the path (`grabbed_torrents.source_url`, `direct_rss_feeds.url`, `rss_seen.link`, and the `link:` / `guid:` keys in `rss_seen.item_key`; a UNIQUE column gets the row id appended, `row_tagged`, since two URLs on one host redact alike), the addresses an admin typed, which can hold a credential the key and password columns never see (`indexers.url` cut to scheme and host like a feed's; `download_clients.url`, `config.jellyfin_url` and the four legacy `config` client addresses through `sanitize::strip_url_credentials`, which drops the `user:password@` part, the query and the fragment and keeps the path a bug report needs), poll errors, URLs and `apikey=` values in log text (`redact_text`), then a VACUUM so overwritten values don't survive in free pages; the CLI `--sanitize-db-for-debug` runs the same function). Every snapshot, sanitized or not, drops `sessions` under `PRAGMA secure_delete` (a live session is a working admin cookie), and the archive is created 0600 (`create_private`) → `tar.gz` of `manifest.json` + `ryokan.db` + `.ryokan-key` + `artwork/` written to `<out>.partial` then renamed. `BackupPaths::from_env()` takes the data dir from `paths::db_dir()` (the live database's parent, so work dirs share its filesystem) and the database from `paths::live_db_path()`, the key path from `crypto::key_file_path()`, artwork from `artwork::media_cache_dir()`; the configured `backup_directory` defaults to `<data dir>/backups`. Names are `ryokan-backup-<ts>.tar.gz` / `auto-pre-restore-<ts>.tar.gz`; `parse_backup_name` doubles as the allow-list for the file download / delete endpoints; `prune_backups` never touches pre-restore files. Restore is **stage-then-restart**: `stage_restore` extracts with an entry allow-list + `unpack_in` (regular files and directories only, never links; at most 500k entries and 64 GiB, `manifest.json` ≤ 1 MiB, the key exactly 32 bytes), refuses a database holding anything but plain tables and indexes (`lower(type)` in `sqlite_master`, since SQLite loads the stored type case-insensitively, plus `pragma_table_list` for virtual and shadow tables; a `sessions` view with an INSTEAD OF trigger once survived the purge), runs its purges through `sanitize::delete_unless_table_missing` (only a missing table is ignored; `clear_placeholders` deletes sessions before users, whose foreign key otherwise blocked the users delete) and refuses the archive if any session row is left, clears a sanitized archive's placeholders (`sanitize::clear_placeholders`), checks the manifest's `max_migration_id` (`backup::migration_level`, the count of one-shot migrations in `schema_migrations`, whose ids are names; the `MAX(id)` it was first read from never decoded, so every manifest written before the fix carries 0 and the gate never fired) and version against the running binary, `PRAGMA integrity_check`s and `DELETE FROM sessions` on the staged DB, takes a pre-restore backup, then renames the staging dir to `<data dir>/.ryokan-restore-pending/` (its existence is the lock). `apply_pending_restore` runs in `main.rs` **before the pool opens**, in the order key → database → artwork: the key first because it is the highest-value, smallest file and nothing else has moved if it fails; the live DB (with `-wal` / `-shm`) goes aside as `ryokan.db.pre-restore-<ts>` and a failed DB placement puts the DB *and the key* back; artwork (and removing the staging dir) can only produce `RestoreApplied.warnings`, never a rollback, so `Err` always means "nothing changed". `sweep_work_dirs` runs right after at boot and clears whatever a crash stranded in `.backup-tmp` / `.restore-staging-tmp`. `create_backup`'s precheck covers both the work dir (3×DB when sanitizing, else 2×) and the archive's own filesystem. The `backup` supervised task ticks hourly and runs when the newest scheduled backup in the folder is older than the cadence (the folder is the state). Endpoints are cookie-auth only (no #114 scope is broad enough for a key-bearing archive); the upload is a raw gzip body streamed to disk with the 2 MB body limit lifted on that route. Handlers: `handlers/system/backup.rs`; UI: System → Backup tab, schedule in Settings → General.

## The scheduled task

- **`backup` shape (#126)**: hourly tick, first check 2 min after boot; runs only when `config.backup_schedule` is `daily` / `weekly` and the newest `ryokan-backup-*.tar.gz` in the backup folder is older than that cadence (minus a 5-min grace), so restarts never double up and a missed day catches up on the next tick. Shares `services::backup::BACKUP_LOCK` with the download endpoint and the pre-restore backup (`try_lock` → "busy" / 503). Re-`touch_definition`s itself every tick so the Scheduled Tasks tab's enabled flag follows the setting without a restart.
