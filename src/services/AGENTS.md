# services/AGENTS.md

Rules that span more than one service: how episodes are numbered, what counts as a file for an episode, how the metadata providers fall back, and the bounds on outbound fetches. Loads with any file under `src/services/`. A subsystem with its own folder has its own file beside its code (linked from the root `AGENTS.md`, "Code Layout").

Keep this file under 40,000 characters (`wc -m`): past that, a Claude Code session with a 200K context window is given only its start. `tests/agents_md_audit.rs` enforces it.

## Episode numbering

- **Absolute-numbering offsets** live on `series.cumulative_prior_episodes` and are read by `post_processing::state::fallback_ep_offset` (import; a bare number past the offset reads as absolute, except that `claimed_ep_offset` keeps the relative reading when the grab's own episode list claims it and not the absolute one and the number is within the series' known episode count (`SeriesImportCtx::known_episode_count`: row, then cached detail or aired bound, then episode map; an unknown count keeps the absolute reading, since Search-page, RSS and autobrr grabs record a title's own absolute number), since in a sequel longer than everything before it `- 12` reads both ways and auto-search grabs it as E12; pack preflight passes no claim), the picker and its commit (`grab::file_episodes`, `grab_commit::episode_numbers_for_commit`, both through `grab_commit::file_slot_episodes`; the import's ownership check accepts a grab list in either numbering, a split part's included: a Search-page grab that auto-added it records the title's own number before its offset is stored), `auto_search`'s franchise-alias queries, and the manual-import range walk. Write them only through `services::anime_relations::cumulative_prior_episodes` (rule, split, else PREQUEL walk) and `series::update_cumulative_prior_episodes`, which stores the source beside the offset; a call site that reaches for `local_metadata::compute_cumulative_prior_episodes` directly silently skips the curated rules (#206). A refresh from a fallback provider (MAL / Kitsu detail, whose relations replaced the AniList rows) never overwrites an offset already known, except with a rule.
- **Episode numbering is one rule, `services::numbering::Numbering`** (#303), resolved from the row by `Series::numbering()`: the offset plus a `Reading`. `Either` (an offset from a rule or the TV walk, and what a bare `i32` offset converts to) is the #30 behavior above: a bare number reads as the target or target + offset. A split (`OffsetSource::Split`, Steel Ball Run 2nd - 3rd STAGE: every group numbers it on from 1st STAGE, so `- 07` is its episode 6) reads `Absolute` only: a number at or below the offset is an earlier part's, and the search queries the absolute number (`auto_search::query_target`), never the relative one. The user's choice on the series page (`series.episode_numbering`: empty for automatic, `anilist` for `Relative`, `absolute`) wins over the source; an offset of 0 is always relative. A real season tag (`S01E07`, `numbering::season_tag`) counts within its season under `Absolute`, as the import and the grab commit have always read tags, except a tag of the TVDB season the split was confirmed in (`series.cumulative_offset_season`, `Numbering::tag_season`: Steel Ball Run is TVDB S06 with 1st STAGE as `S06E01`, and 11 of the 17 groups measured tag it that way), which counts on from the earlier parts; the search gate and RSS let that season through (`Numbering::season_allowed`, RSS's `own_season`). Under `Either` the search gate and scoring still accept a tagged number equal to target + offset, as before #303. Under `Absolute` a single release whose run reaches back to the offset (`- 01-02`) matches nothing and records no episodes (the import refuses the file), while a pack of three or more (`01-12`, `S06E01-S06E12`) still matches its episodes for the upgrade sweep and scoring (`Numbering::pack_accepts`), since the import skips the earlier part's files one at a time; scoring's Season Mismatch uses `season_allowed` like the gate. Every reader of a release title or download file name takes a `Numbering`, never the bare offset: the search gate (`aliases::classify_match_detailed`), the interactive filter, scoring's Episode Number Match (its detail names the absolute number), `select_episode_set_hits`, `grab_commit::GrabSeries` / `relative_episodes` / `file_slot_episodes`, the picker's `file_episodes_for`, the import's `resolve_episode` / `claimed_ep_offset` / batch preflight, and RSS's `resolve_episode_numbers`. A lone video whose name holds no number takes the grab list as its span; under `Absolute` that list is the resolved episode already and no offset comes off it, unless `grab_commit::grab_list_numbering` reads it as the title's own numbers (recorded before the split was stored), which lose the offset as the file's own number would; under `Either` the claim rule reads it as before. Under `Absolute` the import's ownership check reads a grab list in the numbering its title shows (`grab_commit::grab_list_numbering`): the series' reading, or the title's own numbers when the list predates the stored split (a Search-page auto-add records `- 07` as `[7]` before the detached refresh stores the offset); counting both let a stray `- 06` in a SAB parent folder claim a `[6]` grab and replace the library's E05. A title that names no episode cannot say: both count while the download holds one video, and only the series' reading once it holds more, so a neighbor is never claimed by its raw number. Under `Either` both numberings count, as before #303. The RSS tie-break counts a row's episodes as placed only within its known count, so 1st STAGE (one episode) never wins `S01E06` from 2nd - 3rd STAGE when both carry the alternate title. RSS keys a split part's items by its offset too (`canonical_absolute_numbers`), so its episode 1 and the earlier part's episode 1 are two logical items. An auto-expand parent route of a split part carries the offset, but the import reads the grab's own routed files with the series' numbering (`post_processing::route_offset_for`), so a tag counts the way the coverage rows read it. The franchise pass and the franchise-name aliases run only for a rule or walk offset (`SeriesSearchCtx.franchise_offset`), never for a split: groups name a split by its own MAL entry, and the franchise head (`JoJo no Kimyou na Bouken`) would pull in every other part. `metadata_sync::build_episode_cache` and the series page's live fetch shift the MAL-numbered Jikan / Kitsu lists by the split (`mal_entry_split`: the relations' `split_prior_episodes` for the AniList id the list is cached under, else the row's stored split during a fallback refresh; no TVDB confirmation, since it describes MAL's list, not release numbering), Kitsu's `Episode N` placeholders renumbered with them, so the titles and air dates are the part's own. Library files are never read through it: Ryokan names them relative.
- `anime_relations.rs` — #206 curated absolute-numbering offsets. Parses the vendored `static/anime-relations.txt` (erengy/anime-relations, Taiga's episode-redirect table, CC0) into a destination-keyed index (AniList id, then MAL id; a Jikan-sourced row's `-mal_id` sentinel doubles as its MAL key). A rule contributes only `src_range.start - 1`; rules whose destination range does not start at 1 (mid-run remaps) or whose offset is not positive (episode-0 specials) are dropped, and when several rules share a destination the largest offset wins (root-relative numbering, what the PREQUEL walk sums to). `cumulative_prior_episodes(db, anilist_id, mal_id)` is the **single decision point** for `series.cumulative_prior_episodes` and its source (`series.cumulative_offset_source`, #303): rule first, then a split (`confirmed_split`: `local_metadata::split_prior_episodes` sums the PREQUEL chain's entries of any format that share the series' MAL id, and `anibridge::season_at_offset` has to place the entry at that offset in a TVDB season (the season is stored as `series.cumulative_offset_season`, whose tags then count on from the earlier parts), since a shared MAL id alone does not say how groups number it: Throne of Seal 3 shares MAL 52684 with Throne of Seal 2 and its one measured group counts from the first season), else `local_metadata::compute_cumulative_prior_episodes`; it returns `None` when a split is found but the mappings are not loaded, and then the refresh writer keeps a stored split and otherwise stores the walk (`plan_offset_write`, which also never lets a MAL / Kitsu detail overwrite a known offset, except with a rule); every writer (`metadata_sync::refresh_series_metadata` through `plan_offset_write`, `handlers::library::reconcile::maybe_hydrate_cumulative_offset`, which fires on a rule even when AniList lists no TV prequel, or on a PREQUEL sharing the series' MAL id, and `metadata_sync::apply_split_offsets`, the boot pass `main.rs` runs once the anibridge mappings load, which stores only a split the decision point returns) goes through it. `metadata_sync::hydrate_rule_source` caches the rule's source entry so `source_titles` (the search path's franchise aliases for a ruled series, falling back to the walk when the source is not cached) never fans out to AniList per search. No network path: the snapshot is refreshed by copying upstream's file over the vendored one; the round-trip test pins the rule count.

## Files and episodes

- **One file can hold several episodes (#246).** The span comes from the file name only (`media::parse_episode_span`); there is no per-file table. Every reader of the tag table or the disk scan treats the file as present for each episode in `EpisodeFile::episodes()`: the library have-sets (series page, library cards, auto-search `existing_eps`, monitoring, RSS, the upgrade sweep, the Sonarr shim's file count), the delete handler (`holds`, clears every tag / history row, `episode_numbers` in the `HX-Trigger` payload), reclassify and the `library_classify` sweep (one `episode_quality_tags` + `episode_grab_history` row per episode that needs one, written once per file; a pinned or already-confident episode is left alone), manual import (same-episodes refusal, a pin on any held episode pins the file). Import: `ResolvedEpisode` carries `episode_last`; the batch preflight ranks files by version, then single over multi, then file order, and each file takes every slot it covers or is superseded whole by the earlier holder (so `05-06v2` beside `05` and `06v3` still imports episode 5 from `05`, and `OVA 01-02` beside `01` / `02` is skipped rather than failing the pack; only equal version and equal shape on one slot fail closed); a lone unparseable video takes a contiguous `grab.episode_numbers` as its span (`span_from_grab_episodes`); `Imported` fires once per file; `grab_claims_episode` accepts a file when any held episode is claimed, the NFO is one `<episodedetails>` per episode (`nfo::write_multi_episode_nfo`, the Kodi shape Jellyfin reads), and `existing_for_ep` is an overlap check. **Sonarr's same-episodes rule holds in both directions**: a release covering fewer episodes than an overlapping file on disk is not imported (warn + `ImportFailed`, the grab fails and so blocklists; its grab-time rows are failed through `mark_grab_failed_for_release` and the refused episodes' tags are rebuilt from the disk file through `crud::reclassify_on_disk_episode`, because the grab-time upsert had replaced the file's `completed` row with the release's), `build_upgrade_targets` never targets a multi file, and RSS's `episode_is_upgradeable` wants the item to cover the file's whole span. The interactive grab (`grab_interactive_result`) records the run a range title names around the clicked episode (`grab_commit::grab_episode_list` with `GrabFor::Episode`: `release_title`'s reading, a run of at most `media::MAX_FILE_SPAN` that includes the episode, so `Show Season 2 - 03` is episode 3 alone) on the grab row and as grabbed tags, so every held episode shows as downloading. **Every grab path records its episode list through `grab_episode_list`** (the auto-search handler, the upgrade sweep, the interactive single and batch grabs, the Search-page grab in `library_link`, and the picker commit's title fallback): series-relative (a `SxxEyy` tag is already relative, otherwise a run past `cumulative_prior_episodes` is absolute, judged on its first number as the import judges a file, unless the searched episode shows the numbering), a pack that names no episodes takes the series' count (the AniList detail's when the caller has it, capped at 1000), and a whole-series release naming nothing is episode 1 only for a one-episode series. The upgrade sweep's `covered_by_batch` set is therefore relative too. The refusal fails only the refused episodes' rows (`mark_grab_failed_for_episodes`), because a batch's other files land in the same pass and `mark_completed` promotes `grabbed` rows only; pinned rows are left alone. Nothing searches for a release covering an exact span yet.
- **Specials are a name flag, not a season.** `media::parse_episode_span` sets `EpisodeSpan.special` for `OVA NN` / `SP NN` / `Special NN` / `OAD NN` (`RE_OVA_EP`, `RE_SPECIAL_EP`, both before the bare-number branches), Sonarr's number-then-marker shape (`RE_NUM_THEN_SPECIAL`: the marker has to end the segment, so `- 01 - Special Training` is an episode title), a bare marker segment past the first ` - ` or in brackets (`RE_BARE_SPECIAL`; `Special A - 01` keeps its name), and season 0. `media::has_special_marker` / `is_special_release` are the same rules for a release title. **What the flag means is decided by the series**: `media::is_tv_format` (AniList `TV` / `TV_SHORT`) turns it into a special; for an OVA / ONA / SPECIAL / MOVIE entry the marker is part of the series' name and the file is an ordinary episode. Consequences: the **scanner decides by place, never by name** (`EpisodeFile.is_special` = season 0 or a `Specials` path segment, `media::path_names_specials`), so an OVA-format series whose files say `OVA 01` keeps every one of them in its have-set while `Specials/` and `S00Exx` files are dropped by `scan_series_folder` whatever they are called (`scan_series_folder_split` lists them); the batch preflight puts a TV series' specials in `BatchPlan.specials` (a flagged name, a bare `- OVA` with no number, or a `Specials/` subfolder inside the pack; no slot, so `01` and `OVA 01` no longer tie and fail the grab); the import loop files them, when the grab claims them (a batch, a routed file, a legacy grab with no episode list, or a release that is itself a special by `media::is_special_release`; a `- 05` grab's folder-mate OVA is a stranger, as it was when `OVA 01` parsed to episode 1), through `import_special_file` into `<series>/Specials/` (`post_processing::SPECIALS_FOLDER`, a fixed name every scanner reads) as `S00Exx` through the episode template with `season_number = 0` (a numberless bare marker is E01; a second special rendering the same name in one pass gets its source stem as a suffix), no tag or history row, never overwriting; a grab whose files were all specials, imported or already there, counts as `Imported` with its source paths stamped, and the `grabbed` tag rows the picker or auto-expand wrote for the claimed episodes are cleared. The manual-import wizard shows them as **Special** (a `Specials/` or `Season 00` parent counts too) and copies them under their own name. The automatic search passes (`AutoQueryCtx.reject_specials = require_verbatim && is_tv_format`, read through `release_title`'s `is_special_for`, so a series whose own name ends in `Special` keeps its weeklies) and RSS reject special releases for a TV target; the interactive lists keep them, since a grab from there now imports into Specials. The search gates' episode reading (`release_title::ParsedTitle::for_series`) follows the same rule: a TV series' special names no episode, an OVA / ONA / special / movie entry's `OVA 01` is its episode 1 (`GatePrecompute::with_series_format`). Known gaps: nothing lists or deletes what sits in `Specials/` from the UI; a special imported into `Season 01` before this rule keeps its tag row.
- **`.strm` stubs are library files, never download files (#287).** `media::is_stream_stub` marks the text file Jellyfin / Emby / Kodi play in place of a video. The scanner (`media::is_library_file`), the manual-import walk (`walk::is_library_file`) and the upgrade's `existing_for_ep` count one as the episode's file, so an offloaded episode stays present and an upgrade retires the stub; `post_processing::is_video_file` (the download side) does not, because the URL inside a release would be the uploader's to choose. `classify_ffprobe` returns nothing for a stub without opening it, so an untagged stub is classified from its name. Sonarr's own `.strm` support comes from its Pneumatic client, which is why Sonarr also imports them from downloads; Ryokan deliberately doesn't.

## Metadata providers

- **Metadata fallback chain**: AniList → Jikan-shaped MAL provider (Tenrai by default) → Kitsu. Activates on AL 403s or force flags. Series added via Jikan with no AL mapping store as `series.anilist_id = -mal_id` (negative-ID sentinel); every AL call site filters `id > 0`. **A MAL id is not a series identity (#292)**: AniList splits some MAL entries in two (Steel Ball Run's 1st STAGE and 2nd - 3rd STAGE are both MAL 61469), so `series.mal_id` is not unique (the column UNIQUE the original `CREATE TABLE` carried is removed by a one-time table rebuild, `migrations::drop_series_mal_id_unique`). Look a row up by AniList id first; the MAL id answers through `series::get_by_mal_id_for_entry`, which for a positive AniList id matches only a MAL-fallback row (what `series::upsert` promotes), and `get_by_mal_id` (oldest row) is for callers that have nothing but a MAL id. Two places resolve the split the other way: the MAL-fallback promotion (`reconcile::maybe_reconcile_mal_entry`) asks `anilist::find_anime_details_by_mal_id`, a `Page { media(idMal:) }` query, because `Media(idMal:)` answers with one entry of a split; more than one match leaves the row a MAL series with an `AniList` warn naming the entries (once a day per row), never a guessed part. Watch-list sync applies a MAL list entry to every library row of its MAL id (`merge::existing_rows` / `update_existing_rows`, on both the anibridge-resolved and the Jikan path; anibridge maps a MAL id to one AniList id) and creates nothing beside them, and `detect_removals` keeps a row whose MAL id is on a MAL list (`fetch_mal_ids`), since those rows carry the sync stamp but not the entry's AniList id. The Sonarr / Radarr shims' add paths, when AniList is down and only the MAL detail came back for a requested AniList id, skip the entry with a `Library` warn if `series::other_anilist_entry_on_mal_id` finds another AniList entry of that MAL id in the library (the Sonarr fan-out continues with the other entries, Radarr answers 502), since `upsert` would hand back that sibling's row; and `anibridge::resolve_tvdb` / `resolve_tmdb_id` use a MAL-keyed mapping for a positive AniList id only when the mappings don't tie that MAL id to another AniList entry (`mal_speaks_for`), so a split sibling never reports the other part's TVDB season or TMDB id. The Search-page auto-add (`library_link::resolve_or_add_series_for_grab`) links a MAL search hit (AniList down) to the one library series of that MAL id, and answers `AmbiguousMatch` when there are several. Relation cards and artwork keys follow the same rule: `local_metadata::relation_identity_key` and `artwork::canonical_identity_key` key on the AniList id first and on the MAL id only for a MAL-sourced entry, "is this the page's own series" checks go through `local_metadata::same_relation_entry` (a MAL-sourced relation still matches the AniList entry carrying its MAL id), and `get_incoming_relations_for_provider` matches `related_mal_id` only across providers. Keyed on the MAL id, split siblings dropped each other's SEQUEL / PREQUEL cards as self-references, never cached them (so the PREQUEL walk for `cumulative_prior_episodes` missed a split TV sibling), and shared one cached cover. **Consequence**: SeaDex (keyed by positive AL id) and AL airing-schedule queries are silently invisible to these series. Jikan/Kitsu episode caches use a negative-cache sentinel (`episode_number = 0, title = "__RYOKAN_EMPTY__"`) — read sites must special-case it or the chain hot-loops. **Episode-title identity (#235)**: `kitsu::fetch_episode_titles_fallback` takes only the MAL id and resolves the entry through Kitsu's `/mappings` lookup (a Kitsu endpoint, so it still works while MAL is down); no MAL id, no mapping, or a failed lookup yields no Kitsu episodes rather than a guess, and the title fuzz (`best_candidate`) is never used for episode titles (it remains the *detail* fallback for a series with no MAL id). Kitsu's text search hides its NSFW entries, so the fuzz scored "Gabriel DropOut Specials" for Dropout (MAL 31886) and stamped that show's titles onto the series. `kitsu::get_anime_detail_by_mal_id` stamps `id_mal` on the detail for the same reason. The sentinel is written only for a real empty list: `jikan::fetch_from_jikan` returns `Err` when nothing was fetched (network, 5xx, 429, active cooldown) and both readers keep whatever was cached instead. The manual rebuild (`refresh_series_metadata_inner` with the rebuild flag) calls `jikan::invalidate_episode_cache` for the series' MAL id before the merge, so "Rebuild metadata cache" re-asks Tenrai once per tracked series; the periodic refresh stays cache-driven. **`is_adult`** (issue #219) comes from AL `isAdult`, a Jikan `rating` starting with `Rx`, and Kitsu `nsfw`; it lives on `AnimeDetail` (`#[serde(default)]` for older cached blobs) and reaches `series.is_adult` only through `metadata_sync::refresh_series_metadata` → `series::set_is_adult`, so a freshly added row reads false until its first refresh. Nyaa hosts adult releases on sukebei, which Ryokan does not search; auto-search logs a warn for adult titles instead of skipping them, since a torznab/newznab indexer can still find them. When no indexer is configured at all (`handlers::library::adult_needs_indexer`), the series page shows an `alert-warn` banner and the auto-search terminal toast carries the same note through `AutoSearchReport.notes`. The note rides on the terminal event because the sticky progress toast shows one event at a time, so a mid-search `warn` event is overwritten by the next "Searching" line before anyone sees it.
- **Provider episode counts are bounded.** Every count or episode number from AniList, Jikan or Kitsu goes through `anilist::plausible_episode_count` (1 to `MAX_PLAUSIBLE_EPISODES`, 5,000; anything else is unknown, like a missing count) where the mappers build `AnimeDetail`, and `AnimeDetail`'s `episodes` / `next_airing_episode` deserialize through it so cached blobs are covered; `monitoring::effective_episode_count` applies it to the stored row and the local episode map. The episode table, monitoring and auto-search build `1..=count` whole, so an `i32::MAX` count was an 8 GB allocation.
- **Two metadata-cache windows.** `CachedSeriesMetadata.is_fresh` is the 12-hour refresh window (`metadata_cache::METADATA_REFRESH_INTERVAL_HOURS`) that `handlers::library::reconcile` uses to decide whether to fetch again. The series page's "Metadata may be out of date" banner keys on `is_stale` (`METADATA_STALE_WARNING_DAYS`, 7 days without a successful refresh), never on `!is_fresh`: a row is past the refresh window between any two sweeps, so that showed the banner on nearly every page view.
- **Outbound fetches of third-party URLs are bounded.** Admin-configured endpoints (download clients, indexers, Jellyfin, webhooks, feed URLs) point at the LAN by design and are not filtered. URLs that come from someone else are: `source_description` fetches a result's link only when `nyaa_view_url` maps it to `<nyaa base>/view/<id>` (a Nyaa RSS `/download/<id>.torrent` maps to its page; torznab download URLs, direct-feed links and SeaDex tracker strings are skipped) and follows redirects only on the same host; `artwork::cache_image` caps the body at 20 MB and keeps it only when `sniff_image_type` reads a JPEG / PNG / GIF / WebP / AVIF magic number, and `/media/art` serves the sniffed type (never the stored upstream `Content-Type`) with `default-src 'none'; sandbox`; ffprobe stdout over 4 MiB is dropped (`FFPROBE_STDOUT_CAP`); release URLs pass `download_client::check_release_url` (magnet / http / https) before any client sees them. Every third-party body is size-capped: artwork, the description fetch and Nyaa pages read through `services::http_body::read_capped`; AniList, Jikan, Kitsu, MAL, SeaDex and the OAuth token endpoints use `http_body::CappedBody` (`.text_capped()` / `.json_capped()` in place of `.text()` / `.json()`, `PROVIDER_BODY_CAP` 16 MB); RSS and torznab have their own caps. New provider calls use `CappedBody`, never a bare `.text()`. SeaDex view URLs and the description fetch both go through `nyaa::view_page_url` (the Nyaa origin and `/view/<id>` only), and the Nyaa client follows redirects only on the same host. The AniList pacer holds its turn lock across decide / sleep / stamp; Jikan episode lists stop at 50 pages and a MAL list drain errors past 200 pages rather than return a partial list. No private-address filtering yet: every client still follows reqwest's default redirects.

## Scoring and feeds

- **Custom Formats** are Sonarr-style (TRaSH-Guides-compatible). The `SpecKind::SeaDexBest` variant in `services/custom_formats/` is a Ryokan-only extension matched against SeaDex picks at scoring time — accepted under both `Ryokan.SeaDexBestSpecification` and the shorter `SeaDexBestSpecification` implementation name, emitted in the long form on export. **Presence of a CF using `SeaDexBest` suppresses the separate `seadex_enabled` config toggle** so the CF and toggle don't double-count. Preserve that one-or-the-other invariant. A spec whose regex hits fancy-regex's backtrack limit is unmatched whether or not it is negated (`evaluate_spec_kernel` returns `None`). The import review's per-collision choice is a radio (`cf_action_<index>`, `cf_rename_<index>`) that `settings_custom_formats_import_resolve` reads itself (`collision_decisions`; the `decisions` / `renames` lists `settings.js` builds from the same radios win when filled), and a colliding entry that arrives with no decision is skipped: the handler used to read only the script's lists and default to overwrite, so the form posted without the script replaced every Custom Format left on Skip.
- **RSS dedup** (`services/rss/feed.rs`) keys `rss_seen` entries by `hash:<info hash>` when the item carries one, then `guid:<item.guid>`, falling back to item link. Tombstones survive across restarts. A `grabbed` row is the tombstone the sync's dedup set is read from (`rss::grabbed_item_keys_scoped`), so `rss::record_decision` never replaces one with a later decision that is not a grab, and the sync counts an already-grabbed item as skipped without writing anything: the "skipped" it used to write there re-grabbed the item on every second sync. A grab's hash is the feed's `<nyaa:infoHash>` when present, else the download URL's `btih`. The RSS task uses `RSS_SYNC_LOCK` with `try_lock` so a manual "run now" during the 60s tick returns "RSS sync is already running" rather than queuing.

## Notifications

- **Custom scripts (#288, `notifications/script.rs`)** are a third provider kind, `script`: Sonarr's Custom Script connection. Config is `{path, timeout_secs}` (default 30 minutes, at most a day); nothing in it is a secret, so the path is shown on the card and in the form. **`send` only queues**: the dispatcher gives a provider 5 seconds and a re-encode takes minutes, so the run goes onto the process-wide `script::QUEUE` and one worker runs them one at a time, in order (a pack's twenty imports must not start twenty encoders). A full queue drops the run with a "send failed" warn. **A queued run carries the provider's id, not its settings** (`current_config`): when it comes up it reads the row again and is dropped ("Script run dropped", info) if the provider was deleted or disabled, is no longer a script, or has the event unticked, and otherwise runs with the path and limit saved now. Without that, deleting a misbehaving script left a pack's remaining runs going for hours. The dispatcher logs a script's accepted event as "queued", and the worker writes one `Notifications` row per run: "Script finished" (info, exit 0), "Script failed" (warn, with stdout too), "Script timed out", "Script ended by a signal", or "Script not run" with the reason; each carries the exit code, the time taken and the **end** of stderr (`script::tail`: the last 4 KiB kept, the last 1,000 characters logged; `notifications::truncate` keeps the start, which is the banner and not the error). **The run** (`script::run`): the resolved path directly, no shell, no arguments, stdin closed, the script's folder as the working directory, Ryokan's environment minus `RYOKAN_ENCRYPTION_KEY`, plus `ryokan_eventtype` and one `ryokan_<field>` per field of the event's `data` (`event_env`: a missing value is an empty variable, a list is joined with `|`, a value is cut at 32 KiB because Linux refuses a single one over 128 KiB). The names are lower case because Sonarr's `Sonarr_*` names reach a script lower-cased on Linux. **Stopping at the limit**: the script leads its own process group, which gets SIGTERM; a shell dies at once, so the wait is for the whole group to empty (`group_gone_by`, up to 5 seconds, polled) and only what is left gets SIGKILL, which lets an `ffmpeg` under a wrapper finish its file. `reap_orphans` collects the group's exited members when they are Ryokan's own children, which is the case only when Ryokan is the container's PID 1 with no init (the official image, `exec gosu`): there they would otherwise stay as zombies and keep the group looking alive. It is called only after tokio has waited for the script itself, so it never takes the child tokio is waiting on. Dropping `run`'s future stops the script alone (`kill_on_drop`), not its group, so it only runs in tasks that are never dropped: the worker's, and one `run_test` spawns. Output is read for one second after exit so a background job holding stdout cannot keep the run open. **A stop of Ryokan ends the running script the same way** (`run_with_grace` selects on `Shutdown::wait`; logged as "Script stopped"), since it would otherwise outlive the process that enforces its limit; the run holds a `shutdown::begin` hold until its log row is written, no run starts after a stop, and `main.rs` logs how many were left waiting (`script::waiting`). The queue is in memory, so those are not picked up after a restart. **Known gap**: a script that exits normally and leaves a background job behind is allowed to (nothing is signaled on a normal exit); in a container with no init that job is a zombie once it ends. `init: true` in compose, or tini in the image, is the fix. **Guards, since the kind is on by default** (`RYOKAN_CUSTOM_SCRIPTS=0` turns it off; `script::enabled()`): `check_path(db, path)` wants an absolute path to a regular file that is executable for Ryokan's user (`access(X_OK)`), not equal to or under Sonarr's system-folder list (`SYSTEM_FOLDERS`: a `/sbin/reboot` needs no arguments), and not a file from a download as far as Ryokan can tell: not under `config.media_root`, `recycle_bin_path` or a download client's `download_path`, and not the content of a grab on record (`is_grabbed_content`, `grabbed_torrents.client_content_path`; that is what catches the hardlinked twin of a library file in a download folder the settings don't name). The folder rules apply to the path as typed and as resolved, so a link into `/usr/bin` is refused, and `PathPolicy::load` returns `Err` on a failed settings read rather than an empty policy that would pass everything. It runs on save (`build_script_config`), in Send test, and again before every run, because the file can change in between; `ScriptProvider::from_row` checks only the config's shape, so a script missing at startup is not dropped for good. **None of this is a security boundary, and the docs must not say it is.** The executable bit is not one: libtorrent (qBittorrent, Deluge) sets it for a file its torrent marks executable. A download folder Ryokan was never told about, holding a file that is not yet a recorded grab, passes. What keeps a stranger out is the login, as in Sonarr, which checks the system folders and nothing else. Don't add arguments (Sonarr removed its own in 2019), a shell, or an inline script body. **Send test** (`run_test`) skips the queue, runs once with `ryokan_eventtype=Test` and a 30-second limit, and answers `{exit_code, output}` (`handlers::notifications::TestOutcome`), which `system.js` reads apart from a receiver's `{status, body}`. The per-provider event matrix applies as for the other kinds; the Add form ticks Imported alone when the kind is switched to script (`system.js`, add flow only). The functions that depend on the switch take it as an argument (`build_providers`, `build_script_config`) so tests cover "off" without touching the process environment.
