# services/post_processing/AGENTS.md

Importing a finished download into the library: the file operation, what happens when an import cannot proceed, cleanup afterwards, and routing a pack's files to sibling series. Multi-episode files, specials, `.strm` stubs and episode numbering are read here but are rules for every service: `src/services/AGENTS.md`.

Keep this file under 40,000 characters (`wc -m`): past that, a Claude Code session with a 200K context window is given only its start. `tests/agents_md_audit.rs` enforces it.

## Import modes

- **Post-processing import modes** (`services/post_processing/mod.rs::do_file_op`) keyed off `config.post_processing_mode` (validated to `hardlink` / `copy` / `move`):
  - `hardlink` (default, seed-safe — original stays for the client to keep seeding). Falls back to copy when `fs::hard_link` errors (cross-filesystem common case). The import log names the link error when it fell back (`do_file_op_reporting` → `mode_used`). A symlinked source is imported as the file it resolves to (`do_file_op` canonicalizes it; move mode links or copies the target and removes only the link).
  - `copy`.
  - `move` — `fs::rename` same-fs; cross-fs uses copy-to-`.ryokan-tmp`-then-rename so a partial copy can't be observed at dst by a subsequent pass; source-remove after cross-fs move only logs a warning on failure.
  - The full op runs in `spawn_blocking`. Artwork fan-out uses `fs::hard_link` (banner ↔ backdrop sharing inode) with `fs::write` fallback.
  - **Upgrade-replace is place-then-swap** (issue #202): when the SxxExx slot already has a file, the new one lands at `staging_path(dest)` = `.<basename>.ryokan-new` in the season dir first; only after that succeeds are the old files retired through `recycle::recycle`, the staged file renamed onto `dest` (same directory, atomic), and the old torrent deleted from the client + `mark_replaced`. A failed placement leaves the library and the old grab untouched; a refused recycle undoes the staging (`unstage_upgrade`: remove in hardlink / copy modes, move back in move mode). The leading dot on the staging name is load-bearing: the recycle bin's companion sweep takes every `<stem>.`-prefixed sibling, and a `<dest>.ryokan-new` name would be swept away with the file it replaces.
  - **Import extra files** (`post_processing::extras`, Sonarr's "Import Extra Files"): after a video lands (the `Ok(())` arm, so after an upgrade's place-then-swap), and only with `config.import_extra_files` on (default off), `extras::import_subtitles` takes the download's own files (`wanted` only, through `validate_relative_path_fragment` like the video loop, since the name is the client's, and only when it resolves to a regular file inside the download, `resolves_to_file_inside`, since a torrent can carry a symlink) with a `config.extra_file_extensions` extension (`parse_extensions`, default `srt,ass`, video extensions dropped) from the client's list, or `walk_extras` of the video's folder (depth 2, symlinks skipped) when Ryokan listed the videos itself; a file belongs to the video when its stem starts with the video's, when its own `parse_episode_span` equals the video's, when its parent folder is named that way (Erai-raws' `Subs/<episode>/<lang>.ass`), or, when nothing matched and the download holds one video (wanted or not, so a pack narrowed to one episode never triggers it), every one; names it `<episode stem>[.N][.<lang>][.<tags>].<ext>` (`language_and_tags`: trailing tokens only, tags then one language, so a title word is never a language and `hi` is the hearing-impaired tag; N only when several of one kind), through the same `do_file_op` mode, never overwriting. No database row: the scanner ignores non-video files, the recycle bin's `<stem>.` companion sweep retires them with the video, and the import's `existing_for_ep` lookup is videos-only so a previously imported subtitle never becomes its own recycle entry. The manual-import wizard does not import subtitles.
  - **Remove after import (#228)**: `client_cleanup::remove_after_import` runs on `ImportOutcome::Imported` only (partial / failed stay) when the grab's client row has `download_clients.remove_completed` on (per client, default on, Sonarr's "Remove Completed"): usenet jobs and move-mode torrents are deleted from the client with files (`delete(hash, true)`) and `grabbed_torrents.client_removed_at` is stamped; for usenet the stamped `imported_source_paths` outside the media root are unlinked too (SAB `del_files` no-ops when `storage` is the parent complete dir; with no media root nothing is unlinked). The full-import arm stamps `grabbed_torrents.import_mode` with the mode; the partial arm stamps `partial`. `client_cleanup::sweep_finished_seeds` (after every `run_once` tick from `main.rs`; `SEED_SWEEP_LOCK` try_lock + 5-min throttle; gated like `run_once` on `post_processing_enabled` + `media_root`) walks `list_imported_in_client` (state imported **and** `imported_at IS NOT NULL` **and** `import_mode != 'partial'`, so `mark_completed_no_import` rows and partial imports, whose failed episodes still sit only in the download folder, never qualify): client switch off → skip; item gone → batch-stamp; usenet present + complete → remove; row imported in move mode (`import_mode`, or the current mode for pre-1.9.3 rows) whose stamped sources are all missing **while their parent folder exists** → remove (a dropped mount takes the folder too and reads as waiting); errored → wait; `DownloadItem::seeding_done` (per-impl rules in `src/services/download_client/AGENTS.md`) → remove; else wait. A failed delete stays unstamped and retries. `record_grab`'s reactivation clears the stamp. `remove_stamped_source_paths` lives here now and is re-exported into `handlers::library::episodes`.
  - **Batch preflight** (`validate_batch_episode_map` → `BatchPlan`): every wanted video is resolved to its `(series, episode)` slot before any mutation. Files that parse to `None` (extras) are absent from `slots` and warn-skipped by the loop; two files on one slot with **different release versions** keep the highest and list the rest in `superseded` (issue #204, info-logged "superseded by"); a tie on version fails the whole grab with "no files were changed".

## When an import cannot proceed

- **`post_processing` stall timer (#205)**: `run_once` stamps `grabbed_torrents.completed_seen_at` (idempotent, first writer wins; `record_grab`'s reactivation clears it) on the first tick that sees the client report a grab complete. A grab that keeps coming back `ImportOutcome::NotReady` (no importable video visible: unmounted download path, SAB complete dir not translated, all-extras release) for longer than `config.import_stall_hours` (default 24, `0` = retry forever, Settings → General → Post-Processing) is marked failed with `failure_reason = 'import_stalled'` (`IMPORT_STALLED_REASON`) plus `episode_tags::mark_grab_failed_for_release` and an `ImportFailed` notification, so the failed row is the blocklist entry and the series page stops saying "Importing". A grab judged a misgrab in the same tick is left to the misgrab sweep. Measured from `completed_seen_at`, never `grabbed_at`: a slow download is not a stall. The stamp is wall-clock, so `escalate_if_stalled` also stays quiet for `IMPORT_STALL_BOOT_GRACE_SECS` (15 min) after `AppState.start_time`: a grab stamped before a long shutdown would otherwise fail on the first tick after boot with zero retries in this process (download mount coming up after Ryokan). `build_test_app_state` pins `start_time` to 2024, so tests opt into the grace by setting it. The `PostProcess` warn is written *after* `mark_failed_with_reason` succeeds so it is true when it lands and fires once. `AllFailed` / errored-in-client paths still fail immediately without a reason; `AllFailed` and an import error also fail the `grabbed` tag and history rows the grab wrote (`fail_grab_tags`, the release-wide `mark_grab_failed_for_release` the stall path uses), since the card otherwise kept reading "Downloading" for a grab that is gone. **A client file list is not proof the files are there**: qBittorrent always answers `get_files`, so `import_torrent` checks (under `spawn_blocking`, after the readiness and misgrab checks) that at least one wanted video exists at `source_base` + its name and returns `NotReady` when none does, with one `Import waiting for` warn per grab per 6h (`logger::first_in_window`) naming the expected path. Without it an unmounted or unmapped download path reached the file ops, every one failed with ENOENT, and the grab came back `AllFailed`: failed and blocklisted on the first tick, never retried. A download with some files visible still imports, and its missing files fail as before.
- **Failed-download re-search** (`services::redownload`, Sonarr's `RedownloadFailedDownloadService`): `post_processing::run_once`'s errored-in-client branch (`DownloadItemState::is_errored`, the client's own failure report: SABnzbd `Failed` and qBittorrent `error` only; qBittorrent `missingFiles`, a Transmission local error, Deluge `Error`, and an rtorrent item stopped with a message map to `DownloadItemState::Warning`, Sonarr's warning status, which post-processing waits on, because this branch deletes the item with its data and a dropped download mount must not cost the data once it is back; the branch also sits out `IMPORT_STALL_BOOT_GRACE_SECS` after boot, like the stall timer) fails the grab with `failure_reason = 'client_error'` (`CLIENT_ERROR_REASON`, "Download failed" on the Blocklist tab), fails its tag rows through `mark_grab_failed_for_release`, emits `ImportFailed`, removes the item from the client (`redownload::remove_failed_from_client`, unless seed rules apply or the client row's `download_clients.remove_failed` is off: Sonarr's per-client Remove Failed Downloads, default on, set through `set_remove_failed` like `remove_completed`, a legacy grab with no stamped client follows the default), and once per series per sweep calls `redownload::after_failed_download`, which honors `config.auto_redownload_failed` (default on) and a loop breaker of `LOOP_BREAKER` (3) failed grabs per series in `WINDOW_HOURS` (24, `grabbed_torrents::count_recent_failed`), then runs `search_replacement`: an episode search for a one-episode grab, else the series' auto-search (which covers every missing monitored episode). The misgrab sweep shares `search_replacement` behind its own misgrab counter. **Import failures are deliberately not re-searched**, as in Sonarr: `AllFailed`, an import error, and `import_stalled` blocklist and stop. `run_once.rs`'s `seed_config` sets the switch off so no test spawns a live search.

## Cleanup

- **`cleanup` extras (#205)**: besides the DB prunes and the recycle purge, the hourly tick runs `post_processing::temp_sweep::sweep_orphaned_temp_files` over `config.media_root` for `*.ryokan-tmp` (the cross-fs move's partial copy) and `.<name>.ryokan-new` (the #202 upgrade staging file) older than `ORPHAN_MIN_AGE` (2h by mtime). Two phases: the walk (`spawn_blocking`, walkdir, no symlink following, `max_depth(4)`, canonicalized root and recycle-bin exclude) only collects candidates; removal happens under `POST_PROC_LOCK` **and** `manual_import::import::IMPORT_LOCK` (`try_lock`, the hour is skipped when either is busy), because a `.ryokan-new` made by `hard_link` or a same-fs `rename` inherits the *source's* mtime and reads hours old the second it is staged; with both locks held nothing can be mid-copy, so what is left is a crash leftover. `.ryokan-tmp` is a direct unlink (always a partial, or a duplicate of a source still in place); `.ryokan-new` goes through `recycle::recycle` (in move mode it can be the only copy of the episode) with the series *folder* name as the manifest title, since the sweep has no series row; a recycled file counts nothing toward `TempSweepReport.bytes` (it still sits in the bin) and a restored one is swept again next hour, so the docs tell the user to rename it instead. Directory-form `<dst>.ryokan-tmp` from a crashed cross-fs recycle *restore* is not covered. Errors ride on the task's `warn` status plus a `PostProcess` warn line.

## Auto-expand

- **Auto-expand** (`services::auto_expand::expand_from_files`) is sibling-series detection inside a batch pack — distinct from megapack narrowing in the `DownloadClient` trait. Two call sites: grab-time (180s metadata wait inside a `tokio::spawn` after the HTTP handler returned) and import-time (safety net when grab-time bailed). Writes per-sibling rows into `grabbed_torrent_series` so post-processing routes each file into the correct sibling folder. **Transitive relation walk**: AL's relation graph has missing direct edges across split sagas (Monogatari case); `expand_from_files` fetches walkable neighbors capped at `auto_search::TRANSITIVE_WALK_MAX_FETCHES`, grafts their relations onto the parent before sibling detection. Failed neighbor fetches are soft. **Absolute-numbering offsets**: each sibling route carries `episode_offset` so stored episode numbers are *effective* (post-offset) values — upgrade-search for "Egypt-hen E1" finds the route whose files were originally numbered E25 on disk. **Grab-tag backfill** writes `episode_quality_tags` + `episode_grab_history` rows for every sibling at grab time so each sibling's page shows `grabbed` immediately. **AL-overflow** episodes (parsed episode > `parent_episode_numbers`, e.g. smol Owarimonogatari BD splitting aired E1 into two files producing disk-level E13) get the same backfill so the overflow row renders during download rather than after import. **Parent-route fallback**: every unclaimed media file routes to the parent series; unclaimed alongside sibling routes triggers a `warn` log so misdetection surfaces in System → Logs. **Not load-bearing under failure** — if grab-time aborts, the grab row is already recorded and import-time rescues it; never synthesize an empty grab row to mark auto-expand "complete."
