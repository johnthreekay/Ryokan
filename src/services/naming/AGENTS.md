# services/naming/AGENTS.md

Naming templates (#124) for series folders, season folders and episode files. The root rule stands everywhere: destination names come from here, never from a `format!`.

Keep this file under 40,000 characters (`wc -m`): past that, a Claude Code session with a 200K context window is given only its start. `tests/agents_md_audit.rs` enforces it.

## Layout

- `naming/` — #124 naming templates. `render` / `validate` / `preview` over `{series.title}`-style lowercase-dot tokens with a `:00` zero-pad spec; the three defaults (`DEFAULT_*_FORMAT`) are byte-identical to the pre-#124 layout. Each token value is sanitized on its own (`media::sanitize_folder_name`), then an empty-token cleanup (empty bracket pairs, doubled ` - `, dangling edge separators, `..` / `__` runs) runs on the template's **literal runs only**, never inside a value. NAME_MAX truncation shrinks `{series.title}` first, then `{episode.title}`, then hard-cuts; the episode number and `{ext}` always survive. **`series_folder` is applied once, in `series::upsert`** (which reads `config::get_naming_prefs` itself so its fifteen call sites need no plumbing) and persisted on `series.folder_name`; a name another series row already has (case-insensitively) gets ` (year)`, then ` (2)`, ` (3)` (`unique_series_folder`), since two series in one folder read each other's files; a name regenerated for a row whose stored one is empty or unusable (`load_series_import_ctx`, the manual import) goes through the same rule with that row excluded, and the manual-import preview projects a new series' folder with it (`series::unique_folder_among`); removing a series with files keeps a folder another row still names (folder status `shared`), since rows written before the rule can share one; **a removal always removes the row**, whatever the cleanup managed, so what stayed behind is reported rather than retried: the single remove answers `folder` (`error` / `refused` / `shared`) and `torrent_errors`, which `series_lifecycle.js` turns into one queued toast and the handler into a `Library` warn line, and the bulk delete lists such a series under `failed` with `BulkFailure.removed = true` (its card is dropped, its sync exclusion is written, and a toast of its own says what was left), so only a `failed` entry without the flag is still in the library; `season_folder` / `episode_file` run on every import (`post_processing::load_series_import_ctx` + the per-file `episode_name_context`, whose quality / group read the grab-time tag row and fall back to a filename-only classification; manual import's `preview::season_folder_name` / `import.rs`; the Sonarr / Radarr shims for the would-be path of a series not yet in the library). `validate` requires `{ext}` last and `{episode.number}` present, rejects `/` `\`, renders the sample **and** a sparse context (no year / title / quality / group) to catch templates that go empty, and parse-backs the sample through `media::parse_episode_number` so a template can never produce a name the scanner can't read. For the same reason the upgrade path's `existing_for_ep` is parser-based rather than an `SxxExx` substring check. **Multi-episode files (#246)**: `NameContext.episode_last` above `episode_number` makes `{episode.number}` render the range, `05-E06` when the literal right before the token ends in `E` (`S01E05-E06`, Sonarr's prefixed range) and `05-06` elsewhere (` - 05-06`); `validate` also renders `multi_episode_sample_context` (E07-E08) and parses it back through `media::parse_episode_span`. `{episode.title}` for such a file is the held titles joined with ` + ` (the import builds it), and `NameContext::slot_label` is the `S01E05-E06` display form. Settings → General renders `handlers::settings::naming_panel`; the live preview posts all three templates to `POST /api/settings/naming-preview` (`handlers/settings/naming.rs`), server-rendered so there is no JS resolver to drift. **`{episode.absolute}`** is Sonarr's `{absolute}`: `NameContext.episode_absolute = series.cumulative_prior_episodes + episode` (a range `019-020` for a multi file), filled by `load_series_import_ctx` from `series::absolute_offset_if_known`, which returns `None` until `series::update_cumulative_prior_episodes` has written the offset (`series.cumulative_offset_known`, set by that single writer only when the value came from a curated rule or an authoritative AniList detail, never from a MAL / Kitsu fallback whose relations the walk never saw; on and never off; the column defaults to 0 so a sequel whose PREQUEL chain is not hydrated renders no number rather than the wrong one) and always `None` for a special. The sample context carries `episode_absolute = 19` against episode 7 so `validate`'s parse-back catches a template where the absolute number sits in the episode slot. Renaming an existing library to a new template is deliberately out of scope.
