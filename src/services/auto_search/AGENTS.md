# services/auto_search/AGENTS.md

The search gate: which releases count as naming a series, how a candidate's match is recorded, and what the automatic paths refuse that the interactive lists show. Episode numbering, which the gate reads through `Numbering`, is in `src/services/AGENTS.md`; franchise identity is in `src/services/identify/AGENTS.md`.

Keep this file under 40,000 characters (`wc -m`): past that, a Claude Code session with a 200K context window is given only its start. `tests/agents_md_audit.rs` enforces it.

## Title gate

- **Auto-search title gate** (`services/auto_search/aliases.rs::matches_target`, mirrored by the relaxed interactive gate in `auto_search/mod.rs`): the episode check reads the title with `release_title`'s `for_series` through the anchors `GatePrecompute` builds once per sweep, so a number inside the series' name never counts (`Kaiju No. 8 - 09` is not episode 8, `Mob Psycho 100 (BD)` is not episode 100) and a bare number right after it does (`[EA]Dark_Gathering_24_`); scoring reads the same way with the franchise aliases added (`scoring_anchors`). A release matches an alias either verbatim (the normalized alias is a substring of the normalized title) or fuzzily. **Automatic paths take only verbatim (or SeaDex-curated) matches**: `AutoQueryCtx.require_verbatim` drops fuzzy hits in `run_queries` and collects their titles, `find_best_for_target_with_diag` hands them to the auto-search handler for the "none named the series exactly" report line, and RSS rejects an `alias_score` below 1.0 with "Title does not name the series exactly". A verbatim hit whose series title (`release_title`'s `series_title`) still has a word left after removing every alias word (`aliases::names_more_than_the_series`: "Dr. Stone New World" for Dr. STONE, "Mob Psycho 100 II" for Mob Psycho 100) is skipped the same way, which is how sequels named by subtitle stay out without a relations walk; the one exemption is the `Title - Episode Title - 05` shape, where the series title runs on into the episode title, so when the first dash segment names the series and nothing else a later segment counts only if a leftover word reads like a season or part marker (`is_season_marker_token`: season, part, cour, arc, hen, final, roman numerals, ordinals). **Then `services::identify`**: every collector loads the series' franchise once per pass (`identify::load_franchise` onto `GatePrecompute::with_franchise`), and after the alias, season and episode checks pass, a release another entry of the franchise fits better (`Verdict::Rival`) is dropped on automatic paths and reported on the toast ("named the series but fit another entry of it better", `GateDiagnostics.looked_like`); the interactive lists drop only names-more rivals and keep the rest labeled "looks like <entry>", scored -40 (a tie -10). A tie is decided by Sonarr's identity first (a title whose name is exactly one entry's clean title, years and season words kept, is that entry's), and a tie that remains with another **library** series is dropped on automatic paths (`GatePrecompute::with_tracked`, "fit another series in the library just as well"), as Sonarr rejects a release two library series fit; a tie with an untracked entry is accepted. This replaced the sibling-title overlap rule (`sibling_match_rejects`, retired). Rejected titles are noted once per sweep (`AutoQueryCtx::note_rejected`) and a release rejected in a `run_queries` call is not re-classified by that call's other queries and categories (`rejected_here`); it stays out of `seen` so a later pass with more aliases can still admit it. The batch collector (`collect_scored_batches_for_target`) runs for a `BatchList`: `AutoGrab` (the batch auto-grab) takes only releases whose titles say they are packs and name the series exactly; `Interactive` (the series page's and the Wanted page's batch list) drops the verbatim rule and also offers **unnumbered packs**, titles that name the series exactly and nothing of what it holds (`[UTW] Angel Beats! [BD][h264-720p AC3]`, `release_title`'s `is_unnumbered_pack_for`, verbatim and `names_more_than_the_series` false). Over the 29k-title corpus such disc titles held four or more files 68% of the time and one file 19%, so they are offered as batches with a "no episode numbers" tag (a title year outside the series' years, `Fruits Basket (2019)` for the 2001 show, rules one out; a SeaDex pick of that shape is tagged too), and their Grab opens the file picker even when grab previews are `never` (`data-unnumbered`); with no info-hash the picker cannot open, and the direct `grab-batch` post carries `unnumbered`, which records no episodes until the files are read (a titled no-range batch still records the series' count). The automatic grab never takes one on its title; a SeaDex pick that names no episodes it already took, as before. The user closes a naming gap per series with `series.alternate_titles` (one per line, the Advanced search overrides panel). **Alternate titles are primary aliases**: `resolve_search_overrides` reads them off the series row into `SeriesSearchCtx.alternate_titles`, and every collector folds them into both the gate's alias list and the canonical query list (`add_alternate_aliases`, plus the preferred-group queries), so they drive the primary queries and match verbatim without waiting for a metadata sync. `auto_search::with_alternate_titles` also folds them into the detail's synonyms once at `resolve_series_context`'s single exit (every path: cache, live AniList, MAL, Kitsu) and in the upgrade sweep; the RSS `SeriesMeta` and the misgrab alias set read the row directly. AniList synonyms themselves still enter only through `collect_extended_aliases`, the zero-candidate fallback pass. That pass drops a synonym that is a related anime entry's title, and `split_title_segments` skips the leading segments of a title that together spell one ("Sousou no Frieren: ●● no Mahou" is the minis of "Sousou no Frieren"; that head grabbed the parent's BD batch for them). A head no related entry is titled stays only for a franchise's first entry ("Mushoku Tensei" for the first cour): for an entry with a PREQUEL or parent anime relation (AniList `PARENT`, MAL `PARENT_STORY`) the segments naming the franchise (`aliases::franchise_names`, #300: "JoJo no Kimyou na Bouken" from "JoJo no Kimyou na Bouken: Steel Ball Run - 2nd & 3rd STAGE" matched the 2012 series' `01-03` pack verbatim) are never extended aliases. They are found by position-free rules, since MAL puts the subtitle first ("Steel Ball Run: JoJo no Kimyou na Bouken"): a segment that is or starts a prequel's / parent's first title segment, or is one of their whole titles (the Mugen Train movie's prequel is "Kimetsu no Yaiba"), then the segments beside the entry's own name in the other titles, else a title's first segment when every word of it is in an earlier entry's titles (so "JUJUTSU KAISEN Season 3" and "Kizumonogatari II" stay the entry's own names). `resolve_search_overrides` adds them to the franchise aliases when the series has a franchise offset (`SeriesSearchCtx.franchise_offset`: an absolute offset from a curated rule or the TV walk, never a split, #303, and never under AniList numbering), so they match only the absolute number there; the extended pass reads them as anchors (`GatePrecompute::build_with_anchors`, so `Steel Ball Run - JoJo's Bizarre Adventure 02` keeps its episode), and the misgrab verdict does not count one as naming the series. The batch auto-grab reports the rejected titles too (`find_best_batch_for_target_with_diag`). RSS reads a feed item's episodes and season through `release_title` too (`rss::parse_release` keeps only its alias views; `resolve_episode_numbers` reads `for_series` with each series' anchors, maps an unbound number past `series.cumulative_prior_episodes` the way `Series::numbering()` reads it (never under AniList numbering), else past the tracked seasons before it, and gives a series named by its season, or a split part (#303), no unbound number at or below that offset), and an exact score tie goes to an exact alias, then the item's own season, then placed episodes, then the oldest row, never list order; `match_library_title` (autobrr, the Search page) is the same matcher. RSS matches against the row's titles and alternate titles in normalized, core and collapsed forms (`rss::SeriesMeta`). **An item's title inside an alias** (`alias_holds_item`) counts only as a run of the alias's whole words (spacing and punctuation aside, so `ReZero` is `Re:Zero`) whose leftover words are season or part markers, generic words, or the series' franchise words; when the item names the season the row's own names give (`SeriesMeta::named_season`: a season word, ordinal, tag or Roman numeral, never a `Part N` / `Cour N` reading), or the TVDB season a split part counts in (#303, `SeriesMeta::own_season_words_for`: `JoJos Bizarre Adventure S06E08` is Steel Ball Run 2nd - 3rd STAGE's episode 7, while the franchise name with no season or another season's tag names no entry), the entry's own name words and the season's number may be left over too (`JUJUTSU KAISEN S03E08` is inside "JUJUTSU KAISEN Season 3: The Culling Game Part 1", `Mairimashita! Iruma-kun - S04E23` inside "Mairimashita! Iruma-kun 4"). Any substring used to count, with no word boundaries in the collapsed forms, which matched about 2,500 cross-franchise pairs over the AnimeTosho corpus (`JoJos Bizarre Adventure S06E08` for Steel Ball Run, `Another` for "King of Fighters: Another Day"); a short name of a long title (`Mugen Gacha`, `Ano Hana`) is left to alternate titles. A row's own list of parts ("4th Season Part 1 & 2") is cut whole from its core (`RE_ALIAS_PART_LIST`). **Entry names** (`SeriesMeta::with_detail`, from the cached detail): the entry's own segments of its compound titles minus its franchise names (`auto_search::entry_name_segments`) that hold two distinctive words or more. A release whose show name (`series_title`) is one of them, with nothing beside it but franchise words (spaced or glued, `JoJos`) and generic words, names the series exactly (`JoJo no Kimyou na Bouken: Steel Ball Run - 09` for 2nd - 3rd STAGE), though a real alias wins the tie; a sequence marker beside the name (`Chapter`, `Final`, `II`, `2nd`) is another entry's. Entry and franchise names join the anchors, as in the extended pass. **A split part's MAL entry titles** (#303): AniList's parts of one MAL entry carry none of that entry's names, and release groups name the MAL entry, so the metadata refresh stores its romaji and English titles (never its synonyms) in `mal_entry_titles` (one row per MAL id, written when `mal_entry_titles::is_split_member` finds another AniList entry of that MAL id in the cached relations, fetched through `jikan::get_anime_titles` at most weekly), and `series_metas` adds them as full aliases of every row with a positive AniList id and that MAL id (never as its season). RSS keeps its exactness check on the season- and episode-adjusted winner of `best_series_match` on purpose: an exact runner-up is the series the release fits worse, and grabbing it there would be a wrong-season misgrab. The winner then goes through `identify` (`rss::identified_series_match`, franchises loaded for the whole library at once by `identify::load_franchises_for_details` over the cached details `identify::cached_series_details` reads once per sweep, the entry names' source too): when another entry of its franchise fits better, that entry takes the item if it is a tracked series the item also matches, and otherwise the item is rejected "Looks like <entry>", never handed to the runner-up; a tie with another tracked row is rejected "Fits <entry> as well, also in the library"; `match_library_title` and the canonical history read it the same way. The fuzzy path scores **distinctive tokens only** (`GENERIC_TITLE_TOKENS` drops articles, romaji particles, and format nouns like `the animation` / `movie` / `season`), and its surplus budget (`passes_content_surplus_check`, issue #103) is keyed on the distinctive count, not the full alias length. Issue #219 is the reason: the colon-split alias `Risa THE ANIMATION` used to clear the 0.6 gate on `the` + `animation` alone. An all-generic alias has no fuzzy signal and only matches verbatim. New generic tokens go in that list with a regression test; don't lower the thresholds instead.

## Match provenance

- **Match provenance** (`services/auto_search/provenance.rs`): every candidate that passes the gate is stamped with `SearchResult.match_provenance` (`MatchKind` verbatim / fuzzy / seadex_curated, `MatchPhase` primary / extended / preferred_group / bd_probe / franchise / batch_probe / seadex_seed, the alias, the distinctive-token ratio). `classify_match` is the gate (`matches_target` is its bool wrapper); both collectors set the phase on their query context. Scoring adds a "Title Match Confidence" line: fuzzy costs 25, a fallback phase (extended / franchise) another 10, sized to beat seeder / trusted tiebreakers and lose to every quality signal, so a fuzzy-only pool still grabs. `episode_tags::record_grab_with_match` persists `match_kind` / `match_phase` / `matched_alias` / `match_ratio` on `episode_grab_history` (auto-search, upgrade sweep, interactive grabs; RSS, autobrr and the picker leave them empty), `get_grab_history` renders `grab_match_summary`, and every grab log line ends with `match=... phase=... alias=... ratio=...`. `MatchProvenance.identity` (`IdentityNote`) carries the `identify` verdict (target / rival / ambiguous / spans / neither, with the entry and tier for a rival or tie); it adds the "Franchise Identity" score line (`IDENTITY_RIVAL_PENALTY` -40, `IDENTITY_TIE_PENALTY` -10) and ends the grab log line (`identity=... tier=... entry=...`), and is not persisted. Add a provenance string only in `provenance.rs`; the round-trip test there pins JSON, log, and DB forms together.
