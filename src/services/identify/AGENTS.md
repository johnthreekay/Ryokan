# services/identify

Which franchise entry a release belongs to, decided by comparison. The alias gates answer "does this title name the series?"; `identify` answers the next question: given that it does, does another entry of the same franchise fit it better? The module doc in `mod.rs` states the rule (four tiers, burden of proof on the rival); this file is the map, the call sites, and the rules that look arbitrary but aren't.

## Files

- `mod.rs`: the decision. `identify(franchise, title)` / `identify_parsed` / `identify_prepared` (a `PreparedTitle` reads a title's names once for many franchises; the corpus test judges one title against several entries). `Verdict` is `Target`, `Rival(Rival { entry, title, tier, reason })`, `Spans`, `Ambiguous { entry, title }` or `Neither`; only `Rival` is a veto.
- `names.rs`: `NameForm::of`, the one normalizer for both sides (entry titles and a release's name zones). Reading a name runs `release_title::parse`, which is why names are memoized wherever many franchises are built.
- `structure.rs`: `Claims` (season, multi-season, part, episodes, special, movie, year) and `Fits` (each claim `Yes` / `No` / `Unknown` per entry).
- `graph.rs`: `FranchiseGraph` (plain serde data: nodes, edges, TVDB rows, curated offsets) and its `build(target, alternates)` into a `Franchise` of `EntryCard`s with numbering frames worked out.
- `load.rs`: the franchise out of the metadata caches (`load_franchise`, `load_franchises_for_series` for a whole library in one query, `cached_series_details` plus `load_franchises_for_details` for the RSS sweep, which reads the cached details once for its entry names too, `load_graph`), `Franchise::from_detail` for callers with no database, and the same walk over a graph in memory (`FranchiseGraph::around`, `GraphIndex`).
- `tests.rs`: each tier on hand-built franchises shaped after real ones.

## Loading

`load_graph` walks `provider_relations_cache` level by level from the target (one query per level) through `load::Walk`: chain edges (`PREQUEL` / `SEQUEL` either way, `PARENT` upward only) up to `MAX_CHAIN` (40) entries, and one hop from the chain through side edges (side stories, spin-offs, alternatives, summaries); a side entry's own edges are never walked. Full details (synonyms, end year) come from `provider_metadata_cache` where the sweep cached them; MAL-sourced `-mal_id` nodes merge into their AniList twins. TVDB placements are `anibridge::tvdb_placements` (episode ranges from the mappings, never summed counts); curated offsets are `anime_relations::offset_for`, and the library row's stored offset stands in for the target.

`load_franchise` caches built franchises in `load::CACHE` (512 entries, cleared when full), keyed by root, offset, alternate titles and the caller's detail, and invalidated by a fingerprint of both cache tables (row counts plus newest `cached_at`): any sweep write rebuilds. When the caches hold nothing past the target (a series added before its first metadata sweep), it falls back to `Franchise::from_detail`, the detail's own one-hop relations. No network, ever: an entry the caches don't hold is not in the franchise, which can only cost a veto.

`FranchiseGraph::around(root)` runs `Walk` over an in-memory graph, so the corpus tests cut each entry's franchise out of one vendored graph the way production reads it out of the caches. Keep the two on the one `Walk`; a second walk would drift.

## Call sites and what each does with a verdict

- **Search gate** (`auto_search::aliases::classify_match_detailed`, through `GatePrecompute::with_franchise`; every collector loads the franchise once per pass, and the entries that are library series too through `identify::tracked_entries` onto `GatePrecompute::with_tracked`). `identify` runs after the alias, season and episode checks pass. Automatic paths (`require_verbatim`) drop every `Rival` and report it on the auto-search toast ("named the series but fit another entry of it better", `GateDiagnostics.looked_like`), and drop an `Ambiguous` whose other entry is tracked ("fit another series in the library just as well", `GateDiagnostics.shared`): Sonarr's ambiguous release, which no library series takes. A tie with an untracked entry is accepted, as Sonarr (which never sees that entry) would. Interactive lists drop only names-more rivals (`Tier::NamesMore`) and keep the rest labeled "looks like <entry>" (`InteractiveSearchRow.looks_like`). Scoring adds a "Franchise Identity" line: -40 for a rival, -10 for a tie (`IDENTITY_RIVAL_PENALTY` / `IDENTITY_TIE_PENALTY`). The verdict rides on `MatchProvenance.identity` and every grab log line (`identity=... tier=... entry=...`).
- **RSS** (`rss::identified_series_match`): the matcher's winner goes through `identify`. A rival takes the item when it is a tracked series the item also matches; otherwise the item is rejected "Looks like <entry>". Never the runner-up by score. A tie with another tracked row (`SeriesMatch::Shared`) is rejected "Fits <entry> as well, also in the library". `match_library_title` (autobrr, the Search page) and the canonical history read it the same way.
- **Misgrab verdict** (`misgrab::verdict::apply_identity`): one way only. A misgrab whose files `identify` reads as the series, a tie, or a pack across its entries becomes unverifiable; a verified grab whose every titled file is another entry's by name or structure becomes unverifiable. `identify` never makes a misgrab: a false one deletes a correct download.

## Rules that are deliberate

- **Unsaid markers count.** An unstated sequel marker or format word (`Season 3`, `OVA`, `Movie`) is one more unsaid word on the rival's side (`Evidence.unsaid_marked`): `Jujutsu Kaisen - 05` does not say `JUJUTSU KAISEN Season 3` in full.
- **Ties need equal structure.** A rival ties only if it shows every claim the target shows (`!(t.confirmed && !r.confirmed)`): an unannounced entry with no data is no tie for a target that fits.
- **An exact name decides a tie, either way (Sonarr's identity).** Each card carries its Latin titles (romaji, English, synonyms, the target's alternate titles) through `names::clean_title`, Sonarr's `CleanSeriesTitle`: folded, punctuation gone, inner articles dropped, years and season words kept. When the title's main name is exactly one tied entry's and not the other's, that entry takes it (`Target`, or a names-fully `Rival`): `Fruits Basket 1st Season - 01 ~ 25` is the 2019 remake's, `[DP] Hunter x Hunter - 003` the 1999 series'. An alternate title is the library's scene mapping: on the 2011 series it makes that name exact for both, and the tie stands.
- **Other tie-breaks favor the target only.** After the exact-name rule, notes beside the name naming the target, or a marker the title states that the target's names carry, turn a tie into `Target`. Too weak to veto with: symmetric notes/marker breaks blocked more wrong entries over the corpus (1,297 against 1,647 accepted for a relative) but cost twice the misses, and have no Sonarr counterpart.
- **Part claims come from the main name only**, never notes or the episode title.
- **Equal rivals prefer the main chain** (`EntryCard.on_chain`), after fewer unsaid words.
- **TVDB frames come from anibridge's episode ranges**, not from summing counts; the absolute frame walks the TV PREQUEL chain for every entry, and curated `anime_relations` offsets win.
- **`PARENT` is chain only child to parent**, in both the loader's walk and `chain_from`: whose parent an entry is makes it a side story.
- **An incompatible rival never vetoes, with one exception**: after the four tiers, a rival the title names in full (no unsaid word, no unstated marker) with more of its words than the target's vetoes as names-more when only numbering claims fail it (`Fits::misnumbered_only`: season, part, episode). `BLEACH Thousand-Year Blood War S01E43` numbers the cours as Disney+ does, which no frame holds. A failed year or format still rules the rival out (`Ranma ½ / Ranma 1/2 (2024)`).
- **Missing data only removes vetoes.** Unknown counts, no synonyms, no TVDB row: a claim an entry can't judge is `Unknown`, and two entries' names are compared only on the fields both have (`Evidence::against`).
- **`franchise_names` stays** in the alias builders (#300). `identify` covers the warm-cache case, but with cold caches the 2012 JoJo series is not a direct relation of Steel Ball Run and there is no node to compare against.

## Measuring

- `tests/identify_franchises.rs`: real titles against 13 vendored franchise graphs (`tests/fixtures/franchises/`), each with its expected verdict. The acceptance table for the rule; add a row with every rule change. `fetch_franchise_fixtures` (ignored) refetches them; it runs past nextest's limit, so use `cargo test --features test-support --test identify_franchises -- --ignored --nocapture`.
- `tests/identify_corpora.rs`: the AnimeTosho corpus (26,412 titles whose AniDB anime anibridge maps; labels are AniList id sets from `anibridge::anilist_ids_for_anidb`) against one vendored graph (`tests/fixtures/animetosho-corpus/franchises.json.gz`). Each title is judged by every entry it names verbatim (the gate's precondition): its label's entries and their main-chain relatives. Five totals are held as floors and ceilings (recognized, missed, blocked, a relative's target, a relative's tie) and an insta snapshot groups every missed, wrong and tied title by outcome. The labels are AniDB's grain and AnimeTosho's matching, so many "misses" are the label's; read the snapshot diff, not just the totals. Tighten a limit when a change improves it; loosen it only with the titles named in the commit. `probe` (ignored, `ID_PROBE='<id>|<title>'`) prints one entry's franchise and verdict. `vendor_corpus_franchises` (ignored, about ten minutes, `cargo test --release`) rebuilds the vendored graph.
