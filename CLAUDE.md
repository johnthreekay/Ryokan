# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Ryokan is a self-hosted anime PVR (personal video recorder) written in Rust. It searches Nyaa for anime torrent releases, scores them by quality, and sends them to a torrent client for download. Four clients are supported behind a common `DownloadClient` trait — qBittorrent, Deluge, Transmission, and rTorrent — with one active at a time per instance. It uses AniList as the primary metadata source with MAL (via Jikan) and Kitsu as fallbacks.

Release scoring combines Sonarr-style **Custom Formats** (TRaSH-Guides-compatible), a multi-layer **source classification pipeline**, and optional **SeaDex** (releases.moe) authoritative picks. Ryokan also exposes a Sonarr/Radarr-compatible API shim (**anibridge**) so Seerr and similar tools can request anime through it.

## Build & Run Commands

```bash
cargo build              # build (debug)
cargo build --release    # build (release)
cargo run                # run locally (creates data/ryokan.db, listens on 0.0.0.0:8978)
cargo test               # run all tests
cargo test <test_name>   # run a single test
cargo clippy             # lint
docker compose up -d --build  # build and run in Docker
```

Requires Rust 1.95+ (enforced via `package.rust-version` in Cargo.toml), a C/C++ toolchain (for the vendored anitomy and bundled SQLite), and `cmake` (for aws-lc-sys, reqwest's TLS crypto provider since the 0.13 bump). No OpenSSL headers needed — TLS is pure-Rust rustls.

## Architecture

### Stack
- **Web framework**: Axum 0.8 with Tokio async runtime. `tower` / `tower-http` supply the middleware layers actually wired up: `trace` (request logging), `fs::ServeDir` (static file serving), `compression-br` + `compression-gzip` (response compression), `set-header` (long-lived `Cache-Control` on `/static/*`). Request bodies are streamed through Axum directly; there's no `tower::limit` in front of anything.
- **Database**: SQLite via sqlx 0.8 (`default-features = false`, features `runtime-tokio` + `sqlite` + `macros`). **No compile-time query checking** — every query in the codebase is a runtime string (zero `sqlx::query!` / `sqlx::query_as!` invocations). The `macros` feature is kept only for the derive macros (`FromRow`, etc.), not for the query macros. SQLite itself is statically bundled via sqlx's built-in driver, so no system `libsqlite3` is needed at runtime.
- **HTTP client**: `reqwest` 0.13 with the `json` + `cookies` + `query` + `form` features. TLS is pure-Rust rustls + aws-lc (rustls-platform-verifier for the trust store). This is why the build needs `cmake` and why `SSL_CERT_FILE` / `SSL_CERT_DIR` aren't honored — different trust-store semantics than native-tls had pre-0.13.
- **Async traits**: `async-trait` 0.1 is used for the `DownloadClient` trait specifically. Native Rust async-fn-in-traits (stable since 1.75) does not yet produce `Send`-bound futures by default, which is required for storing `Arc<dyn DownloadClient>` alongside Tokio's multi-threaded runtime — `async-trait`'s boxed-future macro sidesteps this. For non-object-safe traits the native syntax is fine.
- **Templating**: Askama 0.15 (Jinja2-like, compiled into the binary at `cargo build` time via a proc-macro). Templates live in `templates/`. Handlers call `template.render()` directly and wrap the result in `Html(...)` themselves — there's no `axum`-integration crate (Askama 0.13 merged with the rinja fork and dropped its per-framework wrappers).
- **Frontend**: Single `static/css/style.css` plus inline vanilla JS in the templates. No framework, no bundler, no build step. 8 of 13 templates carry inline `<script>` blocks for interactive bits; `static/default_custom_formats.json` is the only non-CSS static asset (embedded via `include_str!` at compile time too — served from disk so it's also grep-able from the browser for "Install defaults" debugging).
- **Regex**: two engines are compiled in. **`regex-lite`** is the default — used for every internal pattern in Ryokan's own code because it has a linear-time guarantee and we don't need look-around. **`fancy-regex`** is used *only* by the Custom Formats engine (`services/custom_formats.rs`) because TRaSH-Guides anime CFs rely on PCRE-style look-around and nested character classes, which neither `regex-lite` nor the main `regex` crate supports. Don't reach for `fancy-regex` elsewhere just to avoid a rewrite — the backtracking engine doesn't carry the linear-time guarantee.
- **Anime release title tokenization**: `anitomy` 0.2 (Rust wrapper around the bundled anitomy C++ library, compiled via `cc` during build). This is why the build needs a C/C++ toolchain. Used by `source_filename` and `auto_search` for parsing release titles into `(group, title, episode, resolution, ...)` token sets.
- **HTML sanitization**: `ammonia` 4 — powers the allowlist-based HTML cleaning in `services::html` for provider-sourced markup (AniList descriptions, Nyaa description bodies) before it's rendered with `|safe`.
- **Hashing / auth / constant-time compare**: `bcrypt` 0.19 (cost 10) for passwords, `sha2` 0.11 for the artwork content-addressed blob hashes, `subtle` 2 for constant-time API-key comparison in the Sonarr/Radarr shims, `rand` 0.10 + `hex` 0.4 for session token generation.
- **API docs**: `utoipa` 5 generates an OpenAPI 3.x schema from `#[derive(ToSchema)]` + `#[utoipa::path]` annotations; `utoipa-swagger-ui` 9 mounts Swagger UI at `/api-docs`, with the JSON schema at `/api-docs/openapi.json`. The schema covers everything the web UI calls, not just the Sonarr/Radarr shim surface — point it at the Swagger UI for a full client-facing API tour.
- **Logging**: `tracing` 0.1 + `tracing-subscriber` 0.3 with the `env-filter` feature for `RUST_LOG` parsing. Layered in `main.rs` alongside the `services::logger` facade that dual-emits to tracing + the `logs` table.
- **Env loading**: `dotenvy` 0.15 is declared in `Cargo.toml` but **not actually imported or called anywhere in the codebase** — env vars come from the process environment directly (`docker-compose.yml` in prod, the user's shell in dev). This is a dead dep; if you're cleaning Cargo.toml, it's safe to remove along with any `.env` support users might have come to expect. Don't add a `.env`-loading call on the assumption that "oh we already have dotenvy" — the choice not to read `.env` may be deliberate (deployed instances shouldn't be picking up stray files from the working directory).

### Code Layout (`src/`)

Three top-level modules, each in its own directory:

- **`handlers/`** — Axum route handlers (request → response). One module per page/feature area: `library` (subdir: `crud`/`episodes`/`pages`/`reconcile`/`search`), `search`, `downloads`, `settings` (subdir: `mod`/`custom_formats`), `system`, `auth`, `media`, `help`, `progress` (long-job polling endpoint), plus `sonarr_compat`/`radarr_compat` (the anibridge Sonarr/Radarr API shims used by Seerr) and `arr_auth` (the shared `X-Api-Key`/`?apikey=` middleware they both use).
- **`services/`** — Business logic and external API clients. Key services:
  - `anilist` (submodule: `rate_limit`) — primary metadata provider. `mod.rs` owns the GraphQL client, `DETAIL_CACHE`, and batch fetch helpers; `rate_limit.rs` owns the process-wide throttling state machine (see Key Patterns)
  - `jikan`, `kitsu` — metadata fallback providers (MAL via Jikan, then Kitsu)
  - `metadata_sync` — periodic refresh of cached metadata across the fallback chain
  - `nyaa` — Nyaa torrent search via HTML scraping
  - `seadex` — releases.moe PocketBase client for authoritative community release picks (keyed by AniList ID)
  - `scoring` — release quality scoring (seeders, group preference, resolution, source, custom format score)
  - `custom_formats` — Sonarr-style Custom Formats engine: parses TRaSH-Guides-shaped JSON and compiles regex specs into a `CompiledCfCache` that lives on `AppState` and is rebuilt on CF edits
  - `source/` (submodule: `types`) + sibling `source_filename`, `source_description`, `source_temporal`, `source_groups`, `source_dir`, `source_ffprobe` — the multi-layer classification pipeline. `source/mod.rs` is the aggregator / pre-download orchestrator; `source/types.rs` holds the primitive enums (`Source`, `WebKind`, `Resolution`, `Origin`, `DecisionRule`) and the `SourceEvidence` / `ClassificationResult` records (re-exported from `services::source` so callers keep using the familiar path). Each `source_*.rs` is one signal layer (filename tokens, Nyaa description body, release-date heuristics, release-group map, directory path, ffprobe inspection). Together they produce `(Source, Resolution, is_remux)` used by scoring and upgrade decisions. Note the `Source` ordering: `Unknown < Tv < Hdtv < Dvd < Web < BluRay` — BD is the canonical reference and WEB sits a notch below, matching community preferences. Don't reorder without understanding the upgrade-sweep consequences.
  - `quality` — shared helpers (`preferred_group_bonus`, `FinishedSeriesMode`, Nyaa category/probe helpers)
  - `upgrade` — upgrade-decision logic for the background upgrade_search sweep
  - `auto_search` — end-to-end auto-grab pipeline (query → score → grab), powers both manual buttons and RSS/background searches
  - `rss` (submodule: `feed`) — RSS auto-sync for new episodes
  - `anibridge` — TMDB↔AniList mapping + request translation backing the Sonarr/Radarr shim handlers
  - `download_client` — trait-based abstraction over torrent clients. `mod.rs` defines the `DownloadClient` trait, `AddOutcome`/`SelectiveOutcome` enums, `DownloadItem`/`DownloadFile`/`DownloadItemState` DTOs, and the `translate_client_path` / `build_download_client` helpers. Concrete impls live in `qbittorrent.rs`, `deluge.rs`, `transmission.rs`, and `rtorrent.rs`. Torrents are addressed by **v1 infohash** (lowercase hex at the trait boundary; each impl case-munges internally for its wire format). `AppState.download_client` is `Arc<RwLock<Option<Arc<dyn DownloadClient>>>>` — swapped out when the user changes active client in Settings.
  - `jellyfin` — Jellyfin media server integration (server info, library refresh)
  - `post_processing` — moves/renames completed downloads into the media library (hardlink/copy/move)
  - `nfo` — Jellyfin-compatible NFO generation
  - `artwork`, `media` — artwork caching with content-addressed blob storage; media-file probing helpers
  - `auto_expand` — **sibling-series detection** in batch packs (not megapack narrowing — that's the `DownloadClient` trait's `add_torrent_with_file_filter`, used elsewhere). Given a pack's file list and its parent AniList detail, detects sibling anime entries whose episodes are present (sequels, prequels, side stories — the Monogatari/JoJo P3/Owarimonogatari split-saga case), upserts each into `series`, and writes per-sibling `grabbed_torrent_series` route rows so post-processing lands each file in the correct series folder. See the Key Patterns bullet below for the transitive relation walk, offset math, and the grab-time vs import-time call paths.
  - `monitoring` — Sonarr-style monitoring state resolution (all / future / missing / existing / none) over `episode_monitor_state`
  - `progress` — in-memory progress registry for long-running user-triggered jobs (e.g. manual auto-search). `ProgressRegistry` on `AppState`; the `progress_sweep` background task drops terminal jobs 60s past their final event
  - `html` — HTML escape + sanitize helpers built on `ammonia`. Used whenever a user-controlled or upstream-controlled string (Nyaa description body, AniList description, release titles) is rendered with `|safe` rather than Askama's default auto-escape. The escape path is a plain `&`/`<`/`>`/`"`/`'` replacement; the sanitize path runs ammonia with an allowlist of tags appropriate for metadata descriptions. Anything rendered with `|safe` must have been round-tripped through one of these helpers or it's an XSS vector.
  - `logger` — application-logger facade. Emits every call to **both** `tracing` (per-level macros) and a row in the `logs` table via `models::log::insert`. Use `logger::info(&db, category, message, detail).await` / `::warn` / `::error` / `::debug` / `::trace` from any handler or service instead of raw `tracing::*!` when the event should appear in the System → Logs tab
- **`models/`** — Database access layer and schema. `models/mod.rs` contains the `migrate()` function with most `CREATE TABLE` and `ALTER TABLE` statements (no migration files — migrations are idempotent SQL in code). A few tables own their own `CREATE TABLE` next to their model module (`custom_formats` + `custom_format_scores`, `group_source_map` + `schema_migrations`, `media_probe_cache`, `nyaa_description_cache`). Notable tables beyond the obvious `users`/`sessions`/`config`/`series`: `grabbed_torrents` + `grabbed_torrent_series` (grab history + blocklist), `episode_quality_tags` (source/resolution/is_remux verdict + confidence columns), `episode_grab_history`, `episode_monitor_state`, `custom_formats` + `custom_format_scores`, `group_source_map`, `media_probe_cache`, `nyaa_description_cache`, `provider_metadata_cache` + `provider_relations_cache` + `provider_episode_metadata`, `series_metadata_cache`, `series_episode_metadata`, `series_relations_cache`, `episode_cache`, `kitsu_episode_cache`, `rss_runs`, `rss_seen`, `artwork_cache` + `image_blobs` + `image_refs`, `scheduled_task_runs`, `seadex_lookup_cache`, `logs`, `schema_migrations` (one-shot-migration ledger — see **Database migrations** in Key Patterns).

### Key Patterns

- **AppState**: Shared via Axum's `State` extractor. Contains the `SqlitePool`; an `Arc<RwLock<Option<Arc<dyn DownloadClient>>>>` that holds the currently active torrent client (swapped on Settings save via `build_download_client`); an `Arc<RwLock<Option<JellyfinClient>>>` for the media server; the `CompiledCfCache` — a swap-on-write `Arc<RwLock<Arc<Vec<_>>>>` of compiled Custom Formats that handlers clone the inner `Arc` out of under the read lock so the scoring hot path runs lock-free; a `ProgressRegistry` for long-running user-triggered jobs; and a `users_exist: Arc<AtomicBool>` flip-to-true-once cache so the auth middleware can skip a `SELECT COUNT(*) FROM users` on every protected request once setup is complete.
- **Auth**: Cookie-based sessions for the web UI. `require_auth` middleware on protected routes redirects to `/login`; first-run setup at `/setup` creates the admin account. **Timing-equalized login**: `models::user::authenticate` bcrypt-verifies against a warmed dummy hash (`DUMMY_BCRYPT_HASH`) on the missing-user path so failed logins take the same ~50ms as real ones. `main()` forces the `LazyLock` to initialize via `warm_timing_equalizer` at startup, otherwise the very first probe would be a one-shot timing oracle for username enumeration. **bcrypt cost is 10** and `models::user::register` pushes the `bcrypt::hash` call into `tokio::task::spawn_blocking` so the ~50ms CPU cost doesn't stall a runtime worker (the dummy hash on the authenticate path is pre-computed at the same cost so the timing-equalizer comparison is apples-to-apples).
- **Session cookie shape**: `session=<hex-token>; Path=/; HttpOnly; SameSite=Lax; Max-Age=604800` — 7-day TTL, `HttpOnly` (not JS-readable), `SameSite=Lax` deliberately (not `Strict`) because `Strict` blocks the cookie on top-level form POSTs from an external referrer, which breaks Seerr-style "click link to sign in" flows. `Secure` is appended only when `RYOKAN_COOKIE_SECURE` is on. The logout `Set-Cookie` uses `Max-Age=0` and echoes the same `Secure` attribute as the set path — some browsers refuse to clear a `Secure` cookie from a non-`Secure` response, but the reverse is safe. Session tokens are hex-encoded random bytes from `rand`, stored verbatim in the `sessions` table (no additional hashing — the cookie value *is* the DB lookup key, so a DB dump is already a session-hijack vector and re-hashing wouldn't change that threat model).
- **CSRF**: OWASP "Verifying Origin With Standard Headers" — not a token. `handlers::auth::is_same_origin_request` prefers `Origin` (always set by browsers on unsafe methods, including cross-origin form submissions) and falls back to `Referer` when Origin is absent. The acceptable-hosts set is built from the `Host` header plus, when `RYOKAN_TRUSTED_PROXY` is on, `X-Forwarded-Host` (covers the "reverse proxy terminates the externally-visible host" case where the browser sends the public host in Origin but the backend sees the proxy's internal host). The same check runs on two layers: `require_auth` applies it to state-changing methods on authenticated routes, and `csrf_public` wraps the unauthenticated `/login` and `/setup` POSTs so those endpoints aren't cross-origin-forgeable either. Missing both headers → reject.
- **Per-IP login throttle**: `handlers::auth` keeps an in-memory `LOGIN_FAILURES: Mutex<HashMap<String, Vec<Instant>>>` keyed by client IP. Failed login attempts push timestamps; the middleware rejects when the per-window count exceeds the cap. A periodic `sweep_login_failures()` call from the `cleanup` background task prunes expired timestamps so a probe storm can't grow the map unboundedly. Client IP comes from `client_ip_from_request()`, which honors `X-Forwarded-For` / `X-Real-IP` only when `RYOKAN_TRUSTED_PROXY` is set (see env var table); otherwise the TCP peer is ground truth so a direct-exposure deploy can't be bypassed by header spoofing. Usernames are passed through `sanitize_for_log()` (strip control chars, cap at 64 bytes) before embedding in log lines so a probe can't smuggle terminal escapes or multi-KB garbage into `tracing` output.
- **Sonarr/Radarr shim auth**: The `sonarr_compat` and `radarr_compat` routers are merged into the app *outside* the cookie-auth layer and use a shared `arr_auth::check_api_key` middleware. The key is accepted via either the `X-Api-Key` header *or* a percent-encoded `?apikey=` query param, compared in **constant time** (`subtle`) against `config.sonarr_api_key` / `config.radarr_api_key`. Transient config-load failures return **503 with `Retry-After`** rather than 500 so Seerr doesn't mark the indexer broken and back off for a long window. Sonarr routes live at `/api/v3/...`; Radarr routes are deliberately mounted under a `/radarr/` prefix (`/radarr/api/v3/...`) because Seerr only allows two Sonarr slots and two Radarr slots, so both shims must coexist on one host/port and are disambiguated by Seerr's "URL Base" field.
- **Background tasks**: Each runs as a `tokio::spawn` loop in `main.rs` wrapped in `supervise()`, which catches panics/join errors, logs them, and respawns so a stray `.unwrap()` can't silently kill a task for the rest of the process lifetime. **Restart policy is exponential backoff**, not a flat 5s: `MIN_BACKOFF = 5s`, `MAX_BACKOFF = 30 min`, `HEALTHY_RUNTIME = 60s`. A task that runs ≥60s before exiting resets the backoff to 5s (one-off transient failures don't punish the next restart); a task that exits in <60s doubles the backoff up to 30 min (a stuck-on-startup task can't spam logs at 12 restarts/min). Each task writes status to the `scheduled_task_runs` table. Current tasks and intervals:

  | Task | Interval |
  |---|---|
  | `progress_sweep` (drop terminal progress jobs >60s past final event) | 30s |
  | `rss_sync` | 60s |
  | `post_processing` | 60s |
  | `cleanup` (log rotation, stale rows) | 1h |
  | `library_classify` | 6h |
  | `metadata_refresh` | 12h |
  | `upgrade_search` | 24h |
  | `anibridge_refresh` (TMDB↔AniList map rebuild) | 24h |

- **Per-client scoping**: Every `DownloadClient` impl owns a distinct "torrents Ryokan added" filter so `list_scoped` never returns torrents from other tooling. Mechanisms: qBit = `?category=` (user-configurable name, default `anime`); Deluge = Label plugin (the plugin is auto-enabled on first connect); Transmission = native labels on 4.x (earlier versions fall back to a save-path prefix convention); rtorrent = the `custom1` field (the ruTorrent label convention). Each mechanism is set at add-time and read at list-time.
- **Per-client `download_path` + `translate_client_path`**: Ryokan and the client don't always see the same filesystem (Docker volume on a different host path, seedbox over SSHFS/NFS/rclone). Each client gets its own `{qbit,deluge,transmission,rtorrent}_download_path` config field; `download_client::per_client_download_path(&config)` resolves the right one via `active_client`. `translate_client_path(path, client_save_path, local_download_path)` rewrites a client-reported path by replacing the client's `save_path` prefix with Ryokan's local mount. Trailing slashes are normalized; an empty `local_download_path` is treated as "no rewrite"; a path that doesn't start with `client_save_path` is returned unchanged rather than silently rewritten (a silent rewrite would mask misconfiguration as a later "file not found"). This replaces the pre-refactor global remote-path mapping — do not reintroduce a single shared mapping.
- **AniList rate-limit state machine**: `services/anilist/rate_limit.rs` owns process-wide throttling state behind `LazyLock<Mutex<_>>`. Reads `X-RateLimit-Limit` / `X-RateLimit-Remaining` / `X-RateLimit-Reset` from every AL response and adapts between two modes: a minimum inter-request spacing at full headroom, and a wait-until-window-reset mode once `Remaining` drops below `REMAINING_HEADROOM_THRESHOLD` (3). On a 429 or 5xx, writes a cooldown-until timestamp using AL's `Retry-After` (capped at 5 minutes) or a 60s default, plus a mandatory **2-second safety margin** past the window boundary — without the margin, waiting exactly the Retry-After value consistently lands the next request at the boundary and trips a fresh 429. `classify_anilist_failure` returns a three-way taxonomy (`RateLimited` / `Unavailable` / `NotFound`) that downstream code keys MAL-fallback decisions off — **only `Unavailable` falls back to Jikan**. `RateLimited` defers and retries (falling back on a throttle would just move the load, not fix it, and rapidly exhaust Jikan's 3 req/s budget too); `NotFound` stays not-found. Callers match on the returned error-string prefix (`AniList rate-limited` / `AniList unavailable` / `AniList not found`) rather than HTTP codes, so adding new wordings requires updating the tag, not the policy. Touch the safety margin, threshold, or taxonomy carefully — they're all load-bearing for how the metadata chain behaves under throttle.
- **Metadata fallback chain**: AniList → Jikan (MAL) → Kitsu. Fallbacks activate on AniList 403s or when force flags are set in config.
- **Negative-ID sentinel for MAL-fallback series**: When a series is added via the Jikan fallback and has no AniList mapping, Ryokan stores it with `series.anilist_id = -mal_id`. Every AniList call site filters with `id > 0` (see `get_anime_details_batch` at `services/anilist/mod.rs:968`) so these synthetic ids don't leak into AL requests and instead route back through Jikan on refresh. **User-visible consequence**: SeaDex is keyed by positive AL ID, so series added this way are silently invisible to SeaDex-driven scoring (the SeaDex Custom Format and toggle will never fire for them). Anything new that joins against AL IDs should preserve the `> 0` filter or explicitly document the negated-id case.
- **Negative-cache sentinel (`__RYOKAN_EMPTY__`)**: `services/jikan.rs` and `services/kitsu.rs` episode caches write a row with `episode_number = 0` and `title = "__RYOKAN_EMPTY__"` to record "we asked the provider and it returned nothing" distinctly from "we've never asked." Read sites detect the sentinel and return an empty map without re-querying; anyone editing the episode-cache read path must special-case it or the fallback chain degrades into a hot loop against the provider every query.
- **Docker entrypoint + privilege drop**: `docker-entrypoint.sh` runs as root at container start, ensures a `ryokan` user/group exist with UID/GID matching `PUID`/`PGID` (creating or `usermod`/`groupmod`-ing in place if the IDs don't match), chowns `/data` to that user, then execs Ryokan under `gosu`. The data-volume chown is gated on "not already correctly owned" so a warm start is a no-op scan; on a PUID change it quietly re-chowns. **User-mounted `/downloads` and `/media/*` paths are intentionally left alone** — a chown on a 10TB media library would stall startup for hours and potentially clobber ownership the rest of an *arr stack relies on. The user is responsible for picking a PUID/PGID that already owns those paths on the host. This matches the linuxserver.io convention.
- **Database migrations**: Mostly in `models/mod.rs::migrate()`. New columns use `ALTER TABLE ... ADD COLUMN` with `.ok()` to silently ignore if already present; this is the default pattern because it's idempotent and file-free. The exception is **one-shot migrations** that must run exactly once and can't self-guard (data rewrites where re-running would undo the rewrite, or seed-table fixups). Those live next to their model (currently just `models/group_source_map.rs`), write an ID row into the `schema_migrations` table after running, and skip on subsequent boots via `migration_already_applied(db, id)`. Do **not** invent a per-migration config flag — that's what `schema_migrations` is for. No separate migration files on disk.
- **TRaSH Guides fixtures**: `fixtures/trash-guides-anime/` contains 28 vendored TRaSH-Guides anime CF JSON files. They are bundled into the binary via `include_str!` — both as the CF defaults shipped to users (wired through `static/default_custom_formats.json` and the "Install defaults"/"Reset defaults" endpoints in `handlers/settings.rs`) and as the realistic input corpus for the custom-format parser tests.
- **Ryokan-only Custom Format spec**: The `SpecKind::SeaDexBest` variant in `services/custom_formats.rs` is a non-Sonarr extension that matches a release against SeaDex's curated picks at scoring time. It is accepted under both `Ryokan.SeaDexBestSpecification` and the shorter `SeaDexBestSpecification` implementation name, and is emitted in the long form on export. Presence of a Custom Format using this spec **suppresses the separate `seadex_enabled` config toggle** so the CF and the toggle don't double-count — if you're editing either side, preserve that one-or-the-other invariant.
- **Classifier confidence loop**: `episode_quality_tags` carries `classification_confidence`, `needs_review`, and `manual_override` columns alongside the `(source, resolution, is_remux)` verdict. When the source pipeline's layers don't agree strongly enough, the row is written with `needs_review = 1` and shows up on `/library/review`. Setting a manual override via `/api/library/manual-override` writes `manual_override = 1` and clears `needs_review` — and the upgrade sweep skips rows with `manual_override = 1` so a pinned classification is never silently re-graded by a later reclassification pass.
- **Release-group identity map**: `group_source_map` is seeded at startup from a built-in table; seeded rows are re-upserted on every boot but user-added or user-edited rows are preserved. The Settings → Release Groups tab also surfaces a "Suggested Mappings" panel derived from repeat manual overrides (`N` episodes from the same group pinned to the same source), which the user can promote into the identity map. When editing seeding logic, do not overwrite user edits, and when touching the suggestion query remember it reads from `episode_quality_tags` rows with `manual_override = 1`.
- **CF `ReleaseGroupSpecification` is title-only, not source-inferring**: The bundled `S-Tier BD groups` CF in `static/default_custom_formats.json` lists ~19 groups regex-matched against the scraped `[Group]` prefix. Several of those groups (MTBB, smol, Vodes, Okay-Subs, Arid, LYS1TH3A, sam, MiniMTBB, MegaMTBB) are intentionally **absent** from `SEED_DEFAULTS` in `models/group_source_map.rs` because TRaSH lists them in both BD and WEB tiers. That's not a contradiction: the CF applies a score bonus to the group identity, while `group_source_map` applies a BD-vs-WEB prior to source classification. An S-Tier CF match does **not** imply the release is BluRay — the source classification still comes from filename/ffprobe/temporal/dir layers. Keep these two lists editable independently and do not "sync" them.
- **Post-processing import modes**: `services/post_processing.rs::do_file_op` moves each imported file via one of three strategies keyed off `config.post_processing_mode` (stored as a string; validated on save to one of `hardlink` / `copy` / `move`): **hardlink** (default, seed-safe — the original stays in place for the download client to keep seeding), **copy**, or **move**. Hardlink falls back to copy automatically when `fs::hard_link` returns an error (cross-filesystem is the common case; Docker bind mounts from different host fs's trip this). Move uses `fs::rename` on the same filesystem and a copy-to-a-sibling-`.ryokan-tmp`-then-rename for cross-fs moves so a partially-copied file can't be observed at dst by a subsequent pass and mistaken for a finished import; the source-remove after cross-fs move only logs a warning on failure since the file has already safely landed at dst. The whole op runs inside `tokio::task::spawn_blocking` because a BD episode cross-device copy is 1–4 GB and blocks for seconds — doing that on a Tokio worker would starve the RSS sync, HTTP handlers, and other background tasks sharing the runtime. The artwork-copy path separately uses `fs::hard_link` when fanning out multiple destinations (banner ↔ backdrop sharing an inode) with a `fs::write` fallback if hardlinking fails.
- **Artwork two-step orphan prune**: The hourly `cleanup` background task calls `models::artwork_cache::cleanup_orphans(db, min_age_days)`. Step 1 drops rows from `image_refs` whose `parent_kind` is `series` / `series_relation` and whose `parent_id` is no longer in `series` (ref orphans). Step 2 drops rows from `image_blobs` (and the backing on-disk files under `RYOKAN_MEDIA_CACHE_DIR`) that no ref points at and that are older than `min_age_days` — the age gate exists to cover the small upsert-order race in `cache_image` where the blob row is written before the ref row, and we don't want concurrent pruning to delete the blob during that gap.
- **HTTP middleware**: `CompressionLayer::new().br(true).gzip(true)` wraps the full router — Axum negotiates per the client's `Accept-Encoding` automatically. `/static/*` is served through `ServeDir` with a `SetResponseHeaderLayer::if_not_present(CACHE_CONTROL, "public, max-age=3600")` so browsers don't fire a conditional-GET per topbar navigation (a 304 still costs a round trip, which shows up as a visible tab-switch stall). One hour is intentionally short enough that a hard reload picks up edited CSS during local development.
- **Hardcoded outbound `User-Agent: Ryokan/0.1`**: Every outbound HTTP call site (AniList, Jikan, Kitsu, SeaDex, Nyaa, Nyaa description fetch, RSS feed fetch, anibridge mappings fetch, artwork fetch) sends a static `User-Agent: Ryokan/0.1` header. The string is **not** tied to the crate version — bumping `package.version` does not update it. If a provider starts UA-filtering, edit every call site (grep `"Ryokan/0.1"`). Leaving it static is deliberate so we don't burn per-release goodwill with Jikan/Cloudflare just because Cargo.toml changed.
- **DB-backed application logs**: `models::log` owns the `logs` table (columns: `level`, `category`, `message`, `detail`, timestamp). `services::logger::log()` emits every message to **both** `tracing` (per-level macros — `LogLevel::Error` → `tracing::error!`, etc.) and an INSERT into the `logs` table; convenience wrappers (`logger::trace`, `::info`, `::warn`, `::error`) cover the common cases. System → Logs reads from the table, not from a tail of the tracing stream — so `RUST_LOG` filtering affects what reaches the console, while `LogLevel` filtering on the System page is independent. The `cleanup` task also rotates stale `logs` rows to keep the table bounded. **`LogCategory` taxonomy** (15 values, enum in `models/log.rs`): `Search`, `Grab`, `AutoSearch`, `Nyaa`, `AniList`, `Jikan`, `QBit` (UI label is "qBittorrent" — kept as the enum name even after multi-client work because renaming it would be a data migration on the existing `logs` table; the label function is where the display name lives), `Jellyfin`, `Media`, `Library`, `Auth`, `System`, `PostProcess`, `Quality`, `Scoring`. Pick the closest category when writing a new `logger::*` call; the System → Logs filter dropdown uses these verbatim. Adding a new variant requires updating all three of the `as_str` / `from_str` / display-name match arms.
- **Nyaa RSS dedup by GUID**: `services/rss/feed.rs` keys `rss_seen` entries by `guid:<item.guid>` when present, falling back to the item link otherwise. The `rss_sync` task checks this table before scoring/grabbing so a feed that re-emits the same item (Nyaa occasionally does this on re-index) doesn't trigger a duplicate grab. Tombstones in `rss_seen` survive across restarts.
- **Auto-expand (sibling-series detection in batch packs)**: `services::auto_expand::expand_from_files` runs over a pack's file list and the parent series's `AnimeDetail`. Two call sites: (1) **grab-time** from `handlers::library::search::auto_expand_library_from_pack`, which waits up to **180s** for the download client to deliver file-list metadata (inside a `tokio::spawn`, so blocking is fine — the HTTP handler already returned); (2) **import-time** from `services::post_processing` as a safety net when the grab-time path bailed (slow tracker, metadata wait timed out). Import-time always has the file list because it's about to move files. **Transitive relation walk**: AniList's relation graph has missing direct edges across split sagas (Monogatari — Owarimonogatari 21262 doesn't list Owarimonogatari 2nd Season 99423 as a direct neighbor, but reaches it via the shared saga graph). `expand_from_files` fetches each walkable direct neighbor's AL detail, capped at `auto_search::TRANSITIVE_WALK_MAX_FETCHES`, and grafts each neighbor's relations onto the parent via `expand_parent_with_transitive_relations` before running `detect_sibling_entries_in_pack`. Failed neighbor fetches are soft — the code falls back to whatever the failing batch wrote into `DETAIL_CACHE` before aborting, then to the parent's direct relations. **Absolute-numbering offsets**: when a pack uses absolute episode numbers (JoJo P3 E25..E48 for Egypt-hen), each sibling route carries an `episode_offset` so the stored episode numbers are *effective* (post-offset) values — an upgrade-search looking for "Egypt-hen episode 1" finds the route whose files were originally numbered E25 on disk. **Grab-tag backfill**: the path writes `episode_quality_tags` + `episode_grab_history` rows for every sibling at grab time so each sibling's page shows `grabbed` state immediately (without this the sibling renders UNKNOWN with no progress until post-processing completes). Parent "AL-overflow" episodes — pack files whose parsed episode number exceeds the caller's `parent_episode_numbers` (the smol Owarimonogatari BD that splits aired ep 1 into two files, producing a disk-level E13 on an AL-reports-12-episodes series) — get backfilled the same way so the overflow row renders during the download rather than after import. **Parent-route fallback**: every media file not claimed by a sibling routes to the parent series; if any unclaimed files exist alongside sibling routes, a `warn` log surfaces the count so a misdetection is visible in System → Logs. **Not load-bearing under failure**: if the grab-time call aborts (client error, metadata timeout), the grab row is already recorded and import-time's retry will rescue it; never synthesize an empty grab row just to mark auto-expand "complete."
- **Megapack narrowing (different thing, don't confuse with auto-expand)**: `DownloadClient::add_torrent_with_file_filter` pauses the added torrent, waits for metadata, runs a caller-supplied `FnMut(&[String]) -> Option<Vec<usize>>` pick closure over the file names, and sets the non-picked files to skip before resuming. Used from the interactive selective-download flow with a short **10s** metadata ceiling (the user is waiting). Each impl handles its own wait-and-narrow loop and must be idempotent on retry: if a prior grab already set priorities, a re-narrow must not clobber user edits — the trait contract says read each file's `wanted` flag back before changing it. The `pick` callback is `&mut dyn FnMut` (not generic) specifically to keep `DownloadClient` object-safe for `Arc<dyn DownloadClient>` storage on `AppState`.
- **Finished-series mode**: `services::quality::FinishedSeriesMode` (SameAsAiring / PreferBd / BdOnly) keys off `config.finished_series_mode`. `PreferBd` triggers a BD-probe pass using `bd_probe_queries` (appends ` bluray` / ` BD` / ` BDRip` / ` remux` per alias) before falling back to the normal search; `BdOnly` never falls back and skips the series if no BD candidate is found. `SameAsAiring` is the neutral default — the finished/airing distinction doesn't affect scoring. The determination of "finished" comes from the AL status field at classification time, not from release dates.
- **Title language preference**: `config.title_language` is one of `romaji` / `english` / `native`; anything else coerces to `romaji` on save (`handlers/settings/mod.rs:514`). Pages pass it down to templates, which pick the corresponding field from `AnimeDetail` at render time. Scoring and search are **not** affected — this is a display-only preference.
- **Nyaa category selection**: `services::quality::nyaa_categories_for_format` maps AniList `format` + `allow_non_english` into the Nyaa category-id string(s) used in search URLs. `MUSIC` always searches `1_1` (Anime Music Video) + `2_0` (Audio); everything else searches `1_2` (English-translated) by default or `1_0` (Anime All) when the user has opted into non-English releases.
- **Download-client wire quirks (per-impl gotchas)**: Every `services/download_client/*.rs` module carries a file-header quirk list because each client's API has silent failure modes that are hard to rediscover. Live-probed 2026-04-21. Summarized here so a reader touching any of them knows what to look for — but the module header is the source of truth.
  - **qBit** (`qbittorrent.rs`): `content_path` is exposed natively (≥2.6.1) so no common-prefix computation needed. Scoping via `?category=<config.qbit_category>`. **File-priority scale is 0/1/6/7** and Ryokan only writes 0 (skip) or 1 (normal) — higher levels are a qBit-only feature. **qBit 5.x renamed pause/resume → stop/start**; the impl tries the new names first and falls back to the old without a version probe so 4.x and 5.x both work. **qBit 5.x also changed `POST /torrents/add` duplicate-response body from the silent `200 "Ok."` older builds returned to `200 "Fails."`** — indistinguishable from the body used for a genuinely-malformed magnet. `add_torrent` disambiguates by probing `/torrents/info?hashes=<hash>` after a `Fails.` and reports `AddOutcome::AlreadyPresent` when the hash is actually in the session; only a missing hash surfaces as a hard error. Without this, auto-search on 5.x hard-fails every re-grab of a torrent already in the client (RSS re-emissions, upgrade-sweep + manual grab collisions, post-crash regrabs). `list_scoped` uses a **2s coalescing cache** with single-flight election via `AtomicBool` + `Notify` + an RAII `FetchFlightGuard` that clears the in-flight flag on drop — on both happy and panic paths — so a panic inside the fetcher can't wedge the flag forever and turn every subsequent caller into a waiter stuck on `notify_waiters()` that will never fire. Re-auth on 403 via a session cookie.
  - **Deluge** (`deluge.rs`): **Two-step connect** — `auth.login(password)` establishes a session cookie but a freshly-authenticated session isn't connected to any daemon; every `core.*` call fails with `"Unknown method"` (NOT "not connected" — the methods aren't even registered on the web process) until `web.connect(host_id)` runs. This is the single most common first-time integration failure. **Label plugin required for scoping** — bundled but disabled by default; the connection test enables it via `core.enable_plugin` when it sees `Label` in `available_plugins` but not `enabled_plugins`. There's an **upstream Deluge bug** where an enabled-but-not-restarted Label plugin leaves RPC methods unregistered on the web process for one session — we re-call `web.connect` after enabling to force a method re-registration. **File-priority scale is 0/1/4/7** (Skip/Low/Normal/High), **NOT** qBit's 0/1/6/7 — writing `1` for "wanted" would set the file to Low priority (bandwidth-de-prioritized relative to peers), which is wrong; Ryokan writes 0 for skip and 4 for wanted. Duplicate-add detection is **substring-matching on "Torrent already in session" / "Torrent already being added"** (ticket deluge-dev/#3507 — the error code fluctuates across versions). There's **no `has_metadata` field** in `core.get_torrent_status` (live-probed against 2.x + Label plugin 0.3); proxy: `files` array non-empty. Every deserializer uses `#[serde(default)]` because `get_torrent_status` silently drops unknown keys rather than returning an error.
  - **Transmission** (`transmission.rs`): **CSRF session handshake** — every first request returns HTTP 409 + an `X-Transmission-Session-Id` header that must be echoed on every subsequent request. The session ID rotates when the daemon restarts, so any mid-stream 409 means "re-capture and retry once." The `send` helper handles both first-call and mid-stream 409s transparently. Auth is **HTTP Basic**, not RPC-level — wrong creds surface as 401, not an RPC envelope error. Native labels in 4.x; Ryokan filters `labels.contains(self.label)` client-side because the RPC has no server-side label filter. File-selection is **0/1 (unwanted/wanted)** via parallel `files-wanted: [idx]` / `files-unwanted: [idx]` arrays — priority-high/normal/low is a *separate* axis Ryokan deliberately doesn't touch. Duplicate-add surfaces as a **`torrent-duplicate` key inside the `result: "success"` envelope** (not as an error) — no message parsing like Deluge needs. **Completion is `percentDone >= 1.0`**, NOT `isFinished` — `isFinished` means "hit seed ratio/time target" (user-defined stop condition), not "download complete." State derivation also uses the **status codes 0..=6** (0=Stopped, 1=Queued-to-verify, 2=Verifying, 3=Queued-to-download, 4=Downloading, 5=Queued-to-seed, 6=Seeding).
  - **rtorrent** (`rtorrent.rs`): Speaks **XML-RPC** over HTTP to `/RPC2`. **Hashes are UPPERCASE on the wire** — every `d.<method>` / `f.<method>` call keyed by hash takes an uppercase-hex string; conversion happens inside every helper (not at call sites) because the trait contract says callers pass lowercase hex. Every method takes a target, even `d.multicall2` (empty string as target — "all commands have a target, empty is legal" rtorrent convention). **Duplicate-add is silent** — `load.start_verbose` returns `0` on both fresh and duplicate adds; Ryokan pre-checks by listing hashes and returns `AddOutcome::AlreadyPresent` when known. **File priority is binary 0/1** (NOT Deluge's 0/4), BUT after setting priorities **you MUST call `d.update_priorities(<hash>)`** or the new priorities don't take effect — the single most common "my script sets priorities and nothing happens" bug in rtorrent automation. **`d.erase` does NOT touch disk** — per rtorrent's cmd-ref verbatim: "the data stored for the item is not touched in any way." Ryokan reads `content_path` first, calls `d.erase`, then recursively removes the filesystem path — guarded by `content_path != d.directory` so a multi-file torrent dumped at the save root doesn't nuke the entire download dir. **`d.base_path` is empty on closed/stopped torrents** and after an rtorrent restart; fall back to `d.directory + "/" + d.name` when empty. During metadata fetch, `base_path` ends in `.meta` (also a signal metadata hasn't arrived); post-metadata it rewrites to the actual content name. Poll `!base_path.ends_with(".meta")` at 500ms cadence with a **60s budget** (longer than the other clients because cold DHT legitimately takes longer). Wire tags: rtorrent returns `<i8>` for sizes / rates / most counters; the decoder accepts both `<i4>` and `<i8>`. The recursive filesystem remove after `d.erase` runs in `tokio::task::spawn_blocking` for the same reason post-processing does.
- **Parse-ordering sensitivity in `services/media.rs`**: `parse_episode_number` and `parse_quality` are compositions of many regex branches whose **ordering is load-bearing**: `RE_SXEX` must win before bare-number branches or SxxExx titles get mis-parsed as `NN.`; `OVA 01` / `OVA - 01` patterns must fire before the generic bare-number branches; trailing-marker ranges must be parsed *before* the marker so they pass through to the real parser; the WebRip branch must fire before the unified Web branch (issue #48); the RE_SXEX guard also has to win before any dash-delimited branch. Each of these has an explicit regression-guard comment and a paired test that locks in the ordering. **When editing, do not "tidy up" the match order** — it silently breaks classification and the tests catch it, but only because they were deliberately written to. New branches go in the same spirit: add a test pinning the ordering against the case that motivated the branch.
- **Process-wide global state (static `LazyLock`s crossing request boundaries)**: inventory, so "why is this a global?" is answered once and the surprise-static hunt stops.
  - `services::anilist::rate_limit` — throttle state, documented above.
  - `services::anilist::mod::DETAIL_CACHE` — per-AL-id memoization. Partial-recovery paths read from it after a failed batch fetch (`get_anime_details_batch` aborts on first Err but the writes from completed chunks survive in the cache — neighbor-fetch fallbacks in auto-expand rely on this).
  - `services::post_processing::POST_PROC_LOCK` (`tokio::sync::Mutex<()>`) — serializes the post-processing task so two overlapping runs can't double-import files. Held across the full import sweep including the 60s ffprobe timeout, which is why the ffprobe path has its own budget.
  - `services::rss::mod::RSS_SYNC_LOCK` — same pattern for RSS, but uses `try_lock` + an error return so a user-triggered manual "run now" during the 60s tick returns a readable "RSS sync is already running" rather than queuing up.
  - `handlers::auth::LOGIN_FAILURES` — per-IP throttle map (documented).
  - `handlers::auth::TRUST_PROXY_HEADERS` / `::COOKIE_SECURE` — env-var snapshots (documented).
  - `handlers::system::CLIENT_LOG_HITS` — sliding-window rate limit on the client-side log-ingest endpoint so a buggy / runaway browser client (or a curious user with devtools open) can't flood the `logs` table.
  - `handlers::library::reconcile::HYDRATED_CUMULATIVE` — dedup set for first-grab lazy hydration of `cumulative_prior_episodes` (issue #26). Uses `.unwrap_or_else(|poisoned| poisoned.into_inner())` on the lock so a panic inside a prior hydration doesn't permanently wedge the set.
  - `services::rss::feed::RSS_HTTP_CLIENT` — pre-configured reqwest client with the static `Ryokan/0.1` UA and feed-appropriate timeouts, compiled once.
- **`spawn_blocking` discipline**: anything that burns non-trivial CPU or does a long sync filesystem call goes through `tokio::task::spawn_blocking` so it doesn't stall a runtime worker and starve other tasks on the multi-threaded scheduler. Current sites: `bcrypt::hash` (~50ms) + `bcrypt::verify` (~50ms) in `models::user`; the full post-processing file op (`fs::rename` / `fs::copy` / `fs::hard_link` — BD episodes are 1–4 GB); rtorrent's recursive filesystem `fs::remove_*` after `d.erase` (since `d.erase` doesn't touch disk itself); `warm_timing_equalizer` at startup to pre-pay the LazyLock cost of the dummy bcrypt hash; the directory walk in `handlers::library::pages` for disk-file discovery. Rule of thumb: if it can block for >5ms and isn't already async-I/O, wrap it.
- **FK policy — `rss_seen` is deliberately `NO ACTION`, not `CASCADE`**: Every child table that references `series(id)` uses `ON DELETE CASCADE` except `rss_seen`, which is `NO ACTION` on purpose — the audit trail of which RSS items matched which series is worth keeping after a series is removed, and `series_title` is stored alongside `series_id` on each row so the trail stays readable when the FK is broken. Consequence: `series::remove` must NULL the `series_id` on `rss_seen` rows for that series *before* the final `DELETE FROM series` or the delete fails with `FOREIGN KEY constraint failed`. **sqlx enables `PRAGMA foreign_keys = ON` by default** — nothing in this codebase sets it explicitly, but the enforcement is live, so a missed NULL-out will surface as a hard DELETE failure, not a silent dangling row.
- **Mutex-poisoning recovery is *not* the default pattern**: almost every `std::sync::Mutex` site in the codebase uses a plain `.lock().unwrap()` and will crash the task if a prior holder panicked. The only site that deliberately recovers from poisoning is `handlers::library::reconcile::HYDRATED_CUMULATIVE`, which uses `.unwrap_or_else(|poisoned| poisoned.into_inner())` — documented there as "a panic during prior hydration shouldn't permanently wedge the first-grab dedup set for the rest of the process lifetime." If you're adding a new long-lived cross-request mutex whose state is recoverable, prefer the recovery pattern; if it's security-adjacent (like `LOGIN_FAILURES`), keep the `.unwrap()` so a bug crash-loops rather than silently continues with a half-mutated state.
- **Dockerfile caching pattern**: `Cargo.toml` + `Cargo.lock*` (glob — tolerates first build without lockfile) are copied in first, then an empty `fn main() {}` is written to `src/main.rs` and `cargo build --release` runs to prime the dependency compile cache. The real `src/`, `templates/`, and `static/` are copied in after, followed by `touch src/main.rs` + a second `cargo build --release` that only rebuilds Ryokan's own code. **`static/` is copied twice** — once into the builder stage (because `include_str!("../../static/default_custom_formats.json")` in `handlers/settings.rs` pulls the CF defaults into the binary at compile time) and once into the runtime stage (because ServeDir needs disk-side access for `/static/*` routes). Not a bug — each stage needs its own copy.
- **Error-handling convention: `Result<_, String>` everywhere**: Ryokan uses stringly-typed errors across service and model boundaries rather than a typed error enum. This is deliberate — the error almost always flows into either a `logger::*` call or an HTTP response body, both of which want a human-readable message anyway. Downstream code that wants to *match* on error shape does it by tag-prefix (`"AniList rate-limited"` / `"AniList unavailable"` / `"AniList not found"`, `"Download client not configured"`, etc.) rather than by enum discriminant; see the AniList failure taxonomy bullet for the most load-bearing example. If you introduce a typed error, carry the tag-prefix string in its `Display` impl so existing callers keep working.
- **Route-aliasing helper for Sonarr/Radarr compat**: `main.rs::aliased(paths, handler)` registers the same Axum handler at multiple paths, used by the shim routers to collapse case-variant doublings (e.g. `qualityprofile` vs `qualityProfile`). **Seerr ships both spellings in different versions**, and older/forked arr-clients are inconsistent about casing. New shim endpoints should use `aliased(&["/camelCase", "/lowercase"], ...)` rather than duplicating the `.route()` call, so the case-variant policy has one source of truth. Do not try to canonicalize by redirecting — some clients don't follow the redirect and mark the indexer broken.
- **Route organization in `main.rs`**: three logical groups merged into the final `app` router. `public_routes` — unauthenticated endpoints (`/login`, `/setup`, `/forgot-password`) wrapped in `csrf_public` so the POST paths still enforce Origin/Referer. `protected_routes` — everything behind `require_auth` (library, search, downloads, settings, system, API endpoints the web UI calls — `/api/health`, `/api/library/*`, `/api/progress/*`, etc.). `sonarr_routes` + `radarr_routes` — Sonarr/Radarr shims merged **outside** the cookie-auth layer with their own `arr_auth` middleware instead. A compression layer wraps everything and a `/static/*` `ServeDir` with a `Cache-Control: public, max-age=3600` header layer sits beside them. When adding a route, pick the group by its auth shape — cookie-protected UI routes always go in `protected_routes`, API-key-protected shim routes go in their respective Sonarr/Radarr router. There is no `/healthz` — the closest thing is `/api/health`, which reports integration status (download client, Jellyfin) as JSON. **The Docker healthcheck in `docker-compose.yml` deliberately probes `/login` instead**, not `/api/health`, because `/api/health` is one of the authenticated routes in `protected_routes` (handlers/settings::api_health, required by the Settings page's live status badges). `/login` returns 200 as soon as the listener is up, with no auth, no config dependency, and no side effects — exactly what a healthcheck wants.
- **Large files to know about**: a handful of modules are genuinely big and deserve attention before a wide-sweep edit. `services/auto_search.rs` (~6.5k lines — the end-to-end search/score/grab pipeline, transitive relation walk, batch/season detection, episode-numbering normalization; the biggest file in the project by a wide margin). `services/post_processing.rs` (~2.5k — import, NFO, artwork hardlink fan-out, route resolution). `services/custom_formats.rs` (~2.3k — parser + compiler + evaluator for TRaSH-Guides-shaped JSON, plus the SeaDexBest spec). `handlers/sonarr_compat.rs` (~1.4k) and `handlers/radarr_compat.rs` (~900) are both large by design — each endpoint in Sonarr/Radarr's v3 API gets its own handler, and the `Option<T>` field lists on request DTOs are long because real Sonarr emits every field and Seerr's validation paths mean omitting one can make a connection test fail. `services/nyaa.rs` (~1.3k) is mostly HTML scraping + description-body normalization. None of these are "obviously bloated" — the length reflects the real surface area of what they're covering.
- **Tests**: Every test lives inline as `#[cfg(test)] mod tests` in the file it covers. There is no top-level `tests/` directory; integration-style tests are built on in-memory SQLite pools inside those inline modules. **Env-gated live smokes**: each `services/download_client/*.rs` impl ships a `#[ignore]`d `live_smoke` test that exercises the full trait surface (`test` → `add_torrent` → file filter → `list_scoped` → pause/resume → `delete`) against a real client on localhost. They run only when both `--ignored` is passed *and* the corresponding `RYOKAN_{QBIT,DELUGE,TRANSMISSION,RTORRENT}_E2E=1` env var is set. CI never runs them; they're for hand-validation when touching a client impl.

### CI

GitHub Actions in `.github/workflows/`:
- **`rust.yml`** — triggers on push to `main` or `dev` and on PR to `main`, with a `rust-${{ github.ref }}` concurrency group and `cancel-in-progress: true` so each new push to a branch cancels its prior run. Runs (in order, all must pass): `cargo fmt --all -- --check` → `cargo clippy --workspace --all-targets -- -D warnings` (warnings are errors) → `cargo build --workspace --locked --verbose` → `cargo test --workspace --locked --verbose`. `--locked` means a lockfile mismatch fails the job rather than silently updating. Uses `dtolnay/rust-toolchain@stable` with the `rustfmt` + `clippy` components and `Swatinem/rust-cache@v2` for target-dir / registry caching. Before pushing to any open PR, always run the same four commands locally — fmt in particular is easy to forget and the pipeline short-circuits on it before the slower build/test steps execute.
- **`cargo-audit.yml`** (Security Audit) — runs `rustsec/audit-check@v2` on every push to `main`, on PRs to `main` that touch `Cargo.lock` or `Cargo.toml`, and on a weekly cron (`0 9 * * 1` — Mondays 09:00 UTC) so advisories published between commits still get flagged. The `sqlx` `default-features = false` opt-out in `Cargo.toml` is specifically there to prune the phantom `rsa` RUSTSEC-2023-0071 advisory at the source — **do not re-enable sqlx defaults** without confirming the advisory is resolved upstream, or this job goes red.
- **`docker.yml`** — triggers on push to `main` or `dev` and on `v*.*.*` tags. Uses a per-platform matrix (`linux/amd64` on `ubuntu-latest`, `linux/arm64` on `ubuntu-24.04-arm` — native ARM runners, not QEMU emulation, so the arm64 image builds in the same wall-clock time as the amd64 image) that pushes digest-only refs to GHCR (`ghcr.io/johnthreekay/ryokan`). A subsequent merge job assembles the multi-arch manifest and attaches tags. The repo name is lowercased in `IMAGE_NAME` because GHCR requires lowercase image names and the GitHub repo is capitalized as "Ryokan."
- **`claude.yml`** — Claude Code workflow integration. Fires on `issue_comment`, `pull_request_review_comment`, `pull_request_review` (submitted), and `issues` (opened / assigned) events, gated on an `@claude` substring match in the comment/review/issue body (or the issue title). Permissions: `contents: write`, `pull-requests: write`, `issues: write`, `id-token: write`, `actions: read` — the last one is required so Claude can read CI results on the PR it's commenting on.
