{# Modal body for the Add flow. Returned by `GET /system/notifications/add-form` and also rendered server-side on initial section render so the modal opens fast on first click without waiting for a fetch. The HTMX target on the click handlers is `#notif-modal-body innerHTML`, so this is the entire content of that div (no header, no backdrop). Default kind is webhook (matches the dropdown's `selected` option); the discord and script field groups are hidden initially. The kind-flip JS in static/js/system.js toggles visibility live when the user changes the kind dropdown, and for a script ticks Imported alone under Events. Custom script (#288) is offered only while `RYOKAN_CUSTOM_SCRIPTS` allows scripts. #}
{# Webhook field group — visible by default. The kind-flip JS toggles `display: none` on this and the discord group as a pair. #}
Any receiver that accepts a JSON POST, such as ntfy, Apprise, or n8n. Its path or query often carries a token, so a saved URL is never shown again.
Adds X-Ryokan-Signature (the body, GitHub style) and X-Ryokan-Signature-V2 (t= plus the timestamp and body, so a receiver that checks the time can refuse a replayed delivery).
One per line as Header-Name: value.
{# Discord field group — hidden initially; kind-flip JS shows it when the user picks Discord from the dropdown. #}
From Discord: Server Settings → Integrations → Webhooks → Copy Webhook URL. Keep it secret.
{# Custom script — hidden initially. The path is not a secret, so it is a plain field. #}
The full path to a program Ryokan can run, such as a shell script marked executable. In Docker this is the path inside the container. It is run with no arguments and gets the event as environment variables: ryokan_eventtype, and for an import ryokan_dest_path, ryokan_source_path, ryokan_series_title, ryokan_episode_number and ryokan_quality_tag.
A script still running after this long is stopped. Scripts run one at a time, so a long one holds up the next. The exit code and the end of what it wrote go to System → Logs.
