{# Per-tab subform for Settings → General. Issue #129 completion: previously the bulk `
` covered integrations + quality + general in one POST that always submitted all three tabs' fields together, which made HTMX migration awkward (one swap target couldn't represent a per-tab save) and let a Save click on one tab silently re-save the other two. Per-tab subforms isolate the fields to their tab, post to a dedicated endpoint (`/settings/general`), and HTMX-swap just the form region on save so the user gets a green toast + their inputs preserved without a full page render. Wrapper id="settings-general-region" is the swap target; the handler returns this same partial on the HTMX path so successful saves replace the form in place. The non-HTMX path returns the full SettingsTemplate and the browser does a normal redirect-style reload — progressive enhancement for users with JS off. The plain links inside this form (the Recycle Bin and System → Backup hints) boost to the body like every other link: htmx 4 inherits attributes only where `:inherited` says so, so the form's hx-target / hx-swap stay its own. (Under htmx 2 they inherited implicitly and rendered the destination page nested inside #settings-general-region; keep it that way when adding `:inherited` anywhere near a form.) #}
