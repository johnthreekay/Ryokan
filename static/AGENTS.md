# static/AGENTS.md

Rules for the stylesheets and fonts under `static/`. They apply just as much to a template that adds a control or an inline `style=`; `templates/AGENTS.md` points here.

Keep this file under 40,000 characters (`wc -m`): past that, a Claude Code session with a 200K context window is given only its start. `tests/agents_md_audit.rs` enforces it.

## Fonts, colors, controls

- **Fonts are self-hosted; never reintroduce a bare system stack.** `--font-body` is Noto Sans (Latin + Latin-ext + Japanese via `unicode-range`, so a page without kana or kanji never fetches the 2 MB Japanese file), `--font-display` is Murecho, `--font-mono` is Noto Sans Mono (the variable Latin + Latin-ext slices; no Japanese file, since no mono rule renders kana or kanji), all in `static/fonts/` with their OFL texts and credited on System → Credits. The unpinned stack rendered as fontconfig's default on Linux, Segoe UI on Windows, and the desktop's own UI font through `system-ui` wherever fingerprinting protection was off, so no two installs matched. The fallbacks behind the Noto families only cover the swap window and glyphs outside the subsets. The docs site mirrors all three faces under `docs/stylesheets/fonts/` with `font: false` in `mkdocs.yml`, so keep the two copies in step.
- **Theming is token-only.** Every color, radius, and font in `static/css` and in inline `style=` attributes comes from the `:root` tokens in `static/css/base.css`: the palette (`--accent`, `--green`, `--red`, `--red-hover`, ...), the matching channel triples for tints (`rgba(var(--accent-rgb), 0.12)`, never a restated hex), the standard tint backgrounds (`--green-bg`, `--red-bg`, `--dim-bg`, ...), radii (`--radius-sm` tags, `--radius` controls, `--radius-md` tiles, `--radius-lg` cards, `--radius-pill`), and fonts (`--font-body`, `--font-display`, `--font-mono`). The only literals allowed outside `:root` are black / white overlays for scrims, shadows, and hairlines, the first-paint `html { background }` in `base.html`, and the `--signal-*` colors the library card's completeness bar uses (documented there). A `var(--x, #hex)` fallback is a smell: the token either exists or the reference is a typo, and a missing token silently drops the declaration (this is how the Needs Review bulk bar lost its background). Before adding a literal, add a token.
- **Controls come in fixed recipes** (`static/css/forms.css`, `badges.css`, `base.css`); reuse one rather than sizing a new element by hand, and re-run the computed-style audit (every visible control's height, font, padding, radius, fill, border grouped per role) before a UI PR. Buttons: `.btn` + variant is 41px, `.btn-sm` 32px, as `<a>` or `<button>` alike (transparent 1px border, pixel line-height). Fields: 41px at 14px for forms and primary search boxes, 32px at 13px for toolbars (`.folder-select`, the Logs and Calendar filters), page-background fill. Icon buttons: one round family (`.btn-icon`, `.icon-btn`, `.monitor-all-btn`, `.library-sort-dir`, `.btn-icon-danger`), 32px or 28px with `-sm`. Labels: square `tag` (20px, 11px; `.tag`, `.log-badge`, `.season-badge`), round filled `pill` for statuses and kinds, round outlined `chip` for neutral descriptors and toggles; colors are per-page modifiers only. Boolean settings are setting rows (`.setting-rows` holding `label.setting-row` items: title in the label recipe but sentence case and text color, an optional one-line description, the checkbox at the right, each row its own card-fill box, `--bg-elevated` inside a modal); a bare checkbox (`.checkbox-row`, an inline label) stays only in toolbars, table cells, the horizontal import-list group, and label-led control rows like the series page's monitoring panel, where a card per switch would nest a box in a box. Horizontal tabs (`.system-tabs`, `.calendar-range-tabs`) are one 32px segmented control; many-tab pages use the sidebar. Card grids share the card fill and `--radius-lg`, and their dashed add tile is one rule. Settings and System content sits in `.cf-section` cards (title inside as an `h3`, optional `.cf-section-desc` intro); a `<fieldset>` is only for a sub-group inside a modal.
