# AGENTS.md

This file provides guidance to coding agents (Claude Code, Codex, and friends) working with this repository. Every AGENTS.md has a sibling `CLAUDE.md` symlink pointing at it so tools that only look for `CLAUDE.md` load the same content; older references to `CLAUDE.md` paths still resolve. **It's the base layer**; deeper notes for specific subsystems live in nested AGENTS.md files (linked under "Code Layout" below) and load automatically when work touches those subtrees.

**Where a note goes.** This file is loaded into every session in full, so it holds only what has to be known before touching a subtree: the build, the layout, and each cross-cutting rule in a line with a pointer. The detail lives in the nested file beside the code. A nested file loads once an agent reads or edits a file under its folder (the folders above it included), and Claude Code gives a session with a 200K context window only the first 40,000 characters of one, so each nested file stays under that. `tests/agents_md_audit.rs` enforces both sizes and the `CLAUDE.md` symlinks.

## Project Overview

Ryokan is a self-hosted anime PVR (personal video recorder) written in Rust. It searches Nyaa for anime releases, scores them by quality, and dispatches grabs to a download client. Five clients are supported behind a common `DownloadClient` trait — **four BT clients** (qBittorrent, Deluge, Transmission, rTorrent) and **one Usenet client** (SABnzbd) — with a multi-client routing pool keyed by indexer pin and per-protocol default. Acquisition surfaces beyond the built-in Nyaa search: a **torznab/newznab indexer system** for Prowlarr/Jackett (`services/indexers/`), **direct RSS feeds** (e.g. SubsPlease), and an **autobrr webhook** (`/api/webhook/autobrr`) for IRC-announce push. AniList is the primary metadata source with MAL (via Tenrai, a Jikan-v4-compatible API) and Kitsu as fallbacks.

Release scoring combines Sonarr-style **Custom Formats** (TRaSH-Guides-compatible), a multi-layer **source classification pipeline**, and optional **SeaDex** (releases.moe) authoritative picks. Ryokan also exposes a Sonarr/Radarr-compatible API shim (**anibridge**) so Seerr and similar tools can request anime through it.

**Nyaa stays out-of-band.** The torznab indexer system runs *alongside* the direct Nyaa scraper, not in place of it — the search pipeline dispatches to Nyaa-direct + fans out to `Indexer` impls in parallel and merges. Source classification reads Nyaa's description body directly; conforming Nyaa to the generic trait would have hidden that coupling.

## Build & Run

```bash
cargo build [--release]
cargo run                                                                # 0.0.0.0:8978, creates data/ryokan.db
docker compose up -d --build

# Tests — `cargo t` is the canonical alias (defined in .cargo/config.toml)
cargo t                                                                  # = cargo nextest run --features test-support
cargo t <test_name>                                                      # single-test filter (same syntax as cargo test <name>)
cargo nextest run --workspace --features test-support                    # explicit form; use it in a worktree under .claude/worktrees (below)
cargo test --workspace --locked --features test-support                  # without nextest (CI uses nextest; there are no doctests)

# Lint / format / coverage
cargo fmt --all -- --check                                               # CI runs this first; short-circuits on failure
cargo clippy --workspace --all-targets --locked --features test-support -- -D warnings   # CI form — `--all-targets` covers tests too
cargo llvm-cov --workspace --features test-support                       # coverage; cargo-llvm-cov 0.8+ installed locally
```

**Toolchain requirements:**

- **Rust 1.95+** (enforced via `package.rust-version`).
- **C/C++ toolchain** + **`cmake`** — needed because `aws-lc-sys` builds aws-lc via cmake at build time (rustls' crypto provider since reqwest 0.13). Release titles are parsed in Rust (`services::release_title`); the `anitomy` C++ crate was dropped. SQLite is statically bundled by sqlx's `sqlite` feature; no system `libsqlite3` is needed at runtime. No OpenSSL headers either — TLS is pure-Rust rustls + aws-lc.
- **`cargo-nextest`** for `cargo t`. Required: a cargo alias has no fallback, so without nextest `cargo t` errors and you run `cargo test --features test-support` instead. Install: `cargo install cargo-nextest --locked`.
- **`cargo-llvm-cov`** for coverage (optional). Install: `cargo install cargo-llvm-cov --locked`.

**Test profile / nextest config:**

- `[profile.test.package."*"] opt-level = 1` in `Cargo.toml` — dependencies build optimized so wiremock/sqlx/regex hot paths run 2-3× faster; Ryokan's own code stays at `opt-level = 0` for fast incremental rebuilds.
- `.config/nextest.toml`: default profile retries failures once (nextest's own retry, so a flaky wiremock port-bind shows as FLAKY instead of failing the run; `cargo test` never retries), slow-warn at 60s and terminate at 180s. The `ci` profile bumps retries to 2, `fail-fast = false`, and the slow window to 120s × 2.
- **`cargo t` in a worktree nested under the repo** (`.claude/worktrees/...`): cargo reads both `.cargo/config.toml` files and joins array values, so the alias becomes `nextest run --features test-support nextest run --features test-support` and the second `nextest` / `run` act as test-name filters (about 100 of 3,200 tests run, every one with "run" in its name). Call `cargo nextest run --features test-support` there. Making the alias a string doesn't help: cargo refuses to merge a string with the parent checkout's array.

## Environment Variables

| `LISTEN_ADDR` | `0.0.0.0:8978` | Bind address. |
| `RYOKAN_DATA_DIR` | `data` (local) / `/data` (Docker) | #259. Root of Ryokan's own state: every path default below (`ryokan.db`, `.ryokan-key`, `cache/artwork`, `cache/anibridge`) derives from it through `services::paths`, the single resolver. Flip on only behind a reverse proxy that overwrites the headers on ingress. |
| `RYOKAN_COOKIE_SECURE` | unset → false | Read once at startup. Forces `Secure` onto the session cookie. Default off and no inference without proxy trust, because a `Secure` cookie set over plain HTTP is never sent back and locks the user out; `cargo run` on HTTP localhost keeps working. Set it only for an HTTPS proxy that doesn't send the header.
| `RYOKAN_FRAME_ANCESTORS` | unset → framing allowed | Read once at startup by `handlers::security_headers`, which adds `nosniff`, `Referrer-Policy: same-origin`, `Content-Security-Policy: object-src 'none'; base-uri 'self'` and `Cache-Control: no-store` to every response (only where the handler set none; `/static`, `/media/art` and the iCal feed set their own caching, and the iCal 304 must repeat the 200's value). Unset by default because users embed *arr apps in dashboards; the `SameSite=Lax` cookie already logs a cross-site frame out. Entries that aren't an origin (paths, `;`, bare schemes, `*`) are logged and dropped; nothing valid left means `'self'`, never "allow all". |
| `RYOKAN_HOST_CHECK` | unset → off | Read once at startup by `handlers::host_check` (Transmission's `rpc-host-whitelist`, opt-in by the user's choice). When on, browser routes (`public_routes`, `protected_routes`, `/static`) answer 421 unless the raw `Host` (never `X-Forwarded-Host`, which script can set) is an IP literal, `localhost` / `*.localhost`, the machine's hostname (`gethostname()`; in Docker that is the container's own name, a random ID unless compose sets `hostname:`, so a server name like `nas` has to be listed), or in `RYOKAN_ALLOWED_HOSTS`; with `RYOKAN_TRUSTED_PROXY` every `X-Forwarded-Host` entry must pass too. ## Stack at a glance

Axum 0.8 + Tokio · SQLite via sqlx 0.9 (`default-features = false` + `runtime-tokio`,`sqlite`,`macros`; **no compile-time query checking** — all queries are runtime strings; the `macros` feature is kept only for the derive macros) · reqwest 0.13 + rustls + aws-lc + rustls-platform-verifier · Askama 0.16 templates (compiled in at build time) · htmx 4.0.2 vendored under `static/vendor/`, body-wide `hx-boost:inherited="true"` active (explicit inheritance, colon-separated event names; rules in `templates/AGENTS.md`) · `regex-lite` default, `fancy-regex` only inside `services/custom_formats/` (PCRE look-around required by TRaSH CFs) · release titles and file names parsed by Ryokan's own `services::release_title` (no tokenizer dependency) · `ammonia` 4 for HTML sanitize · `bcrypt` 0.19 cost 10, `subtle` 2 for constant-time compare, `rand` 0.10 + `hex` for session tokens · `utoipa` 6 + `utoipa-swagger-ui` 10 (`vendored`: the Swagger UI files come from a crates.io crate Cargo.lock checksums, not a build-time GitHub download) mount Swagger UI at `/api-docs`, JSON at `/api-docs/openapi.json` · `tracing` 0.1 + `tracing-subscriber` 0.3 (env-filter) + a separate DB-backed `logs` table via `services::logger`.

`async-trait` 0.1 is used specifically for `DownloadClient` because native async-fn-in-traits doesn't yet produce `Send`-bound futures by default, which is required for `Arc<dyn DownloadClient>` storage on a multi-threaded Tokio runtime. Non-object-safe traits use native syntax fine.

## Code Layout (`src/`)

- **`handlers/`** — Axum route handlers, one module per page or feature (`library`, `search`, `downloads`, `settings`, `system`, `auth`, `media`, `progress`, `grab`, `oauth`, `webhook/`, `calendar`, `wanted`, `system::manual_import`, `api_keys`, `scoped_auth`, `notifications`, `misgrabs`, plus the `sonarr_compat` / `radarr_compat` shims with `arr_auth`, `arr_shared` and `arr_queue`). What each module does and the handler-side rules: **`src/handlers/AGENTS.md`**. Auth deep dive: **`src/handlers/auth/AGENTS.md`**.
- **`services/`** — Business logic + external API clients. Rules that span services (episode numbering, multi-episode files, specials, the metadata fallback chain, outbound fetch bounds): **`src/services/AGENTS.md`**.
  - Metadata chain: `anilist/` → `jikan` → `kitsu`, plus `mal` (OAuth-authenticated, distinct from `jikan` which is the public-fallback path; `jikan` defaults to Tenrai's Jikan-v4-compatible API since #193).
  - `download_client/` — trait + **5 client impls** (qBit / Deluge / Transmission / rtorrent / **sabnzbd**) + `DownloadClientPool` for multi-client routing. Wire quirks + pool: **`src/services/download_client/AGENTS.md`**.
  - `indexers/` — torznab/newznab indexer abstraction (`Indexer` trait, `Release`/`SearchQuery`/`IndexerCaps`, `torznab/` impl). Runs alongside the Nyaa hot path. Deep dive: **`src/services/indexers/AGENTS.md`**.
  - `release_title/` — the one parser for release titles and file names (batch flag, episodes, seasons, group, resolution, specials, extras, revisions, the show's own name, series-aware readings through `SeriesAnchors`; `file_mode.rs` is the file-name parser `media` re-exports). Pure, no I/O. Deep dive: **`src/services/release_title/AGENTS.md`** (rule order, deliberate rules, corpora, snapshot).
  - `identify/` — which franchise entry a release belongs to, decided by comparing it against the target and every relative (four tiers, burden of proof on the rival). Pure; the franchise is read out of the metadata caches (`load_franchise`, cached in `identify::load::CACHE`). Called by the search gate, the RSS matcher's winner, and the misgrab verdict (soften only). Deep dive: **`src/services/identify/AGENTS.md`** (call sites, deliberate rules, the corpus measurement).
  - `source/` + sibling `source_*.rs` — multi-layer source classification pipeline. `quality.rs`, `scoring.rs`, `custom_formats/`, `upgrade.rs`, `auto_search/`, `auto_expand.rs`. Classifier deep dive: **`src/services/source/AGENTS.md`**. Search gate and match provenance: **`src/services/auto_search/AGENTS.md`**.
  - `external_sync/` — AL/MAL watch-list sync (delta cursor, force-full-resync, removal detection, auth-rejection taxonomy) and its exclusions (Sonarr's import-list exclusions). **`src/services/external_sync/AGENTS.md`**.
  - `shutdown.rs` — stopping in order on SIGTERM / Ctrl+C: the stop flag and the holds work takes so it is not cut. See "Stopping" below.
  - `paths.rs` — #259 data-directory resolver (`data_dir`, `database_url`, `live_db_path`, `db_dir`, `reset_auth_sentinel`, `override_or_data_path`, `opening_creates_db`). Every state path default goes through it; don't add a new `"data/..."` literal.
  - `datetime.rs` — dates and times over the `time` crate, UTC only (`now`, `now_unix`, `today`, `from_unix`, `parse_date` / `format_date`, `parse_sqlite` / `format_sqlite` / `sqlite_age_secs`, `rfc3339`, and the display labels). It replaced chrono (RUSTSEC-2026-0543, unmaintained); `time` was already in the build through reqwest's cookie store. Every text shape is defined once there with a test pinning the exact string, because several are read back: the recycle bin's `YYYY-MM-DD` folders, SQLite `CURRENT_TIMESTAMP` values, the iCal stamp. Functions that format a clock value return `String`; functions that take stored seconds return `Option`, since a restored database or an uploaded backup manifest can hold a number no calendar has.

  - `nyaa/`, `seadex.rs`, `rss/`, `anibridge.rs` (TMDB/TVDB↔AL id tables for the Sonarr/Radarr shims, shows and movies apart, plus since #122 `tmdb_episode_spans`: per-(tmdb show, season) episode ranges composed at load time from the mappings' `{pivot range: target range}` objects, where the source key's numbering is the pivot; `map_tmdb_episode` translates a TMDB episode to `(anilist_id, anilist_episode)`; `seed_tmdb_episode_spans_for_tests` seeds it), `interactive_search_cache.rs`, `indexer_catalog.rs` (provisioning), `task_registry.rs` (in-memory supervised-task lifecycle).

  - `monitoring.rs`, `progress.rs`, `library_link.rs`, `grab_commit.rs`, `grab_sweep.rs`, `metadata_sync.rs`, `html.rs`, `sanitize.rs`, `logger.rs`, `relative_time.rs`.

## AppState

## Background tasks

Each runs as a `tokio::spawn` loop in `main.rs` wrapped in `supervise()`. The supervised list (13 tasks: `progress_sweep`, `rss_sync`, `post_processing`, `grab_sweep`, `external_sync`, `cleanup`, `library_classify`, `metadata_refresh`, `upgrade_search`, `anibridge_refresh`, `airing_refresh`, `backup`, `misgrab_sweep`) and intervals are inline in `main.rs` — grep `supervise(&` for the canonical names. Non-obvious bits the code doesn't explain on its own:

- **Restart policy is exponential backoff**, not flat 5s: `MIN_BACKOFF = 5s`, `MAX_BACKOFF = 30 min`, `HEALTHY_RUNTIME = 60s`. Healthy ≥60s run resets to 5s; <60s exit doubles up to 30 min.
- **Two layers of status tracking** — `scheduled_task_runs` DB table is the historical record (System page per-task history pane); `AppState.tasks: TaskRegistry` is the in-memory live status served at `/api/system/tasks` (lock-free atomics, snapshot-on-read).
- Notes on single tasks live with their subsystem: `external_sync` (**`src/services/external_sync/AGENTS.md`**), the `backup` schedule (**`src/services/backup/AGENTS.md`**), `cleanup`'s temp-file sweep, the `post_processing` stall timer and the failed-download re-search (**`src/services/post_processing/AGENTS.md`**), `misgrab_sweep` (**`src/services/misgrab/AGENTS.md`**), `airing_refresh` (**`src/services/AGENTS.md`**).

## Stopping

`main.rs` handles SIGTERM and SIGINT (`StopSignals`, `shutdown_gently`); the rules are in `services::shutdown`'s module docs. Before, a stop was the process dying wherever it stood, and as a container's PID 1 it ignored SIGTERM (Linux delivers a signal to PID 1 only if it has a handler), so `docker stop` waited out its grace period and killed it.

- **The sequence**: the web server takes no new request and finishes the ones in flight (`HTTP_DRAIN`, 5 s); then the process waits for every `shutdown::Hold` to drop, closes the pool (which checkpoints the WAL, so the database file is whole by itself) and exits 0. A second signal exits at once.
- **No time limit of Ryokan's own on the wait.** Whoever stops the process has one (Docker's stop grace period, 10 s by default; systemd's `TimeoutStopSec`; a second Ctrl+C), and a shorter limit in here would cut work they were willing to wait for. Don't add one.
- **A hold is for work that is wrong when cut, not merely unfinished.** `shutdown::begin(what)` refuses once a stop is asked for (a loop that can simply not start its next unit); `shutdown::hold(what)` is always granted (work under way that stops itself by watching `shutdown::requested()`). Today: one download's import in `post_processing::run_once` (a whole download, not a file: a pack cut between files has had none of its post-loop bookkeeping done, and in move mode the files that landed have lost their sources, so the retry no longer finds them), a manual import (a stop is its Cancel), and a script run (stopped, not waited for; runs still queued are dropped and counted in one log row).
- **Everything else is dropped where it stands**, as before: the sync and sweep loops are not told, and nothing aborts them. A backup is staged under `.partial`. Known gap: a grab made by a background task that is cut between the client taking it and its row being written leaves a download Ryokan does not know about; grab dispatch is spread over eight files with no one place to hold from. A grab made from a page is a request, and requests are finished.
- **Testing against a stop**: code under test takes a `&Shutdown` (`run_once_until`, `script::run_with_grace`) and production passes `shutdown::global()`. Never call `shutdown::global().request()` in a test: under plain `cargo test` it stops every other test in the process.

## Cross-cutting conventions

- **Error type: `Result<_, String>`** end-to-end. Errors flow into `logger::*` or HTTP bodies; downstream code matches on **tag-prefix strings** (`"AniList rate-limited"`, `"AniList unavailable"`, `"AniList not found"`, `"Download client not configured"`, MAL refresh-failure prefixes, etc.) not enum discriminants. New errors keep the prefix. If you introduce a typed error, carry the prefix in its `Display`.
- **`spawn_blocking` discipline**: anything that can block >5ms goes through `tokio::task::spawn_blocking`. Current sites: `bcrypt::hash` / `verify` (~50ms), post-processing file ops (BD episodes are 1–4 GB), rtorrent recursive `fs::remove_*` after `d.erase`, the directory walk in `handlers::library::pages`, the `warm_timing_equalizer` startup pre-pay, the misgrab verdict (`misgrab::assess_and_stamp`), the fetched `.torrent`'s info-hash (`torrent_file::fetch_torrent_info_hash`).
- **Mutex poisoning**: default is `.lock().unwrap()` (crash-loop on programmer error). The one deliberate-recovery site is `HYDRATED_CUMULATIVE` in `handlers::library::reconcile`. Don't add `.into_inner()` recovery to security-adjacent state (`LOGIN_FAILURES`).
- **FK policy**: every child of `series(id)` is `ON DELETE CASCADE` *except* `rss_seen` (NO ACTION — keep audit trail; `series_title` is stored alongside `series_id` so the trail stays readable when the FK is broken). `series::remove` must NULL out `rss_seen.series_id` for the series **before** the final DELETE — `PRAGMA foreign_keys = ON` is the sqlx default and a missed NULL surfaces as a hard DELETE failure.
- **Outbound `User-Agent: Ryokan/0.1`** is hardcoded at every call site (AL, Jikan, Kitsu, SeaDex, Nyaa, RSS, anibridge, artwork). Not tied to crate version. If a provider starts UA-filtering, grep `"Ryokan/0.1"`. **AniList requests also carry `Referer: https://github.com/johnthreekay/Ryokan`** (`anilist::ANILIST_REFERER`, stamped by `anilist::anilist_post`, which every AniList GraphQL POST goes through, `handlers::oauth`'s Viewer check included). AniList's September 2026 "temporarily disabled due to severe stability issues" 403 refuses requests with no Referer and answers any Referer normally; a new AL call site that builds its own `client.post(...)` therefore lands on the MAL fallback with no error in sight. `tests/metadata_sync_e2e.rs` pins the header with a wiremock matcher.
- **Logging**: `services::logger::{trace,debug,info,warn,error}(&db, category, message, detail).await` dual-emits to `tracing` + the `logs` table. Console filtering is `RUST_LOG`; table filtering is `RYOKAN_DB_LOG_LEVEL` (write-side floor). The 19-variant `LogCategory` enum (`models/log.rs`) is what System → Logs uses verbatim — adding a category requires updating `as_str` / `from_str` / display-name match arms. Categories: `Search`, `Grab`, `AutoSearch`, `Nyaa`, `AniList`, `Jikan`, `Kitsu`, `DownloadClient`, `Jellyfin`, `Media`, `Library`, `Auth`, `System`, `PostProcess`, `Quality`, `Scoring`, `ExternalSync`, `Rss`, `Notifications`. Legacy `qbit` strings still parse to `DownloadClient` for old-URL compat.
- **Metadata fallback chain**: AniList → Jikan-shaped MAL provider (Tenrai by default) → Kitsu. Series added via Jikan with no AL mapping store as `series.anilist_id = -mal_id` (negative-ID sentinel); every AL call site filters `id > 0`. **A MAL id is not a series identity (#292)**: look a row up by AniList id first. Provider episode counts are bounded (`anilist::plausible_episode_count`), and the metadata cache has two windows (12-hour refresh, 7-day stale banner). All of it: **`src/services/AGENTS.md`**.
- **The file-name parser is `release_title`'s reading plus file shape rules** (`services/release_title/file_mode.rs`, re-exported through `services::media`), and **batch detection, group and resolution have one home** there too. Don't "tidy" the branch order; new branches go with a pinning test. **`src/services/release_title/AGENTS.md`**.
- **Dates go through `services::datetime`**, never a format description or a `time` parse at a call site. `time`'s `format` returns a `Result` and its descriptions use their own syntax (`[year]-[month]-[day]`, not strftime), so a new shape is a named function there with a test for its exact output. Use `time::UtcDateTime` / `time::Date` / `time::SignedDuration` in signatures (the `Duration` and `PrimitiveDateTime` names are aliases `time` plans to remove). Parsing is exact about padding and whitespace, except that `parse_date` takes a one-digit month or day. `rfc3339` writes a `Z` offset and trims trailing zeros from the fraction. A few hand-written readers and writers predate it and are left alone: `relative_time::parse_sqlite_utc` (which also takes a `T` separator), the torznab RFC 2822 reader, `mal::parse_rfc3339_to_unix`, and `indexers::format_publish_date`.
- **Destination names come from `services::naming`**, never a `format!` with `S{:02}E{:02}` (the last hardcoded shapes were replaced in #124). Folder / file names inside the media root: `naming::series_folder` (add time only), `naming::season_folder`, `naming::episode_file`. Display-only labels (log lines, the recycle page's `S01E07` badge) may still format the tag directly.
- **One file can hold several episodes (#246), specials are a name flag and not a season, and `.strm` stubs are library files, never download files (#287).** Every reader of the tag table or the disk scan treats a file as present for each episode in `EpisodeFile::episodes()` (`holds()`, never `episode_number` alone); the scanner decides a special by place (`Specials/`, season 0), the series' format decides what the name flag means. **`src/services/AGENTS.md`**.
- **Outbound fetches of third-party URLs are bounded.** A new provider call uses `http_body::CappedBody` (`.text_capped()` / `.json_capped()`), never a bare `.text()`. Which URLs are fetched at all, and the caps: **`src/services/AGENTS.md`**.
- **`/series/{id}` and `/api/series/{id}/...` take the library (internal) id**; a link to a series that may not be in the library carries its AniList id plus `?by=anilist`. **Streaming bodies must survive a poll after the end** (`.fuse()` them). **Stored credentials for other systems are write-only** (`handlers::secret_field`): none is ever rendered into a page. **`src/handlers/AGENTS.md`**.
- **Library deletes go through `services::recycle::recycle`**, never a bare `fs::remove_file` / `remove_dir_all` on a media-root path. The helper decides recycle-vs-permanent from `config.recycle_bin_path`, so a call site that unlinks directly silently bypasses the user's recycle bin. Download-side cleanup (SAB `complete/` hardlink sources in `handlers::library::episodes`, rtorrent `d.erase` paths) is *not* a library delete and stays a direct unlink.
- **Static asset URLs carry `?v={{ crate::asset_version() }}`** (every `<script src>` / `<link href>` under `/static/` in the templates). `ServeDir` answers with `Cache-Control: max-age=3600`, so an unstamped URL kept a browser on the previous release's JS and CSS for up to an hour after an upgrade, and a rebuilt scratch server showed no change until a hard refresh. The stamp is 12 random hex characters drawn once per process (`lib.rs::asset_version`), so any restart refreshes; it used to be the crate version plus the start time, which the unauthenticated login page disclosed. Add it to every new asset tag; font and license files referenced from CSS are not stamped.
- **HTMX-aware redirects**: `handlers::responses::htmx_aware_redirect` is mandatory for any handler that does `Redirect::to`. Bare `Redirect::to` under body-wide hx-boost gets nested-rendered into the source page. `tests/htmx_redirect_audit.rs` is a CI-enforced lint. See `templates/AGENTS.md` for the full rationale.
- **Auto-search title gate and match provenance** (`services/auto_search/aliases.rs::matches_target`, `provenance.rs`). Automatic paths take only verbatim (or SeaDex-curated) matches, then `services::identify` decides between the entries of a franchise. New generic tokens go in `GENERIC_TITLE_TOKENS` with a regression test; don't lower the thresholds instead. **`src/services/auto_search/AGENTS.md`**.
- **Misgrab guardrails**: `grabbed_torrents.verification` is written once, and **the blocklist is `state = 'failed'`**, which every automatic path honors. Don't loosen the verdict to catch more. **`src/services/misgrab/AGENTS.md`**.
- **Hardcoded Nyaa hot path**: when adding indexer support, never refactor Nyaa into a generic Indexer trait — Nyaa stays out-of-band as the protected hot path.
- **Built-in Nyaa card** (Settings → Indexers): Nyaa is rendered from the config row, not an `indexers` row; its columns are written only by `settings_indexers_nyaa_save` and every tab form preserves them. **`src/handlers/AGENTS.md`**.
- **Sonarr/Radarr shim auth and ids, webhook auth**: `arr_auth::check_api_key` and the autobrr receiver compare keys in constant time; `tvdbId` is always a TVDB id and the Radarr `tmdbId` a TMDB movie id; shim provider order is fixed AL-first then MAL, never the user-facing source toggles. **`src/handlers/AGENTS.md`**.
- **Fonts are self-hosted, theming is token-only, controls come in fixed recipes.** Before adding a system font stack, a literal color or a hand-sized control: **`static/AGENTS.md`**.
- **No em dashes in user-facing prose** (templates, README, error messages, toast text). Use `;` or `.` Internal Rust comments / AGENTS.md / commit messages are exempt. **US English** spellings (color, honor, favorite — not colour, honour, favourite).
- **Custom Formats** are Sonarr-style (TRaSH-Guides-compatible). A Custom Format using `SeaDexBest` suppresses the separate `seadex_enabled` toggle: one or the other, never both. **`src/services/AGENTS.md`**.
- **Post-processing import modes** (`hardlink` by default, `copy`, `move`), place-then-swap upgrades, extra files, remove-after-import, the batch preflight, and **auto-expand** (routing a pack's files to sibling series; never load-bearing under failure): **`src/services/post_processing/AGENTS.md`**.
- **Title language preference**: `config.title_language` is `romaji` / `english` / `native`; anything else coerces to `romaji` on save. Display-only — scoring and search are unaffected.
- **Nyaa category selection**: `services::quality::nyaa_categories_for_format` maps AniList `format` + `allow_non_english` into Nyaa category-ids. `MUSIC` always searches `1_1` (AMV) + `2_0` (Audio); everything else `1_2` (English-translated) by default or `1_0` (Anime All) when non-English is opted-in.
- **RSS dedup** keys `rss_seen` by info hash, then guid, then link; a `grabbed` row is the tombstone and is never replaced by a later decision that is not a grab. **`src/services/AGENTS.md`**.
- **The upgrade decision is `source::judge_upgrade`** (`services/source/upgrade_policy.rs`); `is_valid_upgrade` is only its quality half. **`src/services/source/AGENTS.md`**.
- **Episode numbering is one rule, `services::numbering::Numbering`** (#303), resolved from the row by `Series::numbering()`: every reader of a release title or a download file name takes a `Numbering`, never the bare offset. Offsets live on `series.cumulative_prior_episodes` and are written only through `anime_relations::cumulative_prior_episodes` and `series::update_cumulative_prior_episodes`. **`src/services/AGENTS.md`**.

## Process-wide global state

Static `LazyLock`s crossing request boundaries — inventory:

- `services::anilist::rate_limit::*` — throttle state. Deep dive: `src/services/anilist/AGENTS.md`.
- `services::anilist::DETAIL_CACHE` — per-AL-id memoization; partial-recovery paths read from it after a failed batch fetch.
- `services::jikan::DETAIL_CACHE` — per-MAL-id memoization (parallel to AL's).
- `services::jikan::JIKAN_COOLDOWN_UNTIL` — Jikan's equivalent of AL's rate-limit machine. When Jikan 429s, sets "unavailable until Instant" so subsequent calls return a clean cooldown error instead of hammering and piling up more 429s. **60s default, 300s max.** Honors the response's `Retry-After` when present.
- `services::source_description::LAST_FETCH` — Process-global throttle for live Nyaa description fetches. **`MIN_FETCH_INTERVAL = 1s`** (Nyaa doesn't publish a rate limit but tarpits scrape-looking patterns fast). Holds the mutex *across the sleep*, deliberately serializing all fetches so two concurrent classifier calls can't burst.
- `services::identify::load::CACHE` (`Mutex<HashMap>`) — built franchises by root, offset, alternate titles and the caller's detail, each with the fingerprint (row counts + newest `cached_at`) of `provider_relations_cache` and `provider_metadata_cache` it was built from; a mismatch rebuilds. Cleared when it passes 512 entries.
- `services::anime_relations::INDEX` (`LazyLock<Index>`) — the compiled-in anime-relations rule index, parsed from `include_str!` on first use. Never refreshed at runtime; a new snapshot ships with the binary.
- `services::anibridge::CACHE` (`RwLock<Option<CacheState>>`) + `DOWNLOAD_LOCK` (`Mutex<()>`) — In-process TMDB↔AniList mapping cache + single-flight download serializer (no TOCTOU race). A body that is valid JSON but not the mappings (`[]`, `{}`, an error object: no mapping comes out of it) is a parse error (`parse_bytes`), so a bad download never replaces the cache in memory or on disk and `reload` reports failure. `ensure_loaded`'s `false` (no cache, no disk copy, download failed) means ids are unknown, not unmapped: the shims' id lookups and adds go through `anibridge::require_loaded` and answer 503 instead of a stub or the title-search fallback, which added AniList's first hit for the request's title. The `anibridge_refresh` 24h task warms `CACHE`; the disk cache underneath uses conditional GET via stored meta, with multiple `spawn_blocking` sites for read/meta/write paths and an unconditional-read fallback on the 304 path.
- `services::auto_search::seadex_lookup::SEADEX_CACHE` + `SEADEX_INFLIGHT` — per-AL-id memoization for releases.moe lookups + thundering-herd guard so a burst of concurrent scoring calls share a single in-flight fetch. `SEADEX_HASH_CACHE` beside them holds the hashes-only results RSS fetches (`seadex_hashes_for_rss`, same TTLs, in memory only): RSS scores feed items after its gate loop, reads `SEADEX_CACHE` first, and puts every other series with an item to score into one `seadex::lookup_batch` request with no Nyaa view-page fetches. A hashes-only payload never goes into `SEADEX_CACHE`, where it would stand in for one with seed candidates; a "no entry" answer does (it is complete), and is persisted as the prewarm does it.
- `services::anilist::SEARCH_CACHE` — per-query AL search memoization (parallel to the listed `DETAIL_CACHE`).
- `services::post_processing::POST_PROC_LOCK` — serializes the post-processing task. Held across the full import sweep including the 60s ffprobe timeout.
- `services::post_processing::client_cleanup::SEED_SWEEP_LOCK` + `LAST_SWEEP` — the finished-seed sweep's `try_lock` serializer and its 5-minute throttle stamp (#228); a tick that finds a sweep running skips.
- `services::rss::RSS_SYNC_LOCK` — `try_lock` + readable error so manual run during a tick doesn't queue.
- `services::external_sync::EXTERNAL_SYNC_LOCK` — same shape; Sync-now click during the supervised loop returns "already running."
- `services::manual_import::import::IMPORT_LOCK` — `try_lock` shape (#122); a second confirm while an import runs returns "already running" instead of racing folder names and the post-processing lock.
- `services::recycle::RECYCLE_UNWRITABLE` (`AtomicBool`) — set when a recycle attempt found `recycle_bin_path` configured but unwritable and refused the delete; cleared by the next successful recycle. Polled by the `/library/recycle` and `/system` banners. Not persisted; a restart clears it until the next failed delete.
- `services::upgrade::UPGRADE_LOCK` — same `try_lock` shape; manual upgrade-search button returns "already running" rather than queuing during the supervised tick.
- `services::metadata_sync::METADATA_SWEEP_LOCK` — same `try_lock` shape, held by `run_metadata_sweep` for the whole sweep (retry rounds included), so the 12h `metadata_refresh` tick and the manual rebuild never run over the same rows at once (#235's log showed two rebuild sweeps two seconds apart). Both public sweep entry points return `Err("... is already running")` when busy; the System handlers probe the lock before `mark_started` so the audit row and the toast stay honest, and the supervised loop records a busy tick as `warn`.
- `services::backup::BACKUP_LOCK` — `try_lock` shape (#126); the scheduled task, `GET /api/backup/download`, `POST /api/backup/run`, and the pre-restore backup inside `stage_restore` all serialize on it. The staged-restore lock is not in memory at all: it is the existence of `<data dir>/.ryokan-restore-pending/`.
- `services::misgrab::MISGRAB_LOCK` — same `try_lock` shape; the supervised tick and any manual trigger share it so two sweeps never race the client deletes.
- `handlers::wanted::WANTED_SEARCH_LOCK` — `try_lock` shape; `POST /api/wanted/search` returns 409 while a wanted search runs. The guard moves into the detached task, so the lock is held until every series' search has finished.
- `services::airing_refresh::AIRING_REFRESH_LOCK` — same `try_lock` shape (#115/#116); the 12h supervised tick and the `POST /api/tasks/airing-refresh` manual trigger share this lock so a click during the scheduled tick returns "already running" rather than double-stamping the AL budget.
- `services::nyaa::NYAA_CONCURRENCY` (`Semaphore`) — bounds Nyaa fan-out concurrency so a wide auto-search target list can't burst-attack the scraper.
- `services::nyaa::LAST_SEARCH_FAILURE` — the last failed `nyaa::search` and when (a transport error, or any non-2xx answer: the status is checked, since an error page parsed as a results page is an empty result). The collectors keep only hits (`Err(_) => continue`) across dozens of queries, so whoever is left with nothing asks `nyaa::search_failure_since(started)`: the auto-search handler reports "Nyaa could not be searched" for the target (plus one `Nyaa` warn a minute) instead of "no matching release found", and the three interactive searches answer the table partial saying so (JSON callers get 502) and skip the 5-minute cache, which would otherwise serve the outage's empty list. Never cleared, compared by time; process-wide, so a concurrent request's failure counts, which only ever turns an empty list into "could not be searched" while Nyaa is in fact failing. The Search page shows the error in place of "No results".
- `services::notifications::script::QUEUE` (`Mutex<Option<mpsc::Sender<Job>>>`) + `SWITCH` (`LazyLock<bool>`) — #288. `QUEUE` is the sender of the one serial script queue (1,024 waiting runs, one worker, started on the first run and restarted if its worker is gone); it is process-wide because the provider objects are rebuilt on every settings save and a queue inside one would drop its waiting runs. `SWITCH` is the `RYOKAN_CUSTOM_SCRIPTS` snapshot.
- `services::shutdown::GLOBAL` (`LazyLock<Shutdown>`) — the process's stop flag and its live holds ("Stopping" above).
- `services::crypto::ENCRYPTION_KEY` — the AEAD key. Crashing at LazyLock force is intentional.
- `models::series::UPSERT_LOCK` (`tokio::sync::Mutex<()>`) — serializes `series::upsert`, whose lookup, `unique_series_folder` pick and insert are only correct with no other upsert in between: two interleaved adds of one AniList id failed the second insert on `UNIQUE(anilist_id)` (a raw SQL 500 on a double click), and concurrent adds of same-titled series all took one folder. Held for the whole call; nothing inside it takes another lock.
- `handlers::settings::CONFIG_WRITE_LOCK` (`tokio::sync::Mutex<()>`) — serializes handler-level read-modify-write of `Config`. Multi-process deployment (which Ryokan doesn't support) would need DB-level locking instead.
- `handlers::auth::LOGIN_FAILURES` — per-IP throttle map. See `src/handlers/auth/AGENTS.md`.
- `handlers::auth::TRUST_PROXY_HEADERS` / `COOKIE_SECURE` — env snapshots. `cookie_secure_for` combines them with the request's `X-Forwarded-Proto` per response, so the two `Set-Cookie` paths (set on login / setup, clear on logout) read it from the same request rather than a global.
- `handlers::system::CLIENT_LOG_HITS` — sliding-window rate limit on the client-side log-ingest endpoint.
- `services::logger::first_in_window`'s map — one log row per key per window for lines an unauthenticated client can repeat; bounded at 4096 keys.
- `handlers::library::search::SHIM_SEARCHES_QUEUED` + `SHIM_SEARCH_PERMITS` — the shims' background search queue (dedup set, two permits).
- `handlers::library::reconcile::HYDRATED_CUMULATIVE` — first-grab `cumulative_prior_episodes` lazy-hydration dedup. Uses `.unwrap_or_else(|p| p.into_inner())` recovery.
- `handlers::oauth::OAUTH_HTTP_CLIENT`, `services::rss::feed::RSS_HTTP_CLIENT`, `services::jikan::HTTP_CLIENT`, `services::mal::HTTP_CLIENT`, `services::artwork::HTTP_CLIENT`, `services::source_description::HTTP_CLIENT`, `services::nyaa::HTTP_CLIENT`, `services::seadex::HTTP_CLIENT`, `services::torrent_file::HTTP_CLIENT` — per-service pre-configured `LazyLock<reqwest::Client>` instances. Each owns its own UA / timeout / TLS config; sharing one client across services would cross-pollinate timeouts. Standard reqwest hygiene — connection-pool reuse means do NOT build a `Client` per request.

## Database & migrations

- sqlx 0.9 with **no compile-time query checking** (zero `sqlx::query!` invocations); `macros` feature kept for derive macros only. SQLite statically bundled; no system `libsqlite3` needed at runtime.
- **`SqlSafeStr` (sqlx 0.9)**: `query`/`query_as`/`query_scalar` accept `&'static str` implicitly; any dynamically-built query string (our `format!`'d placeholder-splicing and `SELECT {COLS}` const-interpolation sites in `models/`) must be wrapped in `sqlx::AssertSqlSafe(..)`. These are all internal SQL with bound parameters — no user input is interpolated — so the audit the wrapper asserts is satisfied. Prefer moving an owned single-use `String` into `AssertSqlSafe(s)`; use `AssertSqlSafe(s.as_str())` only when the string is reused (e.g. an `insert_sql` driven in a loop).
- Migrations in `models/migrations/`. New columns use `ALTER TABLE ... ADD COLUMN ... .ok()` to ignore-if-present (idempotent, file-free). The exception is **one-shot migrations** that must run exactly once and can't self-guard (data rewrites, seed-table fixups). Those live next to their model (`models/group_source_map.rs` is the current example), write an ID row into `schema_migrations` after running, and skip on subsequent boots via `migration_already_applied(db, id)`. Don't invent a per-migration config flag — that's what `schema_migrations` is for. No separate migration files on disk.

## Routes

Six route groups in `main.rs`, each with a different auth layer — pick the right group when adding a new route:

- **`public_routes`** — unauthenticated; wrapped in `csrf_public` so POSTs still enforce Origin/Referer (`/login`, `/setup`, `/forgot-password`).
- **`protected_routes`** — behind `require_auth` cookie middleware. Default for all UI routes and web-UI-facing API endpoints.
- **`sonarr_routes`** and **`radarr_routes`** — merged *outside* the cookie-auth layer; use `arr_auth::check_api_key` instead. Two separate routers because Seerr only allows two Sonarr + two Radarr indexer slots and both shims must coexist on one host/port.
- **`webhook_routes`** — outside cookie-auth; each receiver carries its own API-key middleware.
- **`calendar_routes`** — outside cookie-auth; carries `require_calendar_scope` (scoped-API-key middleware from #114) so iCal subscribers (Apple Calendar / Google Calendar / Thunderbird, which can't carry cookies) can reach `/api/calendar.ics`. Same scoped-key shape as the future `search`-scoped surfaces planned on top of #114.

**Boot order matters for #126**: `services::backup::apply_pending_restore` runs in `main.rs` before `SqlitePoolOptions::connect`, so a staged restore is swapped in with no connection open; the post-migration `logger::info` line is the only DB write it makes.

**First-run setup is two steps.** `/setup` creates the account and sends it to `/setup/library` (a protected route, `handlers::settings::setup_library`): media root (refused unless Ryokan can see and write to it, the usual Docker mistake being a host path), import mode, and an optional media server connection (Jellyfin, Emby or Plex). Saving turns post-processing on, which defaults off; Skip is a plain link and changes nothing. The page stays reachable afterwards and shares Settings' write-only Jellyfin key rules.

There is no `/healthz`. **The Docker healthcheck deliberately probes `/login`** (200 with no auth, no config dependency, no side effects) rather than the auth-gated `/api/health`.

## Docker

`docker-entrypoint.sh` runs as root, ensures a `ryokan` user/group matching `PUID`/`PGID`, resolves the data dir the way the binary does (blank = unset = `/data`, relative made absolute against `/app`) and **exports it back** so the chowned folder and the binary's folder can't diverge, refuses one that resolves (symlinks included) to `/`, `/app` or `/app/static`, warns for each per-path variable pointing outside it, mkdirs + chowns it, then execs under `gosu`. Three non-obvious deliberate choices (don't "fix" any of these):

- **User-mounted `/downloads` and `/media/*` paths are intentionally NOT chowned**, and neither is `/data` once `RYOKAN_DATA_DIR` points elsewhere (#259: in the hardlink-friendly *arr layout `/data` is the shared media mount). Chowning a 10TB media library would stall startup for hours and could clobber ownership the rest of an *arr stack relies on. The user picks a `PUID`/`PGID` that already owns those paths on the host (linuxserver.io convention).
- **`static/` is copied into BOTH stages of the Dockerfile.** Builder needs it for `include_str!("../../static/default_custom_formats.json")`; runtime needs it for `ServeDir`. Looks like duplication; isn't.
- **ffprobe is built from source in its own `ffprobe` stage, not `apt install ffmpeg`.** Debian's package adds ~470 MB of codec libraries; the stage builds a ~4 MB static ffprobe with only what `services::source_ffprobe` reads (demuxers for the importable extensions, codec parsers, video decoders for `pix_fmt`). Checked field-for-field against a full ffprobe on real and synthetic BD / DVD / web files. Updating is two `ARG`s (`FFMPEG_VERSION`, `FFMPEG_SHA256` from the signature-checked release tarball); Dependabot can't track it. A new extension in post-processing's video list needs its demuxer added to the stage's `--enable-demuxer`.

## Tests (one-paragraph summary; deep dive in `tests/AGENTS.md`)

Most tests live inline as `#[cfg(test)] mod tests`; integration tests in `tests/` are binary crates that import `ryokan` as a library and require `--features test-support` (each `[[test]]` target declares this so plain `cargo test` silently skips them). Topic-split submodule pattern when a test module exceeds ~1500 LoC. Env-gated `live_smoke` tests in download-client impls. Browser tests for HTMX UI assertions are Playwright Test specs in `tests/browser/`, run with `scripts/browser-e2e.sh` on Chromium and Firefox against a fixture host binary that builds only under `--features browser-e2e`; CI runs them in `rust.yml`'s Browser tests job.

## CI

Six workflows in `.github/workflows/`: `rust.yml` (fmt → clippy → build → test, plus an MSRV build job and a Browser tests job that builds the fixture host and runs the Playwright suite in `tests/browser` on Chromium and Firefox; runs on every branch push except `gh-pages`, plus `pull_request` only for fork PRs against `main` / `dev`, so a same-repo PR shows the checks from its head commit's push run rather than running twice), `cargo-audit.yml` (weekly + on Cargo lock changes), `docker.yml` (native amd64/arm64 → GHCR on every branch push, tagged by branch, plus semver tags and `latest` on releases; fork PRs cannot write to GHCR, so they upload `docker load`-able tarballs as artifacts instead), `docs.yml` (Zensical site build → `gh-pages` on push to `main`), `license-notices.yml` (auto-regen `licenses/THIRD_PARTY_LICENSES.html` on dev pushes when `Cargo.lock` / `about.toml` / `about.hbs` change; commits with `[skip ci]` to avoid recursive triggers), `mutants-weekly.yml` (Sunday 03:17 UTC cron — curated cargo-mutants subset against last week's baseline; an 8-shard `round-robin` matrix of ~90 mutants each plus a merge job, because a hosted job caps at 6h and the subset needs ~22h of runner time at the measured ~30 mutants/hour; the baseline is saved only from a run where every shard finished; opens an issue only on caught → missed regressions). Build & Run section above lists the four lint commands to run locally before pushing. Two non-obvious traps:

- **Supply chain: pin by SHA, and keep third-party code out of jobs that can write.** Every `uses:` is a full commit SHA with a `# vX.Y.Z` comment (Dependabot bumps both; a tag can be moved under you, which is how tj-actions/changed-files leaked secrets). `dtolnay/rust-toolchain` has no releases, so it pins a `master` commit and takes `toolchain:` as an input; bump that SHA by hand. An action can read its job's `GITHUB_TOKEN` through its own input defaults, so `persist-credentials: false` is not enough: third-party actions run in read-only jobs and only first-party steps hold write tokens (`docs.yml` builds read-only and deploys from an artifact; `license-notices.yml` generates read-only and commits in a second job; `mutants-weekly.yml` grants `issues: write` to the report job only). The exceptions are actions that need the token themselves (`docker/*` for GHCR, `rustsec/audit-check`, `peaceiris/actions-gh-pages`), which is why their pins matter most. There is deliberately no coding-agent workflow (the `@claude` one was removed, and the same goes for any agent's mention-triggered action): it needs write access and a credential in a job that acts on issue and PR text anyone can write. To have an agent review or change a PR, check the PR out locally and run whichever agent you use there. `taiki-e/install-action`'s manifest at the pinned commit fixes each tool's version and checksum. `docs-requirements.txt` is hash-pinned (`pip install --require-hashes`), compiled from `docs-requirements.in` by the `uv pip compile` command in that file. The Dockerfile's base images are `tag@sha256:` multi-arch index digests. Dependabot waits 7 days before proposing a release (`cooldown`), security updates excepted. On GitHub, the "Protect main" ruleset blocks force-pushes and deletion and requires a PR (admins bypass, workflow tokens can't), and fork PRs from every outside contributor need approval before workflows run.
- **Don't re-enable sqlx default features.** `default-features = false` in `Cargo.toml` is what prunes the phantom `rsa` RUSTSEC-2023-0071 advisory at source. Re-enabling defaults pulls `rsa` back in and turns `cargo-audit.yml` red. Note (sqlx 0.9): `sqlx-mysql` + `sqlx-postgres` now appear as `Cargo.lock` entries even with the opt-out, but `cargo tree -i sqlx-mysql` confirms they're never compiled/linked and `rsa` stays absent — don't "clean them up" by toggling features.
- **Don't add a Rust browser-driver crate back.** The browser tests moved from `fantoccini` to Playwright Test (#319) because an optional dependency's whole tree sits in `Cargo.lock` and in `cargo audit` whether or not it is ever compiled: fantoccini's `webdriver` crate held `cookie` 0.16 there with no patched release (RUSTSEC-2026-0594), and before that its default features pulled `openssl` in. The tests' one npm dependency, `@playwright/test`, is pinned exactly in `tests/browser/package.json`; `package-lock.json` holds three packages with integrity hashes and installs with `npm ci --ignore-scripts`; Dependabot's `npm` entry tracks it and the Browser tests job runs the suite on the bump. The `browser-e2e` feature now carries no dependency: it only builds the fixture host (`tests/browser/host.rs`) and the fixture pages in `test_support`.
- **GHCR image name must be lowercase** (`ghcr.io/johnthreekay/ryokan`). The repo is capitalized "Ryokan" but `IMAGE_NAME` lowercases it — GHCR rejects uppercase image names.
