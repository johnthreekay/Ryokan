# AGENTS.md

This file provides guidance to coding agents (Claude Code, Codex, and friends) working with this repository. Every AGENTS.md has a sibling `CLAUDE.md` symlink pointing at it so tools that only look for `CLAUDE.md` load the same content; older references to `CLAUDE.md` paths still resolve. **It's the base layer**; deeper notes for specific subsystems live in nested AGENTS.md files (linked under "Code Layout" below) and load automatically when work touches those subtrees.

## Project Overview

Ryokan is a self-hosted anime PVR (personal video recorder) written in Rust. It searches Nyaa for anime releases, scores them by quality, and dispatches grabs to a download client. Five clients are supported behind a common `DownloadClient` trait — **four BT clients** (qBittorrent, Deluge, Transmission, rTorrent) and **one Usenet client** (SABnzbd) — with a multi-client routing pool keyed by indexer pin and per-protocol default. Acquisition surfaces beyond the built-in Nyaa search: a **torznab/newznab indexer system** for Prowlarr/Jackett (`services/indexers/`), **direct RSS feeds** (e.g. SubsPlease), and an **autobrr webhook** (`/api/webhook/autobrr`) for IRC-announce push. AniList is the primary metadata source with MAL (via Tenrai, a Jikan-v4-compatible API) and Kitsu as fallbacks.

Release scoring combines Sonarr-style **Custom Formats** (TRaSH-Guides-compatible), a multi-layer **source classification pipeline**, and optional **SeaDex** (releases.moe) authoritative picks. Ryokan also exposes a Sonarr/Radarr-compatible API shim (**anibridge**) so Seerr and similar tools can request anime through it.

**Nyaa stays out-of-band.** The torznab indexer system runs *alongside* the direct Nyaa scraper, not in place of it — the search pipeline dispatches to Nyaa-direct + fans out to `Indexer` impls in parallel and merges. Source classification reads Nyaa's description body directly; conforming Nyaa to the generic trait would have hidden that coupling.

## Build & Run

```bash
cargo build [--release]
cargo run                                                                # 0.0.0.0:8978, creates data/ryokan.db
docker compose up -d --build

# Tests — `cargo t` is the canonical alias (defined in .cargo/config.toml)
cargo t                                                                  # = cargo nextest run --features test-support
cargo t <test_name>                                                      # single-test filter (same syntax as cargo test <name>)
cargo nextest run --workspace --features test-support                    # explicit form
cargo test --workspace --locked --features test-support                  # CI-shape fallback (doc tests, --locked)

# Lint / format / coverage
cargo fmt --all -- --check                                               # CI runs this first; short-circuits on failure
cargo clippy --workspace --all-targets --features test-support -- -D warnings   # CI form — `--all-targets` covers tests too
cargo llvm-cov --workspace --features test-support                       # coverage; cargo-llvm-cov 0.8+ installed locally
```

**Toolchain requirements:**

- **Rust 1.95+** (enforced via `package.rust-version`).
- **C/C++ toolchain** + **`cmake`** — needed because two crates compile native code at build time: `anitomy-sys` ships C++ source it builds via `cc` (anime title tokenization), and `aws-lc-sys` builds aws-lc via cmake (rustls' crypto provider since reqwest 0.13). SQLite is statically bundled by sqlx's `sqlite` feature; no system `libsqlite3` is needed at runtime. No OpenSSL headers either — TLS is pure-Rust rustls + aws-lc.
- **`mold` + `clang`** — `.cargo/config.toml` pins `linker = "clang"` with `-fuse-ld=mold` for x86_64 + aarch64 Linux. Cuts incremental link time 3-5× vs ld/lld; without them a build fails with `"linker 'clang' not found"` or `"ld.mold not found"`. Install: `sudo pacman -S mold clang` (Arch) / `sudo apt install mold clang` (Debian/Ubuntu). CI installs both via apt before the build steps.
- **`cargo-nextest`** for `cargo t`. Falls through to `cargo test` if not installed, but nextest is the default. Install: `cargo install cargo-nextest --locked`.
- **`cargo-llvm-cov`** for coverage (optional). Install: `cargo install cargo-llvm-cov --locked`.

**Test profile / nextest config:**

- `[profile.test.package."*"] opt-level = 1` in `Cargo.toml` — dependencies build optimized so wiremock/sqlx/regex hot paths run 2-3× faster; Ryokan's own code stays at `opt-level = 0` for fast incremental rebuilds.
- `.config/nextest.toml`: default profile retries failures once (matches `cargo test` behavior so a flaky wiremock port-bind doesn't fail the whole run), slow-warn at 60s and terminate at 180s. The `ci` profile bumps retries to 2, `fail-fast = false`, and emits `junit.xml`.

## Stack at a glance

Axum 0.8 + Tokio · SQLite via sqlx 0.9 (`default-features = false` + `runtime-tokio`,`sqlite`,`macros`; **no compile-time query checking** — all queries are runtime strings; the `macros` feature is kept only for the derive macros) · reqwest 0.13 + rustls + aws-lc + rustls-platform-verifier · Askama 0.16 templates (compiled in at build time) · htmx 4.0.0 vendored under `static/vendor/`, body-wide `hx-boost:inherited="true"` active (explicit inheritance, colon-separated event names; rules in `templates/AGENTS.md`) · `regex-lite` default, `fancy-regex` only inside `services/custom_formats/` (PCRE look-around required by TRaSH CFs) · `anitomy` 0.2 for release-title tokenization (the `anitomy-sys` crate builds bundled C++ source via `cc` at build time — not vendored into Ryokan) · `ammonia` 4 for HTML sanitize · `bcrypt` 0.19 cost 10, `subtle` 2 for constant-time compare, `rand` 0.10 + `hex` for session tokens · `utoipa` 5 + `utoipa-swagger-ui` 9 mount Swagger UI at `/api-docs`, JSON at `/api-docs/openapi.json` · `tracing` 0.1 + `tracing-subscriber` 0.3 (env-filter) + a separate DB-backed `logs` table via `services::logger`.

`async-trait` 0.1 is used specifically for `DownloadClient` because native async-fn-in-traits doesn't yet produce `Send`-bound futures by default, which is required for `Arc<dyn DownloadClient>` storage on a multi-threaded Tokio runtime. Non-object-safe traits use native syntax fine.

  - `crypto.rs` — AEAD wrapper for OAuth tokens. `oauth_state.rs` (PKCE verifier store), `user_score.rs`.
  - `nyaa/`, `seadex.rs`, `rss/`, `anibridge.rs` (TMDB/TVDB↔AL id tables for the Sonarr/Radarr shims, plus since #122 `tmdb_episode_spans`: per-(tmdb show, season) episode ranges composed at load time from the mappings' `{pivot range: target range}` objects, where the source key's numbering is the pivot; `map_tmdb_episode` translates a TMDB episode to `(anilist_id, anilist_episode)`; `seed_tmdb_episode_spans_for_tests` seeds it), `interactive_search_cache.rs`, `indexer_catalog.rs` (provisioning), `task_registry.rs` (in-memory supervised-task lifecycle).
  - `anime_relations.rs` — #206 curated absolute-numbering offsets. Parses the vendored `static/anime-relations.txt` (erengy/anime-relations, Taiga's episode-redirect table, CC0) into a destination-keyed index (AniList id, then MAL id; a Jikan-sourced row's `-mal_id` sentinel doubles as its MAL key). A rule contributes only `src_range.start - 1`; rules whose destination range does not start at 1 (mid-run remaps) or whose offset is not positive (episode-0 specials) are dropped, and when several rules share a destination the largest offset wins (root-relative numbering, what the PREQUEL walk sums to). `cumulative_prior_episodes(db, anilist_id, mal_id)` is the **single decision point** for `series.cumulative_prior_episodes`: rule first, else `local_metadata::compute_cumulative_prior_episodes`; both writers (`metadata_sync::refresh_series_metadata` and `handlers::library::reconcile::maybe_hydrate_cumulative_offset`, which fires on a rule even when AniList lists no TV prequel) go through it. `metadata_sync::hydrate_rule_source` caches the rule's source entry so `source_titles` (the search path's franchise aliases for a ruled series, falling back to the walk when the source is not cached) never fans out to AniList per search. No network path: the snapshot is refreshed by copying upstream's file over the vendored one; the round-trip test pins the rule count.
  - `post_processing/` — moves/renames completed downloads (hardlink/copy/move). `nfo.rs`, `artwork.rs`, `media.rs`, `jellyfin.rs`.
  - `recycle/` — recycle bin (#123). `recycle()` is the single funnel for every library delete (episode delete, series remove / bulk remove via `handlers::library::cleanup::cleanup_series_files`, and the post-processing upgrade-replace path). Layout is `<recycle_bin_path>/<YYYY-MM-DD>/<8-hex entry_id>/manifest.json + files`; `restore` / `delete_entry` / `empty` back `/library/recycle`; `purge_old` runs inside the hourly `cleanup` task. Empty `config.recycle_bin_path` = disabled (permanent unlink, the pre-#123 behavior, one `Library` info line per delete); configured-but-unwritable **refuses the delete** (Sonarr's fail-closed behavior, the file stays) and raises `RECYCLE_UNWRITABLE` for the recycle-page and System-page banners. Cross-fs copies are size-verified before the source is removed (file and whole-tree). Episode entries sweep companions by `<stem>.` / `<stem>-` prefix (nfo, `.en.srt`, `-thumb.jpg`) so `S01E07` never captures `S01E070`. Same-fs is a rename; cross-fs is copy-through-`.ryokan-tmp`-then-unlink. Restore is "put it back where it was" only and never recreates a deleted `series` row. The episode-delete `HX-Trigger` payload carries `recycle_entry_id` so the toast offers a one-click Undo (restore); the Library toolbar's bin control renders only when `recycle::cached_entry_count` (60s cache, dropped on every mutation) is non-zero.
  - `misgrab/` — misgrab guardrails (the download-side half; the search-side half is match provenance, below). `verdict.rs` is the pure file-list judgment: media files only; a file names the series when its normalized path contains an own or sibling alias (or a multi-word colon / dash segment of one) verbatim, or carries 60% of its distinctive tokens; **misgrab** only when at least one file has title signal (2+ Latin-lettered content tokens after `GENERIC_TITLE_TOKENS`, release noise, and episode / resolution / CRC tokens are stripped; a file named only in another script, like a Chinese raw group's file for a Japanese series, is unverifiable because no alias can match it) and no file matches or even shares one distinctive word with any alias, so abbreviated fansub names (`JoJo Stardust - 01`) and generic names inside a titled folder are never condemned; everything else is **unverifiable**. `mod.rs` stamps the verdict once (`grabbed_torrents::stamp_verification`, first writer wins) wherever a file list first appears: the grab-time wait in `auto_expand::expand_from_files` (which returns before any route / coverage write on a misgrab, **including one the sweep stamped while the waiter was still polling**: a stamped verdict is final whoever wrote it, and only an unjudged grab is assessed), the post-processing import path (`import_torrent` judges an unjudged grab from the client's file list before importing), and the `misgrab_sweep` task. Remediation lives only in the sweep: `remove_and_blocklist` (client `delete` unless `respects_seed_rules`, usenet never touched; `mark_failed_by_hash_with_reason("misgrab")`, which makes the failed row the blocklist entry for hash and title; `episode_tags::mark_grab_failed_for_release`), then `emit_misgrabbed` and a detached re-search through the auto-search handler, gated by `research_allowed` (`RESEARCH_LOOP_BREAKER` = 3 misgrabs per series per 24h). `config.misgrab_auto_remove` off turns remediation into flag-and-hold. Restore / Dismiss are `handlers::library::misgrabs`. `assess` is pure CPU (a regex normalization per alias form plus an anitomy parse per path segment) and runs under `spawn_blocking` from `assess_and_stamp`; alias forms are prepared once per verdict (`prepare_aliases`) and folder parses are memoized per segment, so cost is files + aliases, not files × aliases.
  - `backup/` — #126 backup / restore. `create_backup` = `try_lock(BACKUP_LOCK)` → free-space precheck (`nix::statvfs`, 2×DB + artwork) → `VACUUM INTO` a work dir under the data dir (spliced as an escaped literal: SQLite reads a *bound* parameter here as `""` and silently runs a plain `VACUUM`; also a no-op against sqlx's shared in-memory DB, so tests use a file-backed pool) → optional sanitize (`services::sanitize::run_sanitize`: config secrets, `indexers.api_key`, `download_clients.password`, `api_keys.key`, sessions, password hashes, OAuth tokens, and the query string of `grabbed_torrents.source_url` / `direct_rss_feeds.url`, since torznab download links carry `apikey=`; + log trim to `SANITIZED_LOG_ROWS`, key and hostname omitted) → `tar.gz` of `manifest.json` + `ryokan.db` + `.ryokan-key` + `artwork/` written to `<out>.partial` then renamed. `BackupPaths::from_env()` derives the data dir from `live_db_path()` (DATABASE_URL), the key path from `crypto::key_file_path()`, artwork from `artwork::media_cache_dir()`; the configured `backup_directory` defaults to `<data dir>/backups`. Names are `ryokan-backup-<ts>.tar.gz` / `auto-pre-restore-<ts>.tar.gz`; `parse_backup_name` doubles as the allow-list for the file download / delete endpoints; `prune_backups` never touches pre-restore files. Restore is **stage-then-restart**: `stage_restore` extracts with an entry allow-list + `unpack_in`, checks the manifest's `max_migration_id` and version against the running binary, `PRAGMA integrity_check`s and `DELETE FROM sessions` on the staged DB, takes a pre-restore backup, then renames the staging dir to `<data dir>/.ryokan-restore-pending/` (its existence is the lock). `apply_pending_restore` runs in `main.rs` **before the pool opens**, in the order key → database → artwork: the key first because it is the highest-value, smallest file and nothing else has moved if it fails; the live DB (with `-wal` / `-shm`) goes aside as `ryokan.db.pre-restore-<ts>` and a failed DB placement puts the DB *and the key* back; artwork (and removing the staging dir) can only produce `RestoreApplied.warnings`, never a rollback, so `Err` always means "nothing changed". `sweep_work_dirs` runs right after at boot and clears whatever a crash stranded in `.backup-tmp` / `.restore-staging-tmp`. `create_backup`'s precheck covers both the work dir (3×DB when sanitizing, else 2×) and the archive's own filesystem. The `backup` supervised task ticks hourly and runs when the newest scheduled backup in the folder is older than the cadence (the folder is the state). Endpoints are cookie-auth only (no #114 scope is broad enough for a key-bearing archive); the upload is a raw gzip body streamed to disk with the 2 MB body limit lifted on that route. Handlers: `handlers/system/backup.rs`; UI: System → Backup tab, schedule in Settings → General.
  - `naming/` — #124 naming templates. `render` / `validate` / `preview` over `{series.title}`-style lowercase-dot tokens with a `:00` zero-pad spec; the three defaults (`DEFAULT_*_FORMAT`) are byte-identical to the pre-#124 layout. Each token value is sanitized on its own (`media::sanitize_folder_name`), then an empty-token cleanup (empty bracket pairs, doubled ` - `, dangling edge separators, `..` / `__` runs) runs on the template's **literal runs only**, never inside a value. NAME_MAX truncation shrinks `{series.title}` first, then `{episode.title}`, then hard-cuts; the episode number and `{ext}` always survive. **`series_folder` is applied once, in `series::upsert`** (which reads `config::get_naming_prefs` itself so its fifteen call sites need no plumbing) and persisted on `series.folder_name`; `season_folder` / `episode_file` run on every import (`post_processing::load_series_import_ctx` + the per-file `episode_name_context`, whose quality / group read the grab-time tag row and fall back to a filename-only classification; manual import's `preview::season_folder_name` / `import.rs`; the Sonarr / Radarr shims for the would-be path of a series not yet in the library). `validate` requires `{ext}` last and `{episode.number}` present, rejects `/` `\`, renders the sample **and** a sparse context (no year / title / quality / group) to catch templates that go empty, and parse-backs the sample through `media::parse_episode_number` so a template can never produce a name the scanner can't read. For the same reason the upgrade path's `existing_for_ep` is parser-based rather than an `SxxExx` substring check. Settings → General renders `handlers::settings::naming_panel`; the live preview posts all three templates to `POST /api/settings/naming-preview` (`handlers/settings/naming.rs`), server-rendered so there is no JS resolver to drift. ## AppState

Defined in `src/lib.rs`. Fields:

- `db: SqlitePool`.
- `download_clients: DownloadClientsCache = Arc<RwLock<Arc<DownloadClientPool>>>` — **multi-client routing pool** (id-keyed `HashMap<i64, Arc<dyn DownloadClient>>` plus `default_torrent_id` and `default_usenet_id`). The whole `Arc<DownloadClientPool>` swaps atomically on `services::download_client::rebuild_clients_cache` (Settings → Connections → Downloads add/edit/delete). Lookup at grab time is a `HashMap::get` against the cheap-cloned inner Arc — read lock releases before dispatch. Resolved through `AppState::client_for_indexer` / `client_for_nyaa` / `default_download_client` / `client_by_id` / `resolve_grab_client`.
- `jellyfin: Arc<RwLock<Option<JellyfinClient>>>`.
- `custom_formats: CompiledCfCache = Arc<RwLock<Arc<Vec<_>>>>` — swap-on-write so the scoring hot path runs lock-free. Handlers clone the inner `Arc` under read lock; rebuilt by `custom_formats::rebuild_cf_cache` on CF create/update/delete.
- `indexers: IndexerCache = Arc<RwLock<Arc<Vec<Arc<dyn Indexer>>>>>` — same swap-on-write shape as `custom_formats`. Avoids rebuilding `reqwest::Client` instances on every per-target search.
- `progress: ProgressRegistry` — long-running user-triggered jobs (currently manual auto-search). The frontend mints an opaque `progress_id`, the trigger handler binds it via `register(...).await`, and `/api/progress/{id}` drains buffered events.

While false, the middleware still hits the DB on the setup-pending path so a fresh `/setup` submission is picked up on the very next request.
- `interactive_search_cache: InteractiveSearchCache` — 5-minute TTL for interactive-search results so rapid modal reloads during UI iteration reuse the previous Nyaa hit. Scoped to interactive only; auto-search / RSS / manual grabs continue to hit Nyaa directly.
- `oauth_state: OAuthStateStore` — in-memory store for pending MAL OAuth attempts (PKCE verifier between `/start` and `/submit`). 10-minute TTL. AL has no entry — implicit grant, no per-attempt server state.
- `start_time: chrono::DateTime<Utc>` — wall-clock timestamp captured at boot. Used by Sonarr/Radarr `system_status` so Seerr's UI pill reports actual liveness; the prior hardcoded `2024-01-01T00:00:00Z` claimed the indexer had been up over a year regardless of when Ryokan restarted.
- `tasks: TaskRegistry = Arc<RwLock<HashMap<&'static str, Arc<TaskState>>>>` — supervised-task lifecycle metadata. Each `supervise()` loop registers itself once at startup, mutates atomics on its `Arc<TaskState>` on every iteration (no further locking until a snapshot read). Distinct from the DB-backed `scheduled_task_runs` table — `tasks` is the in-memory live status view (running / backoff, restart count, last exit kind, current backoff) served at `/api/system/tasks` for the System page.

## Download-client routing (multi-client pool)

`AppState::client_for_indexer_with_id` resolves:

1. **Indexer's `download_client_id` pin** if set and present in the pool.
2. **Per-protocol default** — torznab indexer with no pin → `default_torrent_id`; newznab → `default_usenet_id`. Unknown indexer kind / not in cache snapshot → torrent default.
3. None — caller surfaces "no download client configured."

`client_for_nyaa` reads `config.nyaa_download_client_id` then **always falls back to torrent default** (Nyaa items are magnets / .torrent URLs; usenet fallback would just trip the protocol guard at add-time).

`default_download_client` returns the **torrent** default — every internal default-only call site is torrent-flavored (manual grabs, library re-grab, RSS / upgrade "is anything configured" gates). Usenet routing always goes through an indexer pin or its protocol default.

**`resolve_grab_client(download_client_id, hash)`** — used by post-processing's per-grab routing. Three-layer fallback:
1. The stamped client id, if it still exists in the pool.
2. **Hash-shape heuristic** — `hash.starts_with("SABnzbd_nzo_")` routes to ANY usenet client in the pool. Old grabs predating the `download_client_id` stamp migration have NULL stamps; without this branch, a SAB nzo_id sent to qBit's `delete` endpoint silently 200s (qBit ignores unknown hashes), and the user's symptom is "delete-from-disk leaves the SAB job alive forever."
3. The torrent default (legacy fall-through; correct for BT v1 infohashes).

`grabbed_torrents.download_client_id` is stamped at grab time so post-processing routes back through the same client even if defaults change.

## Background tasks

Each runs as a `tokio::spawn` loop in `main.rs` wrapped in `supervise()`. The supervised list (13 tasks: `progress_sweep`, `rss_sync`, `post_processing`, `grab_sweep`, `external_sync`, `cleanup`, `library_classify`, `metadata_refresh`, `upgrade_search`, `anibridge_refresh`, `airing_refresh`, `backup`, `misgrab_sweep`) and intervals are inline in `main.rs` — grep `supervise(&` for the canonical names. Non-obvious bits the code doesn't explain on its own:

- **Restart policy is exponential backoff**, not flat 5s: `MIN_BACKOFF = 5s`, `MAX_BACKOFF = 30 min`, `HEALTHY_RUNTIME = 60s`. Healthy ≥60s run resets to 5s; <60s exit doubles up to 30 min.
- **Two layers of status tracking** — `scheduled_task_runs` DB table is the historical record (System page per-task history pane); `AppState.tasks: TaskRegistry` is the in-memory live status served at `/api/system/tasks` (lock-free atomics, snapshot-on-read).
- **`external_sync` quirks**: 1-min outer tick re-reads `config.external_sync_interval_minutes` (Settings change takes effect within 60s); `consecutive_errors`-driven exponential skip (2^errors intervals, capped at 5 → 32× multiplier, with 24h ceiling so a 7-day cadence can't get pushed seven months by five errors); `has_linked_account` early-out so no `scheduled_task_runs` row burns when no account is linked.
- **`backup` shape (#126)**: hourly tick, first check 2 min after boot; runs only when `config.backup_schedule` is `daily` / `weekly` and the newest `ryokan-backup-*.tar.gz` in the backup folder is older than that cadence (minus a 5-min grace), so restarts never double up and a missed day catches up on the next tick. Shares `services::backup::BACKUP_LOCK` with the download endpoint and the pre-restore backup (`try_lock` → "busy" / 503). Re-`touch_definition`s itself every tick so the Scheduled Tasks tab's enabled flag follows the setting without a restart.
- **`cleanup` extras (#205)**: besides the DB prunes and the recycle purge, the hourly tick runs `post_processing::temp_sweep::sweep_orphaned_temp_files` over `config.media_root` for `*.ryokan-tmp` (the cross-fs move's partial copy) and `.<name>.ryokan-new` (the #202 upgrade staging file) older than `ORPHAN_MIN_AGE` (2h by mtime). Two phases: the walk (`spawn_blocking`, walkdir, no symlink following, `max_depth(4)`, canonicalized root and recycle-bin exclude) only collects candidates; removal happens under `POST_PROC_LOCK` **and** `manual_import::import::IMPORT_LOCK` (`try_lock`, the hour is skipped when either is busy), because a `.ryokan-new` made by `hard_link` or a same-fs `rename` inherits the *source's* mtime and reads hours old the second it is staged; with both locks held nothing can be mid-copy, so what is left is a crash leftover. `.ryokan-tmp` is a direct unlink (always a partial, or a duplicate of a source still in place); `.ryokan-new` goes through `recycle::recycle` (in move mode it can be the only copy of the episode) with the series *folder* name as the manifest title, since the sweep has no series row; a recycled file counts nothing toward `TempSweepReport.bytes` (it still sits in the bin) and a restored one is swept again next hour, so the docs tell the user to rename it instead. Directory-form `<dst>.ryokan-tmp` from a crashed cross-fs recycle *restore* is not covered. Errors ride on the task's `warn` status plus a `PostProcess` warn line.
- **`post_processing` stall timer (#205)**: `run_once` stamps `grabbed_torrents.completed_seen_at` (idempotent, first writer wins; `record_grab`'s reactivation clears it) on the first tick that sees the client report a grab complete. A grab that keeps coming back `ImportOutcome::NotReady` (no importable video visible: unmounted download path, SAB complete dir not translated, all-extras release) for longer than `config.import_stall_hours` (default 24, `0` = retry forever, Settings → General → Post-Processing) is marked failed with `failure_reason = 'import_stalled'` (`IMPORT_STALLED_REASON`) plus `episode_tags::mark_grab_failed_for_release` and an `ImportFailed` notification, so the failed row is the blocklist entry and the series page stops saying "Importing". A grab judged a misgrab in the same tick is left to the misgrab sweep. Measured from `completed_seen_at`, never `grabbed_at`: a slow download is not a stall. The stamp is wall-clock, so `escalate_if_stalled` also stays quiet for `IMPORT_STALL_BOOT_GRACE_SECS` (15 min) after `AppState.start_time`: a grab stamped before a long shutdown would otherwise fail on the first tick after boot with zero retries in this process (download mount coming up after Ryokan). `build_test_app_state` pins `start_time` to 2024, so tests opt into the grace by setting it. The `PostProcess` warn is written *after* `mark_failed_with_reason` succeeds so it is true when it lands and fires once. `AllFailed` / errored-in-client paths still fail immediately without a reason.
- **`misgrab_sweep` shape**: 60s tick (`services::misgrab::SWEEP_INTERVAL`), `sweep_once` split from the loop like `grab_sweep`. Pass (a) asks the client for the file list of every `pending` grab with `verification IS NULL` older than `MIN_AGE_SECS` (the grab-time spawn gets first go): empty list = metadata not ready, retried until `METADATA_GRACE` (15 min) then `unverifiable`; client errors retried for 30 min; usenet is `unverifiable` on sight (SAB reports article names). Pass (b) runs `remediate` on every `verification = 'misgrab'` row with `misgrab_action IS NULL`. `grabbed_torrents::get_all_pending` excludes misgrab rows, so post-processing never imports one even in the minute before the sweep acts.
- **`airing_refresh` shape (#115/#116)**: 12h supervised tick + manual trigger at `POST /api/tasks/airing-refresh`; both share `services::airing_refresh::AIRING_REFRESH_LOCK` (`tokio::sync::Mutex<()>`) so a manual click during the scheduled tick returns "already running" rather than queuing. Library add path also calls `refresh_for_series` inline (fire-and-forget) so freshly-added series show up in the calendar without waiting for the next 12h tick. Past-window prune retains 14 days. Mirrors Sonarr's `Episode.AirDateUtc` shape — stamp once, serve from DB on the calendar's hot path; the calendar reader has no in-process cache because the indexed range-scan is cheap enough on its own.

## Cross-cutting conventions

- **Error type: `Result<_, String>`** end-to-end. Errors flow into `logger::*` or HTTP bodies; downstream code matches on **tag-prefix strings** (`"AniList rate-limited"`, `"AniList unavailable"`, `"AniList not found"`, `"Download client not configured"`, MAL refresh-failure prefixes, etc.) not enum discriminants. New errors keep the prefix. If you introduce a typed error, carry the prefix in its `Display`.
- **`spawn_blocking` discipline**: anything that can block >5ms goes through `tokio::task::spawn_blocking`. Current sites: `bcrypt::hash` / `verify` (~50ms), post-processing file ops (BD episodes are 1–4 GB), rtorrent recursive `fs::remove_*` after `d.erase`, the directory walk in `handlers::library::pages`, the `warm_timing_equalizer` startup pre-pay, the misgrab verdict (`misgrab::assess_and_stamp`).
- **Mutex poisoning**: default is `.lock().unwrap()` (crash-loop on programmer error). The one deliberate-recovery site is `HYDRATED_CUMULATIVE` in `handlers::library::reconcile`. Don't add `.into_inner()` recovery to security-adjacent state (`LOGIN_FAILURES`).
- **FK policy**: every child of `series(id)` is `ON DELETE CASCADE` *except* `rss_seen` (NO ACTION — keep audit trail; `series_title` is stored alongside `series_id` so the trail stays readable when the FK is broken). `series::remove` must NULL out `rss_seen.series_id` for the series **before** the final DELETE — `PRAGMA foreign_keys = ON` is the sqlx default and a missed NULL surfaces as a hard DELETE failure.
- **Outbound `User-Agent: Ryokan/0.1`** is hardcoded at every call site (AL, Jikan, Kitsu, SeaDex, Nyaa, RSS, anibridge, artwork). Not tied to crate version. If a provider starts UA-filtering, grep `"Ryokan/0.1"`.
- **Logging**: `services::logger::{trace,debug,info,warn,error}(&db, category, message, detail).await` dual-emits to `tracing` + the `logs` table. Console filtering is `RUST_LOG`; table filtering is `RYOKAN_DB_LOG_LEVEL` (write-side floor). The 19-variant `LogCategory` enum (`models/log.rs`) is what System → Logs uses verbatim — adding a category requires updating `as_str` / `from_str` / display-name match arms. Categories: `Search`, `Grab`, `AutoSearch`, `Nyaa`, `AniList`, `Jikan`, `Kitsu`, `DownloadClient`, `Jellyfin`, `Media`, `Library`, `Auth`, `System`, `PostProcess`, `Quality`, `Scoring`, `ExternalSync`, `Rss`, `Notifications`. Legacy `qbit` strings still parse to `DownloadClient` for old-URL compat.
- **Metadata fallback chain**: AniList → Jikan-shaped MAL provider (Tenrai by default) → Kitsu. Activates on AL 403s or force flags. Series added via Jikan with no AL mapping store as `series.anilist_id = -mal_id` (negative-ID sentinel); every AL call site filters `id > 0`. **Consequence**: SeaDex (keyed by positive AL id) and AL airing-schedule queries are silently invisible to these series. Jikan/Kitsu episode caches use a negative-cache sentinel (`episode_number = 0, title = "__RYOKAN_EMPTY__"`) — read sites must special-case it or the chain hot-loops. **`is_adult`** (issue #219) comes from AL `isAdult`, a Jikan `rating` starting with `Rx`, and Kitsu `nsfw`; it lives on `AnimeDetail` (`#[serde(default)]` for older cached blobs) and reaches `series.is_adult` only through `metadata_sync::refresh_series_metadata` → `series::set_is_adult`, so a freshly added row reads false until its first refresh. Nyaa hosts adult releases on sukebei, which Ryokan does not search; auto-search logs a warn for adult titles instead of skipping them, since a torznab/newznab indexer can still find them. When no indexer is configured at all (`handlers::library::adult_needs_indexer`), the series page shows an `alert-warn` banner and the auto-search terminal toast carries the same note through `AutoSearchReport.notes`. The note rides on the terminal event because the sticky progress toast shows one event at a time, so a mid-search `warn` event is overwritten by the next "Searching" line before anyone sees it.
- **Parse-ordering in `services/media.rs` is load-bearing.** `parse_episode_number` / `parse_quality` regex branches have explicit ordering: the `NCOP`/`NCED` and half-episode (`- 07_5` / `- 07.5` / `S01E07.5`, issue #203) guards run on the raw string before underscore normalization, then `RE_SXEX` before bare-number, `OVA NN` before generic bare-number, trailing-marker ranges before the marker, WebRip before unified Web (issue #48), and the `RE_SXEX` guard before any dash-delimited branch. The bare-number-before-subtitle branch bails on a digit-free `OVA` / `OAD` / `SP` / `Special` marker in the subtitle position (`Part 2 - SP` must not fall back to the `Part 2` number). An anitomy `AnimeType` gate (`is_non_episodic_extra`) runs last, only when a number was found: `PV` / `NCOP` / `NCED` / `OP` / `ED` / `Opening` / `Ending` / `Preview` types return `None` when the keyword sits after the first ` - ` (or past the title's first word in a dash-less name), which keeps title-leading keywords (`Ed Edd n Eddy - 01`) and subtitle words (`- 05 - Opening Night`) parsing. anitomy contributes only the type; its episode number is never used (its codec handling reads `H.265` as E265). `OAD` / `OVA` / `SP` / `Special` / `Movie` types are wanted content and stay un-gated. `parse_release_version` (`05v2`, `(v2)`, `S02E10v2`, `.V2.`) is a sibling helper for the batch preflight (issue #204). Each branch has a regression-guard test, and `tests/nyaa_filename_corpus.rs` pins 325 real filenames. Don't "tidy" the order; new branches go with a pinning test.
- **Destination names come from `services::naming`**, never a `format!` with `S{:02}E{:02}` (the last hardcoded shapes were replaced in #124). Folder / file names inside the media root: `naming::series_folder` (add time only), `naming::season_folder`, `naming::episode_file`. Display-only labels (log lines, the recycle page's `S01E07` badge) may still format the tag directly.
- **Library deletes go through `services::recycle::recycle`**, never a bare `fs::remove_file` / `remove_dir_all` on a media-root path. The helper decides recycle-vs-permanent from `config.recycle_bin_path`, so a call site that unlinks directly silently bypasses the user's recycle bin. Download-side cleanup (SAB `complete/` hardlink sources in `handlers::library::episodes`, rtorrent `d.erase` paths) is *not* a library delete and stays a direct unlink.
- **HTMX-aware redirects**: `handlers::responses::htmx_aware_redirect` is mandatory for any handler that does `Redirect::to`. Bare `Redirect::to` under body-wide hx-boost gets nested-rendered into the source page. `tests/htmx_redirect_audit.rs` is a CI-enforced lint. See `templates/AGENTS.md` for the full rationale.
- **Auto-search title gate** (`services/auto_search/aliases.rs::matches_target`, mirrored by the relaxed interactive gate in `auto_search/mod.rs`): a release matches an alias either verbatim (the normalized alias is a substring of the normalized title) or fuzzily. **Automatic paths take only verbatim (or SeaDex-curated) matches**: `AutoQueryCtx.require_verbatim` drops fuzzy hits in `run_queries` and collects their titles, `find_best_for_target_with_diag` hands them to the auto-search handler for the "none named the series exactly" report line, and RSS rejects an `alias_score` below 1.0 with "Title does not name the series exactly". A verbatim hit whose anitomy title still has a word left after removing every alias word (`aliases::names_more_than_the_series`: "Dr. Stone New World" for Dr. STONE, "Mob Psycho 100 II" for Mob Psycho 100) is skipped the same way, which is how sequels named by subtitle stay out without a relations walk; the one exemption is the `Title - Episode Title - 05` shape, where anitomy folds the episode title into its series title, so when the first dash segment names the series and nothing else a later segment counts only if a leftover word reads like a season or part marker (`is_season_marker_token`: season, part, cour, arc, hen, final, roman numerals, ordinals). Rejected titles are noted once per sweep (`AutoQueryCtx::note_rejected`) and a release rejected in a `run_queries` call is not re-classified by that call's other queries and categories (`rejected_here`); it stays out of `seen` so a later pass with more aliases can still admit it. The interactive batch list passes `require_verbatim = false`. The user closes a naming gap per series with `series.alternate_titles` (one per line, the Advanced search overrides panel). **Alternate titles are primary aliases**: `resolve_search_overrides` reads them off the series row into `SeriesSearchCtx.alternate_titles`, and every collector folds them into both the gate's alias list and the canonical query list (`add_alternate_aliases`, plus the preferred-group queries), so they drive the primary queries and match verbatim without waiting for a metadata sync. `auto_search::with_alternate_titles` also folds them into the detail's synonyms once at `resolve_series_context`'s single exit (every path: cache, live AniList, MAL, Kitsu) and in the upgrade sweep; the RSS `SeriesMeta` and the misgrab alias set read the row directly. AniList synonyms themselves still enter only through `collect_extended_aliases`, the zero-candidate fallback pass. The batch auto-grab reports the rejected titles too (`find_best_batch_for_target_with_diag`). RSS keeps its exactness check on the season- and episode-adjusted winner of `best_series_match` on purpose: an exact runner-up is the series the release fits worse, and grabbing it there would be a wrong-season misgrab. The fuzzy path scores **distinctive tokens only** (`GENERIC_TITLE_TOKENS` drops articles, romaji particles, and format nouns like `the animation` / `movie` / `season`), and its surplus budget (`passes_content_surplus_check`, issue #103) is keyed on the distinctive count, not the full alias length. Issue #219 is the reason: the colon-split alias `Risa THE ANIMATION` used to clear the 0.6 gate on `the` + `animation` alone. An all-generic alias has no fuzzy signal and only matches verbatim. New generic tokens go in that list with a regression test; don't lower the thresholds instead.
- **Match provenance** (`services/auto_search/provenance.rs`): every candidate that passes the gate is stamped with `SearchResult.match_provenance` (`MatchKind` verbatim / fuzzy / seadex_curated, `MatchPhase` primary / extended / preferred_group / bd_probe / franchise / batch_probe / seadex_seed, the alias, the distinctive-token ratio). `classify_match` is the gate (`matches_target` is its bool wrapper); both collectors set the phase on their query context. Scoring adds a "Title Match Confidence" line: fuzzy costs 25, a fallback phase (extended / franchise) another 10, sized to beat seeder / trusted tiebreakers and lose to every quality signal, so a fuzzy-only pool still grabs. `episode_tags::record_grab_with_match` persists `match_kind` / `match_phase` / `matched_alias` / `match_ratio` on `episode_grab_history` (auto-search, upgrade sweep, interactive grabs; RSS, autobrr and the picker leave them empty), `get_grab_history` renders `grab_match_summary`, and every grab log line ends with `match=... phase=... alias=... ratio=...`. Add a provenance string only in `provenance.rs`; the round-trip test there pins JSON, log, and DB forms together.
- **Misgrab guardrails, the rules that hold it together**: `grabbed_torrents.verification` is NULL / `verified` / `misgrab` / `whitelisted` / `unverifiable` and is written once; `misgrab_action` is `removed` / `removed_no_delete` / `flagged`; `failure_reason` (`misgrab`, `import_stalled`; empty for a disk-full or client failure) renders as a tag on the Downloads → Blocklist row. **The blocklist is `state = 'failed'`** and every automatic path honors it: the auto-search collectors drop candidates through `blocklist_snapshot` (hash globally, exact title per series) after scoring, which also covers the upgrade sweep, the batch auto-grab, and the misgrab re-search; RSS records a `rejected` decision; autobrr keeps its hash check. `find_all_for_target` (the interactive picker) is deliberately not filtered so its unblock-and-continue flow works, and that flow now calls `whitelist_by_hash`. **Whitelist is by hash across rows**: Restore whitelists every row for the hash and writes a fresh `pending` row (`unblock_by_hash` points the failed one at it), so a re-added torrent is never judged again. For a removed grab the whitelist is written **after** the client accepted the re-add: `whitelisted` rows leave the Misgrabs tab (that is its filter), so whitelisting first would strand a failed re-add with no retry button; every failure before the add leaves the row untouched. `source_url` is stamped by every grab path that has the URL (`set_source_url` right after `record_grab`); the picker path has none and Restore falls back to `magnet:?xt=urn:btih:<hash>` for 40-hex hashes.   - `hardlink` (default, seed-safe — original stays for the client to keep seeding). Falls back to copy when `fs::hard_link` errors (cross-filesystem common case).
  - `copy`.
  - `move` — `fs::rename` same-fs; cross-fs uses copy-to-`.ryokan-tmp`-then-rename so a partial copy can't be observed at dst by a subsequent pass; source-remove after cross-fs move only logs a warning on failure.

A failed placement leaves the library and the old grab untouched; a refused recycle undoes the staging (`unstage_upgrade`: remove in hardlink / copy modes, move back in move mode). The leading dot on the staging name is load-bearing: the recycle bin's companion sweep takes every `<stem>.`-prefixed sibling, and a `<dest>.ryokan-new` name would be swept away with the file it replaces.
  - **Remove after import (#228)**: `client_cleanup::remove_after_import` runs on `ImportOutcome::Imported` only (partial / failed stay) when the grab's client row has `download_clients.remove_completed` on (per client, default on, Sonarr's "Remove Completed"): usenet jobs and move-mode torrents are deleted from the client with files (`delete(hash, true)`) and `grabbed_torrents.client_removed_at` is stamped; for usenet the stamped `imported_source_paths` outside the media root are unlinked too (SAB `del_files` no-ops when `storage` is the parent complete dir; with no media root nothing is unlinked). The full-import arm stamps `grabbed_torrents.import_mode` with the mode; the partial arm stamps `partial`. `client_cleanup::sweep_finished_seeds` (after every `run_once` tick from `main.rs`; `SEED_SWEEP_LOCK` try_lock + 5-min throttle; gated like `run_once` on `post_processing_enabled` + `media_root`) walks `list_imported_in_client` (state imported **and** `imported_at IS NOT NULL` **and** `import_mode != 'partial'`, so `mark_completed_no_import` rows and partial imports, whose failed episodes still sit only in the download folder, never qualify): client switch off → skip; item gone → batch-stamp; usenet present + complete → remove; row imported in move mode (`import_mode`, or the current mode for pre-1.9.3 rows) whose stamped sources are all missing **while their parent folder exists** → remove (a dropped mount takes the folder too and reads as waiting); errored → wait; `DownloadItem::seeding_done` (per-impl rules in `download_client/AGENTS.md`) → remove; else wait. A failed delete stays unstamped and retries. `record_grab`'s reactivation clears the stamp. `remove_stamped_source_paths` lives here now and is re-exported into `handlers::library::episodes`.
  - **Batch preflight** (`validate_batch_episode_map` → `BatchPlan`): every wanted video is resolved to its `(series, episode)` slot before any mutation. Files that parse to `None` (extras) are absent from `slots` and warn-skipped by the loop; two files on one slot with **different release versions** keep the highest and list the rest in `superseded` (issue #204, info-logged "superseded by"); a tie on version fails the whole grab with "no files were changed".

The RSS task uses `RSS_SYNC_LOCK` with `try_lock` so a manual "run now" during the 60s tick returns "RSS sync is already running" rather than queuing.
- **Auto-expand** (`services::auto_expand::expand_from_files`) is sibling-series detection inside a batch pack — distinct from megapack narrowing in the `DownloadClient` trait. Two call sites: grab-time (180s metadata wait inside a `tokio::spawn` after the HTTP handler returned) and import-time (safety net when grab-time bailed). Writes per-sibling rows into `grabbed_torrent_series` so post-processing routes each file into the correct sibling folder. **Transitive relation walk**: AL's relation graph has missing direct edges across split sagas (Monogatari case); `expand_from_files` fetches walkable neighbors capped at `auto_search::TRANSITIVE_WALK_MAX_FETCHES`, grafts their relations onto the parent before sibling detection. Failed neighbor fetches are soft. **Absolute-numbering offsets**: each sibling route carries `episode_offset` so stored episode numbers are *effective* (post-offset) values — upgrade-search for "Egypt-hen E1" finds the route whose files were originally numbered E25 on disk. **Grab-tag backfill** writes `episode_quality_tags` + `episode_grab_history` rows for every sibling at grab time so each sibling's page shows `grabbed` immediately. **AL-overflow** episodes (parsed episode > `parent_episode_numbers`, e.g. smol Owarimonogatari BD splitting aired E1 into two files producing disk-level E13) get the same backfill so the overflow row renders during download rather than after import. **Parent-route fallback**: every unclaimed media file routes to the parent series; unclaimed alongside sibling routes triggers a `warn` log so misdetection surfaces in System → Logs. **Not load-bearing under failure** — if grab-time aborts, the grab row is already recorded and import-time rescues it; never synthesize an empty grab row to mark auto-expand "complete."

## Process-wide global state

Static `LazyLock`s crossing request boundaries — inventory:

- `services::anilist::rate_limit::*` — throttle state. Deep dive: `src/services/anilist/AGENTS.md`.
- `services::anilist::DETAIL_CACHE` — per-AL-id memoization; partial-recovery paths read from it after a failed batch fetch.
- `services::jikan::DETAIL_CACHE` — per-MAL-id memoization (parallel to AL's).
- `services::jikan::JIKAN_COOLDOWN_UNTIL` — Jikan's equivalent of AL's rate-limit machine. When Jikan 429s, sets "unavailable until Instant" so subsequent calls return a clean cooldown error instead of hammering and piling up more 429s. **60s default, 300s max.** Honors the response's `Retry-After` when present.
- `services::source_description::LAST_FETCH` — Process-global throttle for live Nyaa description fetches. **`MIN_FETCH_INTERVAL = 1s`** (Nyaa doesn't publish a rate limit but tarpits scrape-looking patterns fast). Holds the mutex *across the sleep*, deliberately serializing all fetches so two concurrent classifier calls can't burst.
- `services::anime_relations::INDEX` (`LazyLock<Index>`) — the compiled-in anime-relations rule index, parsed from `include_str!` on first use. Never refreshed at runtime; a new snapshot ships with the binary.
- `services::anibridge::CACHE` (`RwLock<Option<CacheState>>`) + `DOWNLOAD_LOCK` (`Mutex<()>`) — In-process TMDB↔AniList mapping cache + single-flight download serializer (no TOCTOU race). The `anibridge_refresh` 24h task warms `CACHE`; the disk cache underneath uses conditional GET via stored meta, with multiple `spawn_blocking` sites for read/meta/write paths and an unconditional-read fallback on the 304 path.

- `services::post_processing::POST_PROC_LOCK` — serializes the post-processing task. Held across the full import sweep including the 60s ffprobe timeout.
- `services::post_processing::client_cleanup::SEED_SWEEP_LOCK` + `LAST_SWEEP` — the finished-seed sweep's `try_lock` serializer and its 5-minute throttle stamp (#228); a tick that finds a sweep running skips.
- `services::rss::RSS_SYNC_LOCK` — `try_lock` + readable error so manual run during a tick doesn't queue.
- `services::external_sync::EXTERNAL_SYNC_LOCK` — same shape; Sync-now click during the supervised loop returns "already running."
- `services::manual_import::import::IMPORT_LOCK` — `try_lock` shape (#122); a second confirm while an import runs returns "already running" instead of racing folder names and the post-processing lock.
- `services::recycle::RECYCLE_UNWRITABLE` (`AtomicBool`) — set when a recycle attempt found `recycle_bin_path` configured but unwritable and refused the delete; cleared by the next successful recycle. ## Database & migrations

- sqlx 0.9 with **no compile-time query checking** (zero `sqlx::query!` invocations); `macros` feature kept for derive macros only. SQLite statically bundled; no system `libsqlite3` needed at runtime.
- **`SqlSafeStr` (sqlx 0.9)**: `query`/`query_as`/`query_scalar` accept `&'static str` implicitly; any dynamically-built query string (our `format!`'d placeholder-splicing and `SELECT {COLS}` const-interpolation sites in `models/`) must be wrapped in `sqlx::AssertSqlSafe(..)`. These are all internal SQL with bound parameters — no user input is interpolated — so the audit the wrapper asserts is satisfied. Prefer moving an owned single-use `String` into `AssertSqlSafe(s)`; use `AssertSqlSafe(s.as_str())` only when the string is reused (e.g. an `insert_sql` driven in a loop).
- Migrations in `models/migrations/`. New columns use `ALTER TABLE ... ADD COLUMN ... .ok()` to ignore-if-present (idempotent, file-free). The exception is **one-shot migrations** that must run exactly once and can't self-guard (data rewrites, seed-table fixups). Those live next to their model (`models/group_source_map.rs` is the current example), write an ID row into `schema_migrations` after running, and skip on subsequent boots via `migration_already_applied(db, id)`. Don't invent a per-migration config flag — that's what `schema_migrations` is for. No separate migration files on disk.

## Routes

Six route groups in `main.rs`, each with a different auth layer — pick the right group when adding a new route:

- **`public_routes`** — unauthenticated; wrapped in `csrf_public` so POSTs still enforce Origin/Referer (`/login`, `/setup`, `/forgot-password`).
- **`protected_routes`** — behind `require_auth` cookie middleware. Default for all UI routes and web-UI-facing API endpoints.
- **`sonarr_routes`** and **`radarr_routes`** — merged *outside* the cookie-auth layer; use `arr_auth::check_api_key` instead. Two separate routers because Seerr only allows two Sonarr + two Radarr indexer slots and both shims must coexist on one host/port.
- **`webhook_routes`** — outside cookie-auth; each receiver carries its own API-key middleware.
- **`calendar_routes`** — outside cookie-auth; carries `require_calendar_scope` (scoped-API-key middleware from #114) so iCal subscribers (Apple Calendar / Google Calendar / Thunderbird, which can't carry cookies) can reach `/api/calendar.ics`. Same scoped-key shape as the future `search`-scoped surfaces planned on top of #114.

**Boot order matters for #126**: `services::backup::apply_pending_restore` runs in `main.rs` before `SqlitePoolOptions::connect`, so a staged restore is swapped in with no connection open; the post-migration `logger::info` line is the only DB write it makes.

There is no `/healthz`. **The Docker healthcheck deliberately probes `/login`** (200 with no auth, no config dependency, no side effects) rather than the auth-gated `/api/health`.

## Docker

`docker-entrypoint.sh` runs as root, ensures a `ryokan` user/group matching `PUID`/`PGID`, chowns `/data`, then execs under `gosu`. Two non-obvious deliberate choices (don't "fix" either of these):

- **User-mounted `/downloads` and `/media/*` paths are intentionally NOT chowned.** Chowning a 10TB media library would stall startup for hours and could clobber ownership the rest of an *arr stack relies on. The user picks a `PUID`/`PGID` that already owns those paths on the host (linuxserver.io convention).
- **`static/` is copied into BOTH stages of the Dockerfile.** Builder needs it for `include_str!("../../static/default_custom_formats.json")`; runtime needs it for `ServeDir`. Looks like duplication; isn't.

## Tests (one-paragraph summary; deep dive in `tests/AGENTS.md`)

Most tests live inline as `#[cfg(test)] mod tests`; integration tests in `tests/` are binary crates that import `ryokan` as a library and require `--features test-support` (each `[[test]]` target declares this so plain `cargo test` silently skips them). ## CI

Seven workflows in `.github/workflows/`: `rust.yml` (fmt → clippy → build → test, plus an MSRV build job; runs on every branch push except `gh-pages`, plus `pull_request` only for fork PRs against `main` / `dev`, so a same-repo PR shows the checks from its head commit's push run rather than running twice), `cargo-audit.yml` (weekly + on Cargo lock changes), `docker.yml` (native amd64/arm64 → GHCR on every branch push, tagged by branch, plus semver tags and `latest` on releases; fork PRs cannot write to GHCR, so they upload `docker load`-able tarballs as artifacts instead), `claude.yml` (`@claude` mentions), `docs.yml` (Zensical site build → `gh-pages` on push to `main`), `license-notices.yml` (auto-regen `licenses/THIRD_PARTY_LICENSES.html` on dev pushes when `Cargo.lock` / `about.toml` / `about.hbs` change; commits with `[skip ci]` to avoid recursive triggers), `mutants-weekly.yml` (Sunday 03:17 UTC cron — curated cargo-mutants subset against last week's baseline; opens an issue only on caught → missed regressions). Build & Run section above lists the four lint commands to run locally before pushing. Two non-obvious traps:

- **Don't re-enable sqlx default features.** `default-features = false` in `Cargo.toml` is what prunes the phantom `rsa` RUSTSEC-2023-0071 advisory at source. Re-enabling defaults pulls `rsa` back in and turns `cargo-audit.yml` red. Note (sqlx 0.9): `sqlx-mysql` + `sqlx-postgres` now appear as `Cargo.lock` entries even with the opt-out, but `cargo tree -i sqlx-mysql` confirms they're never compiled/linked and `rsa` stays absent — don't "clean them up" by toggling features.
- **Don't re-enable fantoccini default features.** `fantoccini` is pinned to `default-features = false, features = ["rustls-tls"]` so its default `native-tls` stack (`hyper-tls` → `native-tls` → `openssl`) stays out of the lock. Dropping the opt-out pulls `openssl` back in (Dependabot GHSA-phqj-4mhp-q6mq) even though it would only ever build under the `browser-e2e` feature. Same source-prune rationale as the sqlx case above.
- **GHCR image name must be lowercase** (`ghcr.io/johnthreekay/ryokan`). The repo is capitalized "Ryokan" but `IMAGE_NAME` lowercases it — GHCR rejects uppercase image names.
